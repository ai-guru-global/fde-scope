## 0. 诚实声明（先读）

## 2. 案例档案

### 2.1 案例 A · 茶语万象（标杆案例，讲师演示用）

**客户一句话原话**（演示开场直接念）：

> "全国 2800 家门店，每周订货全凭店长拍脑袋——订多了报废，订少了断货。
> 我们买了数据平台，但没人知道怎么让它'会订货'。"

**背景卡**：新式茶饮连锁 · 门店 2800+ · SKU 86 个 · 三个数据源（门店 POS / 供应链 / 会员）。

**干系人**（参考档案，学员不直接看）：

| 人 | 角色 | 在乎什么 |
|---|---|---|
| 王芳 | 副总裁 · 数字化中心（发起人） | 门店周订货准确率 ≥98% |
| 陈宇 | CTO（**第二发起人**） | 全渠道会员 DAU 增长 30% |
| 林晓 | 供应链总监 | 报废率与断货率 |
| 赵磊 | 数据平台负责人 | 接入工期与系统稳定性 |

**参考成功标准（档案版）**：≤14d 完成数据接入（瞬时 10w+ TPS）· ≤90d AI 订货预测上线覆盖 90% 门店 ·
MAE 较基线下降 ≥20% · ≤120d 完成运维移交，SLO 99.5%。

**演示命令**：

```bash
fde-scope engage init --customer "茶语万象" --profile ticket
fde-scope gate list                       # 全部 10 个门禁（第 3 列 🏭=工业专属 7 关 / 🏢=通用 3 关）
python examples/seed_mock_engagements.py  # 幂等；种出全部 10 个 mock engagement
fde-scope web                             # 找到「茶语万象」看完整档案与已通过的 gate
```

**演示要点**："这是别人家的满分作业——但你要做的不是抄，是知道每一站的**证据长什么样**。"

### 2.2 案例 B · 迅捷出行（学员 A 组，ticket）

**给学员的客户简报**（原始形态，故意不给整理好的）：

> "我们 146 个城市，客服中心每天 8 万通电话，投诉、调度、发票什么都有。
> 老板要求 AI 客服拦截率 60% 以上，人工工单降 30%。但数据总监说数据给不了那么快，
> 客服中心负责人又担心 AI 答错要背锅。你们看着办。"

**背景卡**：网约车平台 · 146 城 · 订单样本 5.2M 行 / 投诉 41k 条 / 司机侧会话 12k 条（含 PII）。

**干系人**（学员要自己整理出这张图，以下是档案对照）：

| 人 | 角色 | 在乎什么 | 隐含冲突 |
|---|---|---|---|
| 罗成 | 技术 VP（发起人） | AI 客服拦截率 ≥60% | 要快 |
| 邓琳 | 数据总监（**第二发起人**） | 146 城数据 ≤14d 接入 | 要稳，怕数据暴露风险 |
| 钱锋 | 客服中心负责人 | 人工工单下降 30% | 怕 AI 答错砸了满意度 |
| 孙丽 | 司机端产品经理 | 司机投诉响应时长 | 关心司机侧，与客服 KPI 不同 |

**训练重点**：
- **冲突干系人**：罗成要快 vs 邓琳要稳；钱锋怕背锅 → 课程会问"成功标准写谁的"？
- **隐含 PII**：投诉与司机会话含 8900 条 PII 候选 → D3 数据体检的靶子。
- **方言/口语化**：已知局限（档案），D5 bad case 的天然素材。
- 反模式考点：Scope Creep（四个人四个 KPI，不砍就爆）、No HITL（客服场景必须有人机协作）。

**参考成功标准（档案版）**：≤14d 接入 146 城 · ≤90d 上线拦截率 ≥60% + 工单下降 30% · ≤120d 移交 bad_case <8%。

**查看参考档案**：`python examples/seed_mock_engagements.py` 后打开 web 控制台 →「迅捷出行」。

### 2.3 案例 C · 南湾汽车（学员 B 组，manufacturing）

**给学员的客户简报**：

> "南沙工厂，焊装 + 座舱两条线。老板签了全栈 AI 战略合作，要'产线数据上云'加'座舱语音助手'。
> 但焊装车间主任说 PLC 谁都不许碰，安全部门还没签字，工会……我们厂没有工会。
> 两个赞助人，一个要激活率，一个要上云速度。"

**背景卡**：整车厂 · 焊装主线 PLC（Siemens S7 / PROFINET 环网）+ 智能座舱 HIL 台架（dSPACE）+ AGV 车队（5G）·
2 班制 · OT/IT 已分离 · 非气隙环境。

**这个案例的特殊价值——门禁会真的拦住你**：

> 想自己新建一个档案走到这一步？**别这么干**——新档案从 `qualification` 起步，
> 要逐关补齐成功标准、数据接入、语料、原型、验证五道材料才能摸到 `deploy`；
> 那本身是案例 C 的练习内容，不是热身。这里直接看**已经走到 deploy 的那份档案**：

```bash
python examples/seed_mock_engagements.py                          # 幂等；先种出 10 个虚构档案
COLUMNS=200 fde-scope engage list                                 # 找到 eng-southbay-manufacturing-seed03
fde-scope engage status eng-southbay-manufacturing-seed03         # 停在 deploy 阶段
# deploy 阶段有三个门禁，逐个查（不带 --gate 只查本阶段第一个 = fat_sat）：
fde-scope gate check eng-southbay-manufacturing-seed03                              # ✋ fat_sat：SAT 未执行
fde-scope gate check eng-southbay-manufacturing-seed03 --gate functional_safety     # ✋ 未做危险分析
fde-scope gate check eng-southbay-manufacturing-seed03 --gate conformity            # ✋ CE / Annex IV / 危险分析 三条
```

档案版显示：FAT/SAT 未执行、功能安全未做危险分析、EU AI Act 高风险 → 缺 CE 与技术构造文件。
**三个门禁全红**（仅 conformity 一家就报了 3 条 blocker）——这正是课程想让你亲眼看到的：
工业现场的"上线"不是技术动作，是合规动作。

> 💡 `gate check` 撞上 blocker 时，系统会自动记一张**待审技能卡草稿**（飞轮设计，不是 bug）。
> 看完用 `fde-scope skill review` 查、`fde-scope skill archive <skill-id>` 清掉即可，详见 [`12`](12-附录-术语表与模板库.md) §3.5。

**训练重点**：
- 工业 7 门禁全清单（`site_survey` / `fat_sat` / `functional_safety` / `conformity` / `works_council` / `air_gap` / `shift_handover`）；本案例主要触发前 3 个 + `air_gap` / `shift_handover`
- 车间主任说"PLC 不许碰" → site survey / 干系人地图的真实形态
- 反模式考点：Safety Incidents（没做危险分析就动产线）、Data Quality Surprises（OT 数据形态与 IT 完全不同）

**配套练习数据**：

```bash
fde-scope corpus --input examples/quickstart_manufacturing/alarm_corpus.jsonl --out reports/alarm_corpus_report.html
# KPI 默认把 5 个工位聚合（grasp_success_rate=0.7931）；想单独看某个工位就先把它单独存一行：
fde-scope kpi eng-southbay-manufacturing-seed03 --samples examples/quickstart_manufacturing/station_samples.jsonl
grep ASSY-HUMANOID-01 examples/quickstart_manufacturing/station_samples.jsonl > assy.jsonl
# ↑ Windows：findstr ASSY-HUMANOID-01 examples\quickstart_manufacturing\station_samples.jsonl > assy.jsonl
fde-scope kpi eng-southbay-manufacturing-seed03 --samples assy.jsonl    # grasp=0.7333、干预率=0.0321
```

（`ASSY-HUMANOID-01` 抓取率 73%、干预率 3.2%，是"还在爬坡"的典型画像——D5 挖 bad case 就用它。
顺带记住这个坑：**指标永远先问"分母是谁"**——整份文件的聚合值不是任何一个工位的画像。）

### 2.5 案例 E · 明源体检（**止损示范**，D7 或 D8 收尾用，5 分钟）

> **用途**：全课唯一一个"**正确答案是走人**"的案例。前四个案例训练"怎么把事做成"，
> 这个训练"**怎么判断一件事不该继续做**"——G2 门禁要求委托单里必须有「放弃标准」，这一节就是它的实战演示。
> **谁讲**：讲师口头讲，不用档案、不用命令，讲完留 3 分钟讨论。

**背景（虚构）**：某连锁体检机构想做"AI 报告解读助手"，已谈了两轮，氛围很好。

**三条致命信号**（讲师逐条给出，每给一条问一句"这时你会怎么做"）：

| 信号 | 事实 | 为什么致命 |
|---|---|---|
| ① 无第二发起人 | 只有运营总监一个人推动；CTO 明确说"这是他们部门自己的事" | **Sponsor Collapse**（同案例 D）；一调岗项目就死 |
| ② 成功标准永远定不下来 | 三次访谈拿到三套说法："客户满意度""解读时长""减少投诉"，且都不肯写数字 | 没有 done = **Infinite Pilot** 的标准开场 |
| ③ 拿不到数据 | 体检报告涉大量健康 PII，法务明确拒绝任何形式的数据出域，也不批脱敏环境 | 数据红线：**连"有条件能做"都构不成** |

**剧本推演**（讲师按这三步讲，学员只需听+讨论）：

1. **第 1 轮（体面提出）**：把三条写成书面风险清单，给出"如果你能解决①和③，我们下周就能开工"的条件。
2. **第 2 轮（对方给不了）**：对方说"先做个小 demo 给上面看看，预算后面再说"。
   —— 这句话**同时**命中 Infinite Pilot 与 Sponsor Collapse，此时**不是**砍价时机，是触发放弃标准。
3. **第 3 轮（正式退出）**：按委托单 §6「放弃标准」执行：书面说明退出原因（**只陈述事实，不指责**）、
   移交已完成的调研成果、留下"满足条件时的重启路径"、把这段经历写成**技能卡**（`12` §2.13）沉淀。

**讨论题（留 3 分钟）**：
- 已经投入两轮访谈，退了"亏不亏"？（考**沉没成本**：投入越多越舍不得，这正是反模式）
- 退出的方式会不会毁掉客户关系？（考**退出方式**：事实陈述 + 移交成果 + 重启路径 = 关系反而更好）

**讲师收尾金句**：
> "**会做的人是供应商，会说不的人才是顾问。** 你在这门课学的一切交付能力，
> 都必须配一条底线：**知道什么时候不该接、接了什么时候该退。**"

**与门禁的对应**：G2 委托单第 6 节「放弃标准」（`12` §2.1）；G7 退场计划「终止条件」（`12` §2.12）；
反模式 Infinite Pilots / Burnout Death Spiral（`12` §1.6 十二大反模式速查表第 8、6 条）。

## 3. Day 2–8 演练剧本（角色扮演）

> **通用规则**：扮演者（讲师/助教）**只给情境与追问，不给答案**；学员必须用**产出里的证据**回应。
> 每次演练 3–5 分钟，结束后扮演者当场给 1 条"最狠的点评"。

### 3.1 D2 · 客户开场（助教 → 学员）

**角色卡**：见 §4.1。**台词骨架**：

```
（学员：自我介绍 + 想了解"痛点"）
客户 CTO：别问了，我时间有限。我就一句话——AI 客服，三个月，能上就上。
          （学员若直接问数据）
客户 CTO：数据的事你找数据部，我只要结果。
          （学员若坚持问成功标准）
客户 CTO：那你说，你觉得这个"成功"应该怎么定？给我个数字。
```

**观察点**：学员是否顶住"直接要结果"的压力，把对话拉回**成功标准与干系人**；
是否识别出"客户只有一位出面人"（→ 追问第二发起人）。

### 3.2 D3 · 数据交接（助教扮演客户 IT → 学员）

**情境**：学员拿到案例数据文件。助教扮演客户 IT 主管，给数据时**埋三个坑**（照 dossier 设定）：

1. "这是我们能给的**全部**字段了。"（实际含 PII 候选字段，学员必须挑出来说"这个不能收"）
2. "类别分布很均匀的，放心。"（实际长尾极不均匀，学员要当场用 `connect` 输出反驳）
3. "时间范围？大概是去年的吧。"（要求学员把"大概"变成确认项写进体检报告）

**观察点**：是否**先看再装**（先跑 `connect` 再下结论）；PII 识别是否敢说"不收"；结论是否明确。

### 3.3 D4 · 语料汇报（助教扮演客户老板 → 学员）

学员用 ≤200 字白话汇报语料结果。老板（助教）**只追问三句**：

1. "你说的'能用多少'，从头到尾是哪几个数字？"
2. "补的那些样本，是你编的吗？"（考诚实标注与合成比例）
3. "我一个字没听懂，重讲一遍，说人话。"（考零术语）

**观察点**：数字链完整（N→M→切分）｜合成比例如实｜**重讲一遍仍不崩**才是真懂。

### 3.4 D5 · 反对意见业务主管（助教扮演）★ 04/05 指定剧本

**角色卡**：见 §4.2。助教从下列反对意见中**抽 3 条**逐一发难，学员须**用数据回应**（禁止讲情怀）：

| # | 反对意见（原话） | 学员应调用的证据 | 反面回应（扣分） |
|---|---|---|---|
| 1 | "AI 答错了谁负责？出了舆情你们赔吗？" | 评估指标 + bad case 率 + HITL 设计（人工兜底） | "我们模型很准的，放心" |
| 2 | "你们根本不懂我们业务，先把知识库做好再说" | 数据体检结论 + 真实数据原型结果（已经跑过） | 争辩"我们很懂" |
| 3 | "预算砍一半，功能一个不能少" | 成功标准优先级 + 放弃标准（当场划掉哪个） | 全盘答应（Scope Creep） |
| 4 | "60% 拦截率太低了，我要 95%" | 基线对比 + 渐进路线（先 60% 再涨）+ 反问成本 | 硬承诺 95% |
| 5 | "上一个供应商的 Pilot 做了半年，然后没有然后了" | 时间盒（≤90d 上线）+ 验收清单 + 明确 done | "这次不一样"（无证据） |

**扮演纪律**：助教必须**追到底**——学员一给数字就换角度再问；学员说"不知道"时，
追问"那你准备怎么查、什么时候给答复"（诚实 + 行动 = 通过）。

**观察点（评分表见 §5）**：用数据而非情怀｜承认不知道时给行动｜把反对意见转成可度量条件｜守住范围。

### 3.5 D6 · 凌晨 2 点盲测（学员 ↔ 学员，助教监考）

**剧本**：随机交换 Runbook。B 学员朗读 A 学员的文档，遇到"读不下去/听不懂/缺步骤"处**当场举手**：

```
B（举手）：这里写"检查服务健康"——凌晨 2 点的人具体敲什么命令？
B（举手）：回滚这步说"恢复备份"——哪个备份？最近的还是昨天的？
B（举手）：升级路径写"联系负责人"——谁的手机号？他不接怎么办？
```

**观察点**：每处卡壳都是 Runbook 的断点，A 学员当场记下并修复；修复后再测一次。

### 3.6 D7 · 客户运维负责人三个刁难问题（助教扮演）★ 04/05 指定剧本

**角色卡**：见 §4.3。这是交接签字演练——助教扮演**不信任你的客户运维负责人**，
提出三个刁难问题，学员须**翻交接包作答**（回答时手指要落在文档上，指出对应段落）：

| # | 刁难问题 | 学员应指向 | 通过标准 |
|---|---|---|---|
| 1 | "你说回滚 5 分钟——我们昨晚试了 40 分钟，怎么解释？" | Runbook 回滚段 + 演练记录 | 承认差距 → 给出重新演练与修订文档的承诺与时限 |
| 2 | "SLO 写 99.5%，真出事故，你们赔吗？" | SLO 卡错误预算段 + 支持安排 | 讲清错误预算语义（预算内不追责）+ 退场计划里的支持边界 |
| 3 | "我们的人看不懂'drift''bad case'这些词——你走了谁给我翻译？" | 培训材料题纲 + 术语白话对照 | 指出培训已覆盖 + 承诺补充白话版；不得贬低客户 |
| 4 | "模型悄悄变差了，谁先发现？" | 监控与漂移段落 + 告警路由 | 指出漂移监控 + 告警路由，且给出**没配监控时的补救方案** |

**观察点**：是否**在交接包内找答案**（找不到 = 交接包不合格，当场记 G7 修复项）｜
是否诚实（"这块我们没做到，我记下来"vs 硬撑）｜语气是否专业不卑不亢。

## 4. 角色卡（可直接打印发给助教）

### 4.1 角色卡 · 客户 CTO（D2 用）

```
你是「<案例客户>」的 CTO。特点：
- 时间少、语速快、要结果，对"调研""需求分析"这类词不耐烦
- 但心里其实是支持这个项目的（你签的字），只是被上次的失败供应商伤过
- 如果学员坚持问"怎么定义成功"，你会松口——但要求他给数字
- 如果学员不问干系人，你全程不会主动提第二个人（埋雷）
暗号：学员问出"谁和您一起为这个结果负责"时，你可以提"VP 和我也在盯"（给出第二发起人线索）
```

### 4.2 角色卡 · 反对意见业务主管（D5 用）

```
你是使用部门的主管，一开始就反对上这个系统。特点：
- 不讲技术，只讲"出事了谁负责""我的团队会不会被裁"
- 对任何指标都先质疑口径："你说 91%——统计的是哪批数据？谁标注的？"
- 学员给数据你就承认一部分，然后换一个新角度继续质疑（不许一次就放行）
- 底线：如果学员承认"不知道"并给出查证动作 + 时限，你要点头
暗号：学员说"我们可以在 90 天验收清单里加这一条"时，你松口："这条我要签字。"
```

### 4.3 角色卡 · 客户运维负责人（D7 用）

```
你是客户方接手运维的负责人。特点：
- 保守、抠细节、怕背锅；你最恨"交接完就找不到人"
- 你的三个刁难问题见 §3.6；学员回答时你必须盯着他的**文档**——他要指给你看
- 如果他只说"我会支持你们"，你会说："你走了以后呢？"
- 底线：交接包里有明确段落 + 支持终止条件 + 演练记录，你就签字
暗号：学员主动说"我们安排一次联席演练，演练通过你再签"时，你同意签字
```

### 4.4 角色卡 · 车间主任（案例 C 专用，D3/D5 备用）

```
你是焊装车间主任。特点：
- 不信任何"上云"，你的 PLC 停一分钟就是几十台车的损失
- 说话带工地味："你们坐在办公室吹空调，知道焊装线停线赔多少吗"
- 学员提"停线做测试"你就炸；学员提"旁路采集、不碰控制回路"你才给好脸色
- 底线：学员把"不碰 PLC 控制层、只读数据"写进方案里，你认可
暗号：学员问"FAT 阶段你们能安排哪个窗口"时，你给一个 2 周后的停机维护窗口（考 site survey）
```

[演练·D5] 张三：✅用 bad case 数据回应了"答错谁负责"，并给了 HITL 兜底设计

## 6. 案例使用规则

| 允许 | 禁止 |
|---|---|
| 把案例替换成自己熟悉的（脱敏）行业场景 | 使用真实客户名 / 真实人名 / 真实 PII |
| 在简报基础上补充合理细节（注明"补充假设"） | 修改门禁标准来"让自己好过" |
| 跨组借用对方案例的数据（D8 交叉提问） | 编造参考档案里没有的"客户原话"当证据 |
| 把参考档案当作"参考答案"对照自己的差距 | 直接抄参考档案当自己的作业（答辩会露） |

**企业内训特别说明**：企业版（`04` 形态 C）直接把案例簿替换为客户自己的一个真实（脱敏）小场景——
但**简报形态要保留"原始、未整理"的样子**，因为训练的核心就是"从模糊到可交付"。
