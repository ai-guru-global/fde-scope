## S0 · 开营（09:00–09:30 · 30 min）

**本节定位**：不讲课。只做三件事——让学员开口、让契约落地、让掉队风险提前暴露。

**一句话目标**（开场念）："今天结束时，你能用自己的话讲清 FDE 交付链路，并亲手跑通第一条迷你链路。"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–5 | 讲师自我介绍（**带一个翻车故事**）+ 今天不讲课先立规矩 | 建立"这里可以犯错"的安全感 |
| 5–16 | 学员接力自我介绍：**30 秒/人** = 我是谁 + **我最怕现场哪件事** | 收集真实痛点，讲师现场归类 |
| 16–24 | 课程契约：D2–D8 每天 2.25h、门禁制、诚实边界、数据红线 | 防止"抽空看看"式报名 |
| 24–28 | 今天的三条红线 + 时间结构（含两个硬性休息） | 降低认知焦虑 |
| 28–30 | 环境预警：现在就跑一次 `python3 --version` | 把装环境失败提前到 M4 之前 |

### 讲稿要点

**① 讲师自我介绍必须"带代价"（0–5 min）**
不要说"我做过 N 个项目"。说一个**具体的翻车**：

> "我曾经在一个项目里，第三周才发现客户说的'准确率'和我理解的不是一回事——
> 他要的是'客服不用改一个字就能发出去'，我做的是'分类对了就行'。
> 那天我回去把已经写好的两百行删了。今天这门课的第一条原则，就是那两百行换来的。"

要求：**真实、脱敏、有代价**。宁可少讲，不可编造（`05` §1 铁律）。

**② 学员自我介绍：30 秒/人，第二句是关键（5–16 min）**

话术模板（投屏）：

```
我是 <姓名>，我现在在 <公司/岗位>。
我最怕现场的一件事是：<一句话>。
```

讲师**必须做一件事**：把每个人"最怕的事"当场归类到 4 区，并写进白板/文档。

- "怕客户不给我数据" → **Zone A**（定边界）——"D2 我们专门练这个"
- "怕数据太脏" → **Zone B**（造物）——"D3 你会看到更脏的"
- "怕上线了没人会用/出事没人管" → **Zone C**（稳运）——"D6 就是给你的"
- "怕人走了东西没人接" → **Zone D**（交离）——"D7 教你交得出去"

> **这个动作本身就是教学内容**：45 人 × 30 秒 = 22 分钟，看起来"浪费"，实际上它同时完成了
> ① 破冰 ② 痛点收集 ③ **Zone A 干系人识别的现场演示**（"你们刚才说的每一句，都是我在做需求框定时要问的"）。
> 人数 > 35 时压到 20 秒/人，或分两组由助教并行收。

**③ 课程契约（16–24 min）——照 `06` §1 念，不展开**

五条要点（投屏，学员在群里回"已签署"）：

1. **时间**：D1 全天 6 小时；D2–D8 每天约 2.25 小时（90 min 直播 + 45 min 自练），整期约 22 小时。
2. **每天交一件产出**，产出里必须有**证据**（命令、文件、截图）——**没有证据 = 没交**。
3. **门禁制**：当天产出不过关，暂时进不了下一关；补交可以，但留痕。
4. **练习只用虚构数据**或**你自己已脱敏**的数据；**真实客户名与 PII 一律不进群、不上传**。
5. **鼓励用 AI 助手**，但你得能脱稿讲清自己的关键决策（D8 答辩会抽查）。

**④ 三条红线 + 时间结构（24–28 min）**
直接念 §0 的表。特别说明第二条："今天我会**故意犯一个错**，你们要抓住我——抓住的有加分。"

**⑤ 环境预警（28–30 min）**
让全体**当场**跑一次：

```bash
python3 --version      # 期望 ≥ 3.11
```

不达标的，现在就进"环境急诊室"（助教 1v1），不要等到 13:30 才开始装。

### 投屏·板书

- 左：话术模板 + "我最怕的事 → 4 区"对照（实时填）
- 右：三条红线 + 契约五条
- 白板角落预留：**停车位**（Parking Lot）——今天所有跑题问题先记这里

### 互动设计

| 问题 | 期望答案 | 冷场备选 |
|---|---|---|
| "你最怕现场哪件事？" | 任何真实回答都接住，并归类到区 | 讲师先自曝一个，再点"第二位"（不点第一个举手的人） |
| "如果只能带走一句话，你想带走什么？" | 无标准答案，收集期望用于 D8 回看 | 改成选择题："A 会跑工具 / B 知道怎么定边界 / C 敢跟客户说不"——群里打字母 |

### 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 学员自我介绍变成"背简历"（讲 2 分钟） | 讲师举牌 30 秒；"第二句才是重点，第一句我知道你是谁就够了" |
| 有人不肯开口 | 不点名逼问；私聊补收，公开只说"还有两位同学我私下单独聊" |
| 讲师自己讲太长挤掉学员时间 | **硬性**：16 分钟必须开始收自我介绍；宁可少收 3 个人，也要准时进契约 |

### 承接语（最后 30 秒）

> "好——你们刚才说的每一句'最怕'，其实都在同一张地图上。接下来 45 分钟，我把那张地图给你们。"

### 学员笔记要点

- 整期节奏：D1 全天 + D2–D8 每天约 2.25h，合计约 22h
- 每天必须交**一件带证据的产出**
- 数据红线：只用虚构/已脱敏数据，真实客户名与 PII 不上传
- 今天三条红线：3 个新概念、一次故意翻车、M1 只讲故事

## S1 · M1 世界观（09:30–10:15 · 45 min）

**本节定位**：全场唯一一段"讲故事"时间。目标是**换世界观**，不是传知识。

**一节课的 KPI（很重要）**：下课时学员能说出**这一句话** ——
> **"FDE 不是做从 0 到 80% 的活，是做从 80% 到 99% 的活。"**

只要这一句记住了，本节就算成功。其余全忘掉都可以。

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–5 | 收课前预读问题："FDE 和售前 / 实施 / 外包差在哪？"——**举手回答** | 让学员先输出，讲师后补充 |
| 5–15 | 三位前身 + "随队工程师"类比 | 用类比替代定义 |
| 15–24 | 时间线三锚点：2003 → 2023 → 2024–2026 | 建立"这不是网红岗位"的时间感 |
| 24–31 | 一句话对比：FDE vs 售前 / 实施 / 客户成功 | 解决最常见的混淆 |
| 31–38 | 40 / 30 / 30 能力模型 | 让学员知道 60% 要靠做中学 |
| 38–43 | 中国市场的三个特殊性（**讲 3 个小故事，不讲报告**） | 校准"照搬硅谷"的错经验 |
| 43–45 | 收口一句话 KPI + 布置世界观笔记 | 留一个明确动作 |

### 讲稿要点

**① 开场先收问题，不先给答案（0–5 min）**

预读问题是 `06` §0.5 布置的："**FDE 和售前、实施、外包到底差在哪？**"
点名 2–3 人回答（**先点举手的人，再点一个没举手的**）。学员答什么都可以，讲师只做一件事：**补齐缺失的那一块**。

**② 三位前身（5–15 min）——照着 `00` §1.1 讲**

| 前身 | 干什么 | 缺什么 |
|---|---|---|
| **解决方案架构师 / 售前** | 讲清方案能不能做 | 讲完就走，不负责跑起来 |
| **实施 / 交付工程师** | 把成熟产品装起来 | 只能"配方化"交付，产品不成熟就抓瞎 |
| **驻场外包 / 咨询顾问** | 客户要什么做什么 | 经验留在个人脑子里，不回产品 |

**FDE = 三者的合体 + 一个新东西：把现场经验回流成产品能力。**

逐字稿（可直接念）：

> "售前是**试驾员**——带你开一圈，签单就走。
> 实施是**装车工**——车是好的，他负责装起来；车要是不成熟，他就抓瞎。
> 外包是**代驾**——你说去哪儿他去哪儿，但你家的路他没记住，下次还得重新讲一遍。
> **FDE 是跟车队跑完整个赛季的随队工程师**：既要开得动，又要**把每一站的数据带回工厂改车**。
> ——最后这半句，是这条线里最值钱、也最容易被砍掉的一半。"

**③ 时间线三锚点（15–24 min）——只讲三个锚点**

| 锚点 | 讲什么 | 引用纪律 |
|---|---|---|
| **2003** | Palantir 成立，工程师直接派进 CIA / FBI / 五角大楼现场；因为环境保密，**没法"把需求带回去再开发"，只能把人派进去** | 讲事实，不带数字 |
| **2023** | AIP 推出，AI 能力层叠加到 Ontology 上——技术上准备好了 | —— |
| **2024–2026** | 全球 FDE 职位从约 **600+ 条**（2024-04）涨到 **6000+ 条**（2025-04），**10 倍**；Indeed 平台 2025-04→2026-04 从 **643 → 5330 条**，年增 **>700%**；国内 FDE 招聘增长 **42 倍**；OpenAI / Anthropic / Accenture + Microsoft 相继组建部署团队 | **必须连来源与日期一起说**（`00` §1.4 / §1.6，查证于 2026-09） |

**两个"比数字更有信息量"的观察**（讲这两个，比念数字有效）：

- **YC 旗下上百家创业公司在招 FDE，三年前几乎为零。**
- 采用 FDE 模式的 AI 公司，前 18 个月 **ARR 增速平均比同行快 3 倍**，
  但**客户成功团队规模只有同行的三分之一**。
  → 说明 FDE **不是在堆人，是在换组织形态**。

**反直觉事实（留一个"钩子"）**：Palantir 2025 财年毛利率约 **82%**，接近纯软件公司，
远高于传统咨询公司 **30%–40%**。
→ "重交付"和"高毛利"**可以同时成立**——秘诀在 D7 讲（前线学习机制）。

> **引用纪律（讲师必读）**：`00` §1.6 有两处来源冲突（如 OpenAI Deployment Company 成立时间），
> 讲到时照 `00` 说"**两种说法，我们讲 2025–2026 年间**"，**不要挑一个顺口的当定论**。
> 所有市场数字都要连来源与日期一起讲——这是这门课"诚实"人设的第一块砖。

**④ 一句话对比（24–31 min）**

| 角色 | 交付的是 | 谁对结果负责 |
|---|---|---|
| 售前 | 方案与承诺 | 签单为止 |
| 实施 | 装好的产品 | 装完为止 |
| 客户成功 | 续约与满意度 | 关系为止 |
| **FDE** | **在客户现场跑起来的系统 + 回流产品的经验** | **从 80% 到 99%，直到能交出去** |

**⑤ 40 / 30 / 30 能力模型（31–38 min）**

| 能力 | 占比 | 内容 |
|---|---|---|
| **工程能力** | 40% | 全栈开发、部署、调试、运维 |
| **业务能力** | 30% | 理解客户业务、拆解需求、定义成功 |
| **解决方案能力** | 30% | 架构设计、技术选型、风险控制 |

> **读法（逐字念）**："40% 是入场券。这门课给你工程侧的起步 + 业务意识的种子；
> **后面 60% 才是区分水平的地方**——而且其中一大半**只能在做中学**。
> 所以这门课的重点不是'教会你所有东西'，是'给你一条能自己走下去的路'。"

**⑥ 中国市场的三个特殊性（38–43 min）——讲成三个小故事**

不是念报告，是把 `00` §1.5 三条各讲成一句话故事：

1. **"我们缺的不是前身，缺的是闭环。"**
   → "国内早有解决方案架构师、交付工程师、AI 售前——差异在于：**很少形成'现场经验反哺产品'的闭环**。
   所以做 FDE，第一步是**把闭环补上，不是把岗位名字改掉**。"
2. **"美国是加装大脑，中国是对话驱动。"**
   → "很多客户的**流程不写在系统里，写在默契和人情里**。
   过去的软件要求客户先填表、画流程、配规则；
   AI 的入口是自然语言——所以在中国，**'一边跑、一边修路'反而更容易起步**。"
3. **"经济性约束是真实的。"**
   → "硅谷高价值客户能撑六到七位数**美元**年合同；国内大量项目在十万到百万**人民币**量级。
   所以中国 FDE 必须靠两件事活：**用 AI 和平台压低交付成本** + **用技能卡/连接器/行业模板提高复用率**。"
   → **这一条解释了本课程为什么反复强调"技能卡""交接包""留痕"**——不是为了让档案好看，
   是为了让**一个人的现场经验变成可复用的资产**，否则国内的项目经济性撑不住。

**⑦ 收口（43–45 min）——把 KPI 钉在墙上**

逐字念：

> "今天记住一句话就够了：
> **FDE 不是做从 0 到 80% 的活，是做从 80% 到 99% 的活。**
> 会搭 Demo 的人很多；能把 Demo 变成生产线上稳定系统的人很少。
> 下午我会让你们亲手看到这句话的**证据**。"

### 常见错误与纠偏

## S2 · M2 交付地铁图（10:30–11:30 · 60 min）

**本节定位**：全场信息密度最高的一节，也是 D1 唯一必须"记下来"的知识结构。
**把 4 区 18 阶段讲成 4 条地铁线**——每站有名字、有下车证据、有闸机。

**一句话目标**："下课时你手里有一张自己画的地铁图，能说出四条线分别解决什么问题。"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–5 | 先给结论：为什么需要地图（"没有地图的交付，就是拿客户的钱试错"） | 动机先行 |
| 5–15 | 画四条线（Zone A/B/C/D），只讲每条线的**一句话使命** | 先骨架，后血肉 |
| 15–35 | 18 站的**名字 + 下车证据**（每条线 5 分钟，逐站过） | 核心内容 |
| 35–43 | **门禁**概念：为什么"清单会烂，门禁不会"；10 个闸机 7 工业 + 3 通用 | 今天的新概念 2 |
| 43–52 | 12 反模式里**最常踩的 4 个**（只讲 4 个，其余预告 D2–D7） | 埋钩子 |
| 52–58 | 学员动手：画自己的地铁图（手绘/数字版皆可） | 产出 |
| 58–60 | 收口 + 承接 M3 | 过渡 |

### 讲稿要点

**① 为什么需要地图（0–5 min）**

逐字稿：

> "客户不会给你一份干净的需求。他会给你一句抱怨：**'我们每周订货全凭店长拍脑袋'**。
> 从这句话到'系统上线、客户验收'，中间有 18 站。
> **没有地图的人会怎么干？** 直接开始写代码——然后在第 3 周发现：
> 客户说的'准确率'和你理解的不是一回事。
> 今天这张地图的全部意义：**让你在第 1 站就知道第 18 站长什么样。**"

**② 四条线（5–15 min）——只讲使命**

| 线 | 区 | 站号 | 一句话使命 | 类比 |
|---|---|---|---|---|
| **A 线 · 定边界** | Zone A 预接触 | 1–4 | 把模糊抱怨变成**可交付的边界** | 出发前定行程 |
| **B 线 · 造物** | Zone B 建造 | 5–10 | 把数据和想法**变成能跑的东西** | 施工 |
| **C 线 · 稳运** | Zone C 运营化 | 11–15 | 让东西**稳得住、有人管、会进化** | 通水通电 |
| **D 线 · 交离** | Zone D 交接退场 | 16–18 | **交得出去，带得走** | 交钥匙 |

> **念法**："交付不是百米冲刺，是**换乘 4 条线的地铁——每站都要验票。**"

**③ 18 站 + 下车证据（15–35 min）——本节核心内容**

> 讲法：**逐站念"名字 → 下车证据"**，不解释为什么（为什么留到 D2–D7 每天讲）。
> 🏭 = 工业/制造 profile 专属；ticket profile 只走 15 站（跳过 3 个 🏭 阶段）。

**A 线 · 定边界（1–4）**

| 站 | 阶段 | 下车证据（离开这站时必须手里有什么） |
|---|---|---|
| 1 | 项目立项与问题框定 `qualification` | 一页"值不值得做"的判断：高价值？数据难？客户集中？ |
| 2 🏭 | 现场勘察 / Gemba walk `site_survey` | 现场记录：物理环境、OT 网络、资产清单、安全约束 |
| 3 | 干系人地图与对齐 `stakeholder_map` | 一张干系人地图：≥2 位发起人 + 每人"在乎什么" |
| 4 | 成功标准契约化 `success_criteria` | **客户签字的可度量 done** + 时间盒（≤14d / ≤90d / ≤120d） |

**B 线 · 造物（5–10）**

| 站 | 阶段 | 下车证据 |
|---|---|---|
| 5 | 数据接入 `connect` | schema + 样本预览 + **PII 清单** |
| 6 | 语料锻造 `corpus` | 语料报告：清洗后可用量、覆盖盲区、合成补齐、train/eval/test 切分 |
| 7 | 真实未策展数据上原型 `prototype_real_data` | 在**真数据**（不是样板数据）上跑通的输出截图 |
| 8 | 干系人验证 `validate` | 验证记录：向谁演示了、接受了什么、**拒绝了什么及理由** |
| 9 🏭 | 部署上线 `deploy` | FAT/SAT 记录 + 功能安全分析 + 合规文件（CE / EU AI Act） |
| 10 | 评估交付 `eval` | 主指标 + 业务口径指标 + **Top 3 bad case** |

**C 线 · 稳运（11–15）**

| 站 | 阶段 | 下车证据 |
|---|---|---|
| 11 | SLO/SLA + on-call `slo_sla` | SLO 卡：目标值 + 测量方式 + **错误预算** + 告警路由 |
| 12 | Runbook 编写 `runbook` | 5 类事件 × 四段：判断信号 → 处置 → **回滚** → 升级 |
| 13 | 监控与漂移检测 `monitoring_drift` | 漂移监控 + 告警路由（"AI 不是坏了才叫坏，慢慢变差也是坏"）|
| 14 🏭 | 变更管理 + 终用户培训 `change_mgmt_training` | 培训题纲 + 工会/共决记录（工业现场） |
| 15 | 飞轮 → 产品化 `flywheel_productization` | ≥1 个现场特性进入产品化评审 |

**D 线 · 交离（16–18）**

| 站 | 阶段 | 下车证据 |
|---|---|---|
| 16 | 运维移交 `ops_handoff` | 所有权移交记录（转交客户运维/CS） |
| 17 | 知识转移 `knowledge_transfer` | 文档包：runbook + eval 报告 + SLO + 模型卡 + 培训材料 |
| 18 | 退场 `disengage` | **客户签字** + 退场计划（≤120 天，含终止条件） |

**④ 门禁：今天的新概念 ②（35–43 min）**

逐字稿（核心比喻，全场要重复）：

> "**清单会烂，门禁不会。**
> 你见过项目计划表吗？第一周很漂亮，第三周开始有人打勾但不做事，第五周没人看了。
> **清单是自觉，门禁是制度。** 门禁长什么样？就是**检票闸机**——
> 你没票，它不放你走。它不骂你，也不听你解释，它只是**不放行**。"

**门禁怎么运作（投屏讲）**：

- **每个门禁有两种判定**：
  - **blocker**：硬拦，过不去，必须补齐
  - **warning**：放行，但留痕并扣作品集等级
- **门禁是活的**：每次推进阶段都会**重新评估**当前阶段的全部门禁——
  "**上周过了不代表今天还过**"。一份过期的"已通过"记录，永远不会自动放你过去。
- **怎么查**：
  ```bash
  fde-scope gate list                        # 看全部 10 个门禁（🏭 工业专属 7 关 / 🏢 通用 3 关）
  fde-scope gate check <你的档案id>           # 查当前阶段第一个门禁
  fde-scope gate check <你的档案id> --gate slo   # 查指定门禁
  ```

**10 个闸机 = 7 工业专属 + 3 通用**（`03` §2）：

| 类型 | 数量 | 门禁 | 挂在第几站 |
|---|---|---|---|
| 🏢 **通用** | 3 | `success_criteria` · `slo` · `handoff_signoff` | 4 · 11 · 18 |
| 🏭 **工业专属** | 7 | `site_survey` · `air_gap` · `fat_sat` · `functional_safety` · `conformity` · `shift_handover` · `works_council` | 2 · 5 · 9 · 9 · 9 · 11 · 14 |

> **念法**："注意最后一行——**第 9 站挂了 3 个闸机**。
> 为什么？因为工业现场的'上线'不是技术动作，是**合规动作**。这个 D5 会亲眼看到。"

**⑤ 12 反模式里最常踩的 4 个（43–52 min）**

> 讲法：每个给**一个现场画面**，不给定义。其余 8 个预告"每天讲 1–2 个"。

| # | 反模式 | 现场画面（讲师照着讲） | 课程里在哪治 |
|---|---|---|---|
| 1 | **Sponsor Collapse**（唯一发起人） | "项目很顺。三个月后那位副总调岗了，新来的第一句话是'这个项目我们重新评估一下'。你前面三个月白干。" | D2 |
| 2 | **Demo-Debt**（把 Demo 当交付） | "演示那天客户鼓掌。生产上线那天你才发现：演示用的是**挑过的 200 条数据**，线上是**没人挑过的 200 万条**。" | D5 |
| 3 | **Data Quality Surprises**（假设数据是干净的） | "客户说'数据在数据平台上了，随时能取'。你打开一看：同一个客户名有 7 种写法，日期有 3 种格式，还有一列全是空的。" | D3 |
| 4 | **Scope Creep**（范围蔓延） | "客户说'既然都做了，顺手加个报表吧'。你答应了。加了 4 次以后，交付日期推了两个月，你成了唯一一个还相信这个项目的人。" | D2 |

> **一句话总结**："这 4 个反模式有一个共同点：**它们都不是技术问题，都是判断问题**。
> 这就是为什么这门课先教定边界，再教写代码。"

**⑥ 学员动手画图（52–58 min）**

画你的交付地铁图（手绘/数字版都行）：

## S3 · M3 三律（11:30–12:00 · 30 min）

**本节定位**：把 D2–D7 六天要反复复用的**三条判断规则**一次讲透。
这是 `00` §2.4 / §2.5 唯一的"正式讲授"时段。

**一句话目标**："记住三句话，后面六天每天都用它们。"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–3 | 先讲今天最大的一个数字：**60% 停在试点** | 制造焦虑（诚实的焦虑）|
| 3–13 | 80/95/99 阶梯图 + "最后 1% 人工兜底" | 三律第一律的出处 |
| 13–21 | 三律逐条讲，每条配一个翻车现场 | 记忆挂钩 |
| 21–27 | 学员动作：写下自己工作中违反三律的一件事 | 迁移到自身 |
| 27–30 | 收口 + 承接 M4（"下午你会亲手体验其中一条"） | 过渡 |

### 讲稿要点

**① 先给一个数字（0–3 min）**

> "两个数字（来源：腾讯研究院报告 Ch.01 §1.4）：
> **超过 70%** 的企业已经在至少一个职能里**尝试**生成式 AI；
> **超过 60%** 仍然**停留在试点或实验阶段**。
> ——**六成企业的 AI 项目没走到生产。**

**② 80 / 95 / 99（3–13 min）——画阶梯图**

| 阶段 | 需要什么 | 难度感受 |
|---|---|---|
| **0 → 80%** | 通用大模型 + 简单 Prompt | **很容易**——有经验的工程师一天就能搭出"挺好用"的原型 |
| **80% → 95%** | 大量 Prompt 优化、规则补充、数据标注、测试集构建 | **难**——模型在特定场景出错、行业术语理解不准、边界情况处理不了 |
| **95% → 99%** | FDE + 专用平台 + **上万级真实对话数据** | **非常难**——1% 的错误也可能造成严重后果；而且 **"改好 A 又坏 B"** |

> **本节最该被记住的一句（`00` §2.4 原文）**：
> **FDE 不是做从 0 到 80% 的活，而是做从 80% 到 99% 的活。**
> ——会搭 Demo 的人很多；能把 Demo 变成生产线上稳定系统的人很少。

**为什么上限是 99%，不是 100%？**（三条理由，念一遍即可）

1. LLM 是**概率系统**——数学上不存在 100% 保证；
2. 从 99% 推到 99.9%，**边际成本指数级增长、边际收益递减**；
3. **高风险场景那 1% 不应该让 AI 覆盖**，而应通过人工审核和回滚机制兜底。

> **最漂亮的一句，建议背下来**：
> **99% 不是技术妥协，而是工程经济学的最优解：
> AI 覆盖可规模化的 99%，人工守住不可自动化的 1%。**
>
> **现场用法**：客户说"我要全自动、不出错"时——**用这句话回应**，
> 然后带他一起设计**那 1% 的人工兜底流程**（这正是 D6 的 Runbook）。

**③ 三律（13–21 min）——每条配一个翻车现场**

**第一律：先成功标准，后代码**

> **出处**：上面那个"60% 停在试点"。瓶颈不在模型能力，也不在工具，**在人**——
> **真正卡住的是最后 20% 的生产化工程。**
>
> **翻车现场**（讲师讲自己的）：
> "客户说'我要提升客服效率'。我做了三个月，上线那天他说'这不是我想要的'。
> 我问他想要什么，他说'客服能少招 5 个人'。
> ——**这句话我第一天就能问到。我花了三个月。**"
>
> **判断口诀**：**"这句话，客户用什么数字来验收？"**（`05` §5 提问库）

**第二律：在真实脏数据上做原型**

> **翻车现场**：
> "我在**挑过的** 200 条数据上做了个 Demo，效果 95%，客户鼓掌。
> 上线那天用的是**没人挑过的** 200 万条，效果掉到 61%。
> 客户问我'你不是说 95% 吗'——我无法解释，因为**我从没在真数据上跑过**。"
>
> **金句**：**"在样板间练出来的手艺，撑不过毛坯房。"**
>
> **今天的证据**：下午你会亲手跑 `connect`——你会看到这份"看起来挺正常"的数据，
> 实际只有 **20 条**、分成 **9 类**（详见 §4）。

**第三律：一切产出可验证**

> **翻车现场**：
> "我交付的时候说'这个系统很稳定'。客户问'多稳定？'
> 我说'挺稳定的'。他说'上次那个供应商也这么说，然后我们崩了三次'。"
>

> 命令可复制、数字可复现、结论有依据、说谎会被抓。
>
> **为什么这条最重要**：它是**唯一能替代"你要相信我"的东西**。

**② 第 1 步 `connect`：先看再装（8–16 min）**

跑完的真实输出（`sample_tickets.csv`，2026-09 实测）：

```
FDE Scope v0.1.0 — connect · csv
Schema · examples/quickstart_csv/sample_tickets.csv
┌─────────┬────────┬──────────┬──────┐
│ field   │ type   │ nullable │ PII? │
├─────────┼────────┼──────────┼──────┤
│ id      │ string │ False    │      │
│ content │ string │ False    │      │
│ category│ string │ False    │      │
│ channel │ string │ False    │      │

'订单修改','会员咨询','发票咨询','售后补发'] · channels=['chat','email','phone']
✅ Sample extracted → samples/preview.json
```

**逐行讲（这是本节最重要的 5 分钟）**：

1. **`Schema` 表**：4 个字段、类型、是否可空。
   `PII?` 那一列**全空**——但**不亮 ≠ 没有 PII**。
   > 讲师当场追问："这份数据的 `content` 列里，如果写着'我的手机号是 138xxxx'，它算不算 PII？"
   > —— **算**。schema 探测**只按字段名判**（`name`/`email`/`phone` 这类列名才亮），
   > **自由文本必须逐条看值**。这是 D3 的第一个坑，今天先埋。
2. **`rows≈20`**：**只有 20 条**。
   > "客户说'我们有海量数据'，你打开一看是 20 条。**这就是真实数据的第一课。**"
3. **9 个类别**：20 条分成 9 类，平均每类 2 条多——**极度不均衡且极度稀疏**。
4. **`✅ Sample extracted → samples/preview.json`**：命令有**产出文件**。
   > "**没有产出文件的命令等于没跑。** 这门课所有作业都要求证据——这就是证据的样子。"

> **新概念 ③「真实数据」就落在这里**：不是"数据"这个词，
> 而是"**真实数据是脏的、少的、不均衡的**"这个体感。

**③ 第 2 步 `corpus`：淘米（16–26 min）**

**先讲类比（30 秒）**：

> "语料工程就是**淘米**：
> **去砂** = 去重（同一个客户名字 7 种写法，是一种米还是七种米？）
> **去石** = 质量门（空的、乱码的、错的，不能下锅）
> **补水** = 补盲（缺口在哪，补的是**缺口**，不是把米堆高）"

跑完的真实输出（2026-09 实测）：

```

✅ PII entities masked: 2
✅ Dropped (dedup+gate): 0
✅ Corpus forged: 20 real + 395 synthetic = 415 total
⚠ Coverage gaps:
   • 物流查询: 3 (need ≥100)
   • 退款: 3 (need ≥100)
   • 账号问题: 3 (need ≥100)
   • 退换货: 3 (need ≥100)
   • 支付问题: 3 (need ≥100)
   • 订单修改: 2 (need ≥100)
   • 会员咨询: 1 (need ≥100)
   • 发票咨询: 1 (need ≥100)
   • 售后补发: 1 (need ≥100)
📊 Report → reports/corpus_report.html (+ reports/corpus_report.json)
```

**逐行讲（关键 6 分钟）**：

| 行 | 讲什么 |
|---|---|
| `Loaded 20 raw rows` | 原料就 20 条——**先承认现状**，不粉饰 |
| `PII entities masked: 2` | 20 条里就有 **2 处** PII 被识别并脱敏。"**你的数据里一定有 PII，问题是你能不能找出来**" |
| `Dropped (dedup+gate): 0` | 这 20 条恰好没有重复与不合格——**这是运气**，真实数据很少是 0 |
| `20 real + 395 synthetic = 415 total` | **注意这里的诚实**：报告**主动标出**了 395 条是合成的。"**合成比例必须如实标注**——这是 D4 的门禁硬指标" |
| `⚠ Coverage gaps`（9 条） | **每一类都缺**，都缺到 `need ≥100`。→ **追问全班**："所以这 20 条数据，能支撑什么、不能支撑什么？" |
| `Report → ...` | 两份产出：HTML（给人看）+ JSON（给机器看） |

**班内提问（本节高潮）**：

> "如果客户问：'我这 20 条数据是不是够用了？'——你怎么答？"
>
> **期望答案**："**不够**。9 类每类 1–3 条，连'这一类到底长什么样'都看不出来；
> 现在这 415 条里 **95% 是我们合成的**——能用来**验证流程跑通**，
> **不能用来证明'这个模型效果好'**。"

**讲述顺序（很重要）**：

   > "这是别人家的满分作业：10 个 mock 档案里的标杆。**看清楚每一站该长什么样。**"
   > （档案版成功标准：≤14d 完成数据接入 · ≤90d AI 订货预测上线覆盖 90% 门店 ·
   > MAE 较基线下降 ≥20% · ≤120d 完成运维移交，SLO 99.5%）
2. **再看「南湾汽车」（工业案例，门禁被真实拦截）**——停在 `deploy` 阶段，**三个门禁全红**：

   ```bash
   COLUMNS=200 fde-scope engage list                                 # 找到 eng-southbay-manufacturing-seed03
   fde-scope engage status eng-southbay-manufacturing-seed03         # 停在 deploy 阶段
   fde-scope gate check eng-southbay-manufacturing-seed03                            # ✋ fat_sat：SAT 未执行
   fde-scope gate check eng-southbay-manufacturing-seed03 --gate functional_safety   # ✋ 未做危险分析
   fde-scope gate check eng-southbay-manufacturing-seed03 --gate conformity          # ✋ CE / Annex IV / 危险分析 三条
   ```

   > **念这段话（本节最重要的一段）**：
   > "FAT/SAT 未执行、功能安全未做危险分析、EU AI Act 高风险 → 缺 CE 与技术构造文件。
   > **三个门禁全红**——仅 conformity 一家就报了 3 条 blocker。
   > 这正是今天想让你亲眼看到的：**工业现场的'上线'不是技术动作，是合规动作。**"
3. **再看「星澜科技（Adnova）」（反面教材）**——`success_criteria` 门禁**是红的**。
   > "它的委托单其实很漂亮，成功标准也有数字。
   > 但**干系人地图上，发起人只有 1 个**。
   > ——追问你们一句：**如果这位 COO 下季度调岗，这个项目还活着吗？**"
   > → 引出 **Sponsor Collapse**（D2 正式讲）。

> **顺带讲一个"设计不是 bug"的点**：`gate check` 撞上 blocker 时，
> 系统会**自动记一张待审技能卡草稿**（这是飞轮设计，不是 bug）。
> 看完用 `fde-scope skill review` 查、`fde-scope skill archive <skill-id>` 清掉即可。

## S6 · M6 迷你链路挑战（15:30–16:30 · 60 min）

**本节定位**：**学员独立复现**。讲师闭嘴，助教主攻。
这是 D1 的**唯一产出**（🎯 产出 1）的生成时段。

**一句话目标**："不靠讲师，你自己跑完 connect → corpus，并跟同桌用 3 句话讲清楚。"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–5 | 宣布规则 + 复习三条命令（不演示，只列清单） | 断奶 |
| 5–35 | 学员独立跑；助教巡场；讲师**只答卡住 > 3 分钟的问题** | 产出 |
| 35–45 | 同桌互讲：3 句话讲清"我刚才干了什么、为什么" | 费曼复述 |
| 45–55 | 抓 2–3 人上台复述（**随机点名**，不点积极分子） | 验证真懂 |
| 55–60 | 对照 G1 自查 + 预告 S7 | 收口 |

### 讲稿要点

**① 规则（0–5 min）**

投屏（**只列清单，不演示**）：

```
今天你要独立完成：
1. fde-scope connect --type csv --source examples/quickstart_csv/sample_tickets.csv
2. fde-scope corpus --input examples/quickstart_csv/sample_tickets.csv --out reports/corpus_report.html
3. 确认 reports/corpus_report.html 真实存在（不是"我以为生成了"）
4. 准备 3 句话（下一环节要用）

规则：
· 卡住 > 3 分钟 → 举手，不要自己耗
· 讲师不给答案，只问你"你试了什么"
· 卡住不是失败，是今天最值钱的时刻
```

**② 学员独立跑（5–35 min）**

- 助教巡场，**只答"卡住超过 3 分钟"的问题**。
- 讲师**闭嘴**。可以在白板上写：**"卡住 > 3 分钟再举手"**。
- 达标的标志（投屏，学员自对）：
  1. `connect` 输出里能看到 **Schema 表**和 **`rows≈20`**
  2. `corpus` 输出里能看到 **`20 real + 395 synthetic = 415 total`**
  3. `reports/corpus_report.html` **真的在那里**

**③ 同桌互讲：3 句话（35–45 min）**

投屏模板（**必须包含"为什么"**）：

```
跟同桌讲 3 句话：
1. 我刚才做了什么？（动作）
2. 为什么要先看数据，再动手？（理由）
3. 报告里最重要的数字是哪个？为什么是它？
```

**期望的"及格答案"**（讲师念一遍示范，让学员知道标准）：

> "① 我把一份 20 条工单数据接进来看了长什么样，然后让它生成了一份语料报告。
> ② 因为不看数据就开始做，就会在**假数据上做出好看但没用的东西**——真实数据只有 20 条、还带 PII。
> ③ 我觉得是 **`20 real + 395 synthetic`** 这行——它告诉我这份数据**主要靠补**，
> 所以**能验证流程，不能证明效果**。"

**④ 随机点名复述（45–55 min）**

- **点后排、点没举手的**（`05` §2：抽人不抽"积极分子"）。
- 学员讲不清时，讲师**不补答案**，只问：
  > "**那你现在最想搞清楚的是哪一点？**"（把"不会"转成"要查什么"）
- 讲得好的，当场给一句具体表扬（**表扬要具体到动作，不要"讲得好"**）：
  > "你刚才主动说了'2 处 PII 被脱敏'——**这说明你看了输出，不是只看最后一行**。"

**⑤ 收口（55–60 min）**

> "现在对照 G1 自查——**注意，G1 有一条不是硬拦的，但你必须自己知道。** 下一节讲。"

### 投屏·板书

- 常驻：三条命令清单 + 达标标志三条
- 白板：**卡住 > 3 分钟再举手**（大字）
- 互讲环节：3 句话模板

### 互动设计

| 问题 | 期望答案 | 冷场备选 |
|---|---|---|
| "为什么要先看数据？" | 不看就在假数据上做出好看没用的东西 | "如果直接跳过 `connect` 会怎样？" |
| "报告里最重要的数字是哪个？" | 无唯一答案，但必须**说出理由** | 群里投票选 3 个候选数字 |
| "你卡在哪？" | 任何答案都接，转成"下一步查什么" | 讲师先自曝"我当年卡在哪个命令" |

### 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 学员跑在错误目录 | "先 `pwd` 看一眼——**必须在仓库根目录**" |
| 学员让 AI 代跑，自己没看输出 | "AI 可以帮你，但你得能**脱稿讲清关键决策**——D8 会抽查" |
| 学员只截图不跑（交截图充数） | G1 是 blocker：**报告文件必须真实存在**（`03` §2 G1） |
| 有人提前跑完开始闲聊 | 让他去帮同桌（**当小助教**）——`06` §8 结对互评的机制 |

### 承接语（最后 30 秒）

> "最后 30 分钟：**交作业、拿反馈、听明天的预告。**"

### 学员笔记要点

- 我今天**亲手**跑通了 `connect` → `corpus`，报告文件真实存在
- 我能用 3 句话讲清：**做了什么 / 为什么要先看数据 / 最重要的数字是哪个**
- **卡住 > 3 分钟就举手**——省下的时间是你的

## S7 · 门禁 G1 + 答疑（16:30–17:00 · 30 min）

**本节定位**：D1 的**验收**环节 + 明天预告。
重点不是"讲 G1 是什么"，而是让学员**当场自评、当场暴露差距**。

**一句话目标**："对照 G1 三条自查，把产出交出去；知道明天自己是什么角色。"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–8 | 逐条念 G1 检查项 + 学员当场自评打钩 | 暴露差距 |
| 8–16 | 提交规范（命名、渠道、截止、补交规则） | 防止因格式被打回 |
| 16–24 | 答疑（先答"停车位"里记的问题） | 兑现承诺 |
| 24–30 | 预告 D2："明天你就是'进场第一天'" | 埋钩子 |

### 讲稿要点

**① G1 自查（0–8 min）**

**G1 冒烟门（`03` §2 原文）**：

| # | 检查项 | 判定 |
|---|---|---|
| ① | `connect` + `corpus` **命令跑通**，报告文件**真实存在** | **blocker** |
| ② | 能用白话解释"我刚才做了什么"（口头或 3 行文字） | **blocker** |
| ③ | 报告中的关键数字与实际运行一致 | **warning** |

> **讲法**："前两条是**硬拦**——做不到就进不了明天。第三条是**软提醒**——
> 数字对不上不拦你，但会被记下来。**为什么它只是 warning？**
> 因为'数字看错'是新手最常见的错，我们不想第一天就把人拦死——
> **但你自己得知道：数字对不上，等于没有证据。**"

**逐条让学员当场打钩，并念一遍提交要求**：

```
提交内容（产出 1 · 迷你链路证据包）：
1. reports/corpus_report.html（提交文件本身，或报告首页截图）
2. 3 行白话解释：做了什么 / 为什么要先看数据 / 最重要的数字是哪个
3. 控制台「星澜科技」红色 blocker 的截图

命名：D1-姓名-产出名（多文件加后缀）
截止：直播次日 21:30（运营催交时间）；次日 08:30 出门禁通过榜
```

**② 提交规范与补交（8–16 min）**

| 项 | 规则 |
|---|---|
| 命名 | `D<N>-姓名-产出名`（多文件加后缀：`-截图1` / `-数据`） |
| 渠道 | 群内指定提交入口（以当期公告为准） |
| 截止 | 直播次日 **21:30** 前；次日 **08:30** 出通过榜 |
| **24h 内补交** | **正常放行**（标注"补交通过"） |
| **超 24h 补交** | 记"**延期通过**"：计入完课，**作品集等级最高 B** |
| 豁免 | 数据涉密 / 岗位冲突等特殊情况，私聊讲师走豁免，记录在证书备注 |

**补交申请格式**（群里 @助教）：

```
【补交申请】D3-李四-数据体检报告
原因：<一句话> ｜ 预计提交时间：<明晚 20:00 前>
当前卡点：<一句话，方便助教提前准备>
```

> **讲师强调一句**："**排不进去就别拖着**——24 小时内补交完全正常，
> 拖过了才降级。**报备比硬扛体面。**"

**③ 答疑（16–24 min）**

- **先答"停车位"里记下的问题**（今天积累的跑题问题）——兑现 S0 的承诺。
- 常见问题的标准答法（`02` D1 常见问题表 + `05` §6）：

| 学员问 | 回答要点 |
|---|---|
| 我不会 Python 能学吗？ | 能。今天所有命令可复制；Level 2 才碰代码。 |
| 没有 API key 能跑吗？ | 能。全链路有零 key 路径（规则模式），LLM 是可选加速器不是门槛。 |
| 我一直在用 Qoder / Trae / CodeBuddy，要换工具吗？ | **不用换**。课程只叠"流程与门禁层"，编码/办公工具继续用你顺手的。 |
| 学完能进大厂做 FDE 吗？ | 本课给能力与作品集，**不承诺结果**；D8 教你正确地把作品集用起来。 |
| FDE 的历史和原理要背吗？ | **不背**。今天 3 个新概念里没有它们。要用只有两个场合：D8 模拟面试、客户现场被追问——翻 `00` §5 即可。引用数字**必须连来源一起说**，不确定的说"待核实"。 |

**④ 预告 D2（24–30 min）**

逐字稿（**留一个悬念**）：

> "今天你是'来上课的人'。
> **明天早上，你就是'进场第一天'。**
> 客户会给你一句抱怨——就一句话，不给整理好的需求。
> 你要在 90 分钟里把它变成一份**能签字的委托单**。
> 今天下午你见过那份红色了：**星澜科技为什么红？** 明天第一件事就是讲它。
>
> 课后动作只有两个：
> ① 交产出 1（别忘了那张红色截图）
> ② 把今天画的地铁图拍照存好——**D8 你要拿它跟自己的实际路径对照**。"

### 投屏·板书

- G1 三条 + blocker/warning 标注（红/黄）
- 提交规范表 + 补交规则
- 命名示例：`D1-张三-迷你链路`
