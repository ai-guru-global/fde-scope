## 1. 你要准备什么（以及不需要什么）

### 1.1 需要

| 项 | 要求 | 说明 |
|---|---|---|
| 电脑 | macOS / Windows 10+ / Linux，8GB 内存 | 2018 年后的机器基本都行 |
| Python | **≥ 3.11** | 唯一硬门槛，§2 教你怎么装 |
| 网络 | 能访问 PyPI（或公司镜像源） | 只在"装包"时需要一次 |
| 磁盘 | 几百 MB（虚拟环境） | 比 Docker 镜像轻得多 |
| 时间 | 首次安装约 30 分钟 | 提前装；开营当天才装 = 高风险 |

### 1.2 不需要（重要）

| 常见误解 | 事实 |
|---|---|
| "得先买 API key 吧？" | **不用**。全链路有零 key 路径（规则模式），LLM 只是可选加速器，见 §4 |
| "要装 Docker 吧？" | 不用。课程全部命令在本机直接跑 |
| "要不要装 AgentScope？" | 不用。`[dev]` 里不含它；真实运行时是进阶内容 |
| "要 GPU 吗？" | 不要。不训练模型，只做语料工程与评估 |
| "公司电脑没管理员权限？" | 基本可以——虚拟环境装在用户目录下，见 §5.2 |
| "要科学上网吗？" | 不要。装包走国内镜像源即可（§3.2） |
| "我平时用 Qoder / Trae / CodeBuddy 写代码，要卸载吗？" | **不用**。课程只要求你用 `fde-scope` 走**流程与门禁**；写代码继续用你顺手的工具（分工见 `01` §6.4） |
| "公司已经买了豆包工作 / 千问办公 / WorkBuddy 这类办公 Agent 呢？" | 照常用，**而且是加分项**——现场本就不该要求客户换工具；你交付的是流程与证据，不是"你用了哪个工具" |

## 2. 安装（约 30 分钟）

### 2.0 第 -1 步 · 打开终端（真·零基础必读，1 分钟）

后面所有命令都要在**终端**里敲。终端就是一个"用打字代替点鼠标"的窗口，别怕，本课你只需要三个动作：**打开它、粘贴一行、按回车**。

**怎么打开**（选你系统那一行照着做）：

| 系统 | 打开方式 |
|---|---|
| macOS | 按 `⌘ + 空格` 打开聚焦搜索 → 输入 `终端`（或 `Terminal`）→ 回车；或 启动台 → 其它 → 终端 |
| Windows | 点开始菜单 → 直接输入 `PowerShell` → 打开「Windows PowerShell」（不用管理员身份也行） |
| Linux | 桌面右键 → 「打开终端」，或快捷键 `Ctrl + Alt + T` |

**怎么执行一条命令**（全文通用，以后不再重复解释）：

1. **复制**文档里的命令（选中 → `⌘C` / `Ctrl+C`）；
2. 切到终端窗口，**粘贴**——macOS 是 `⌘V`；Windows 是 `Ctrl+V`，或**在窗口里点右键**（会自动粘贴）；
3. 按 **回车（Enter）**，等它跑完（命令结束的标志是重新出现一行等你输入的提示符）。

> 📌 **三条纪律**（先记住，能省 90% 的慌乱）：
> 1. **一次只贴一段**——文档里每个代码块代表"一次操作"，别把两个代码块一起贴进去。
> 2. **终端里 `Ctrl+C` 不是复制**，是"中止当前命令"；复制粘贴用上面的方法。
> 3. **报错不可怕，先读最后一行**——最后一行通常就是原因（比如 `command not found` = 这个软件没装）。看不懂就把整屏截图发到学习群。
>
> 还认不全"终端 / 命令 / 参数 / 路径 / PATH"这些词？先花 2 分钟扫一眼 [`12`](12-附录-术语表与模板库.md) §1.0「电脑基础词」表格，全部用大白话解释了。

### 2.1 第 0 步 · 装 Python ≥ 3.11

先自检——在终端里（Windows：PowerShell），运行：

```bash
python3 --version
```

- 显示 **3.11 或更高** → 跳到 §2.2。
- 显示 3.10 或更低 → 按下面方式装新版本。
- 提示 `command not found` / `不是内部或外部命令` → 说明没装，按下面方式装。

| 系统 | 方式 |
|---|---|
| macOS | 官网 python.org 下载安装包（不要用系统自带的 `python3`）；或用 `brew install python@3.12` |
| Windows | 官网 python.org 下载安装包，**安装时务必勾选 "Add python.exe to PATH"** |
| Linux | `sudo apt install python3.12 python3.12-venv`（Ubuntu）或发行版对应命令 |

> 已有 conda / uv 的同学：只要满足 **Python ≥ 3.11** 且能执行 §2.4 的安装命令，也可以用它们，后续命令不变。

### 2.2 第 1 步 · 拿到课程仓库

**方式 A（推荐，便于以后更新）**：

```bash
git clone https://github.com/ai-guru-global/fde-scope.git
cd fde-scope
```

**方式 B（不会 git）**：在仓库页面点 `Code → Download ZIP`，解压后进入文件夹即可。

> ⚠ 之后所有命令都必须在**仓库根目录**下执行（能看到 `pyproject.toml` 和 `examples/` 的目录）。90% 的"文件找不到"都是这里出的错。

### 2.3 第 2 步 · 创建虚拟环境

```bash
python3 -m venv .venv
```

然后激活（每次新开终端都要做一次）：

| 系统 | 激活命令 |
|---|---|
| macOS / Linux | `source .venv/bin/activate` |
| Windows (PowerShell) | `.venv\Scripts\Activate.ps1` |
| Windows (CMD) | `.venv\Scripts\activate.bat` |

激活成功的标志：命令行提示符最前面多了 `(.venv)`。

> 为什么要虚拟环境？把课程依赖装进项目自己的"抽屉"里，不弄乱你电脑上的其他 Python 项目，也不需要管理员权限。

### 2.4 第 3 步 · 安装依赖

```bash
pip install -e ".[dev]"
```

等价写法 `python -m pip install -e ".[dev]"`（更不容易装错解释器，推荐）。

解释一下这行命令：

- `-e` = 可编辑安装，仓库代码改动能立即生效；
- `[dev]` = 核心层 + 测试 + Web 控制台（FastAPI/uvicorn）**一次装齐**——课程要用的都在里面。

期望结果：末尾出现 `Successfully installed ...`。

### 2.5 安装成功的判定

三个信号，缺一不可：

1. 提示符有 `(.venv)`；
2. `pip install` 末尾显示 `Successfully installed`；
3. 运行 `fde-scope --help`，能看到 `connect` / `corpus` / `eval` / `web` 等命令列表。

> 如果第 3 条报 `command not found`，改用 `python -m fde_scope.cli --help` 验证——两者等价，后者更稳。

## 3. 冒烟测试与故障排查

### 3.1 冒烟五条命令（与 `06` G0 同源）

在仓库根目录、`(.venv)` 已激活的状态下依次执行：

```bash
# 1. Python 版本
python3 --version
# 期望：Python 3.11 或更高

# 2. 命令可用
fde-scope --help
# 期望：打印命令列表（connect / corpus / eval / deploy / web / engage / gate …）

# 3. 看数据（学员 D1 产出 1 的一部分）
fde-scope connect --type csv --source examples/quickstart_csv/sample_tickets.csv
# 期望：schema 表（含 PII? 列）+ rows≈… · categories=… · channels=…
#       + 样本预览 + "✅ Sample extracted → samples/preview.json"

# 4. 造语料（学员 D1 产出 1 的另一半）
fde-scope corpus --input examples/quickstart_csv/sample_tickets.csv --out reports/corpus_report.html
# 期望：PII 脱敏条数 → 去重+质量门淘汰数 → "✅ Corpus forged: N real + M synthetic = T total"
#       + 覆盖缺口列表 + "📊 Report → reports/corpus_report.html"（同时生成 corpus_report.json）
# 打开报告：在文件管理器（访达 / 资源管理器）里双击 reports/corpus_report.html
#          —— 会自动用浏览器打开（报告是网页文件，不用装任何东西）

# 5. 控制台（可选但强烈建议）
fde-scope web
# 期望：🚀 Launching http://127.0.0.1:8080 —— 浏览器打开即可
```

**必做：为后续所有练习准备示例数据**（D1 的 blocker 截图、D2 的案例研读、D4 的 KPI 都靠它）：

```bash
python examples/seed_mock_engagements.py
```

会向 `.fde_scope/engagements` 写入 10 个**完全虚构**的客户案例（脚本内附免责声明），可在 Web 控制台里浏览门禁记录、现场记录与技能库；重复执行安全（幂等）。

造完之后马上验一次（**这一步顺便帮你确认数据目录找对了**）：

```bash
COLUMNS=200 fde-scope engage list
# 期望：10 行，id 形如 eng-teaverse-ticket-seed01 / eng-adnova-ticket-seed06 …
```

> ⚠ 两个小坑，先知道了就不会慌：
> - **不加 `COLUMNS=200`，id 列会被截断**成 `eng-adnova-t…`，看着像坏了，其实只是终端宽度不够。
> - **必须在仓库根目录跑**。数据目录靠"当前目录下有没有 `.fde_scope/`"定位；在别的目录跑**不会报错，只会显示 `No engagements yet.`**——遇到这句先 `cd` 回仓库根目录，而不是重新 seed。
>
> 10 个档案分别适合练什么，见 [`12`](12-附录-术语表与模板库.md) §3.2「拿来就能抄的档案 id」。

**到此为止 = 环境全部就绪。** 后面所有天的内容都只用到上述命令的变体。

### 3.2 故障排查表

> 90% 的问题在下表里。按"现象"对号入座；处理完仍不行 → §3.3 环境急诊室。

| # | 现象 | 最可能原因 | 处置 |
|---|---|---|---|
| 1 | `command not found: fde-scope` | 虚拟环境没激活 | 重新执行 §2.3 的激活命令（提示符应出现 `(.venv)`） |
| 2 | `No module named fde_scope` | 装到了别的 Python 环境 | 激活 venv 后重跑 `pip install -e ".[dev]"`；用 `python -m fde_scope.cli` 验证是否指向了当前环境 |
| 3 | `No such file or directory: examples/...` | 不在仓库根目录 | `cd` 回仓库根目录（`ls` 能看到 `pyproject.toml`） |
| 4 | `pip: command not found` | pip 不在 PATH | 用 `python3 -m pip install -e ".[dev]"` |
| 5 | `error: externally-managed-environment` | 系统 Python 受保护（macOS Homebrew / Ubuntu 新版） | 不要加 `--break-system-packages`；**回到 §2.3 建 venv** |
| 6 | `pip install` 超时 / SSL 报错 | 网络到 PyPI 不通 | 换国内镜像源：`python -m pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`，重试；公司网络见 §5.2 |
| 7 | Windows 终端中文乱码 / `UnicodeEncodeError` | 终端编码不是 UTF-8 | PowerShell：`$env:PYTHONUTF8="1"`；CMD：`set PYTHONUTF8=1`；或 `chcp 65001` |
| 8 | 报错里有 `docker` / `agentscope` 字样 | 混入了进阶路径 | **课程路径不需要它们**；逐字比对 §3.1 的命令重跑 |
| 9 | `fde-scope web` 启动失败：端口被占用 | 8080 被别的程序占了 | 换端口：`fde-scope web --port 8081` |
| 10 | `Web UI needs the 'web' extra` | 装的是精简版 | `pip install -e ".[web]"`（`[dev]` 里已含，重装 `[dev]` 也行） |
| 11 | `Refusing to bind non-loopback host` | 想把控制台开给局域网看 | 默认只绑本机是**安全设计**；确需局域网演示见 §6.5 |
| 12 | 任何 Python 版本 < 3.11 的报错 | 装的是旧 Python | 回 §2.1 装新版本，再重建 venv |
| 13 | `fde-scope engage list` 显示 `No engagements yet.`（**什么错都没报**） | 不在仓库根目录——数据目录按"当前目录有没有 `.fde_scope/`"定位，换目录就找不到了 | `cd` 回仓库根目录（seed 过的档案就回来了，**不用重新 seed**）；或从别处用 `FDE_SCOPE_HOME=<仓库绝对路径> fde-scope …` |
| 14 | `engage list` 的 id 带省略号（`eng-adnova-t…`） | 终端宽度不够，表格列被截断 | 命令前加 `COLUMNS=200`：`COLUMNS=200 fde-scope engage list` |
| 15 | 跑 `gate check` / `advance` 后凭空多出一张 `skill-xxxx` 草稿卡 | **设计如此**：门禁阻塞被自动沉淀成知识（飞轮） | 预期行为，不是污染。`fde-scope skill review` 看待审队列，`fde-scope skill archive <skill-id>` 清掉不想要的 |

**通用三步自救法**：① 读报错最后一行（原因永远在最后一行）；② 逐字比对 §3.1 命令（路径/拼写）；③ 确认 `(.venv)` + 仓库根目录这两个前提同时成立。

## 4. 零 key 路径与 LLM 可选配置

### 4.1 默认：零 key 规则路径

不配置任何环境变量时，**所有核心功能照常工作**，走确定性规则路径：

| 能力 | 零 key 时的行为 |
|---|---|
| 数据体检（`connect`） | ✅ 完整可用 |
| 语料锻造（`corpus`） | ✅ 完整可用（规则合成 + 规则质量评分） |
| 评估（`eval --agent mock`） | ✅ 完整可用（规则回复器） |
| Runbook / 交接（`handoff`） | ✅ 模板路径可用 |
| Web 控制台（`web`） | ✅ 完整可用（含看板、门禁、报告浏览） |

**所以：没有 API key 完全不影响你过 G0–G8。** 这是本课程相对其他 AI 课的底气——现场客户经常不给外网，FDE 必须习惯"规则先行"。

### 4.2 什么时候才需要 key

只有三个入口在无 key 时会明确报错（exit 2）并提示你配置，其余命令静默走规则模式：

- `corpus --llm`（LLM 合成补盲样本）
- `eval --agent mimo`（用 LLM 充当被评测的客服 Agent）
- `handoff --llm`（LLM 生成 Runbook 初稿）

课程中这三项都是**可选演示**，不是任何门禁的必需项。

> 💡 **先别急着配 key**：8 天里你**不需要**任何 key 就能拿满 G0–G8。
> 只有讲师演示 LLM 加成、或你自己想听"真模型"的声音时才需要——到那时
> 由**带教在课上统一发放**一个仅限本期演示用的临时 token（不找讲师私下要，
> 也不要用自己公司的 key 练手）。所以 §4.3 现在**跳过也没关系**，标记一下
> 待 D4 演示前再回来看即可。

### 4.3 两种配置方式（任选其一）

**方式 A · 小米 MiMo Token Plan（讲师在课上发放，仅教学演示用）**：

```bash
export FDE_SCOPE_MIMO_API_KEY="tp-..."     # tp- 前缀，与按量付费 sk- 不通用
# 以下两项可省略（已是默认值）：
export FDE_SCOPE_MIMO_BASE_URL="https://token-plan-cn.xiaomimimo.com/v1"
export FDE_SCOPE_MIMO_MODEL="mimo-v2.5-pro"
```

**方式 B · 任意 OpenAI 兼容端点**（vLLM / OpenAI / DeepSeek / 本地 Ollama…）：

```bash
export FDE_SCOPE_LLM_BASE_URL="http://localhost:11434/v1"
export FDE_SCOPE_LLM_API_KEY="sk-..."
export FDE_SCOPE_LLM_MODEL="qwen3:14b"     # 可省略，默认 gpt-4o-mini
```

两种都配时，**方式 B 优先**。

Windows 上把 `export X=Y` 换成：PowerShell `$env:X="Y"`；CMD `set X=Y`（仅当前窗口有效）。

### 4.4 凭据纪律（红线，与仓库 `AGENTS.md` 一致）

1. **key 只从环境变量读**——不要写进任何文件（包括 `.env`、笔记、YAML）、不截图、不进录屏、不进群。
2. 报告、清单、engagement JSON、日志里**永远不会有 key**（工具本身也不会写）——如果哪天你在文件里看到了 key，那一定是手写进去的，立刻删掉并检查有没有提交到 git。
3. 公司环境里用 key：先确认公司允许把哪类数据发往该端点（§6.6）。

### 4.5 失败自动回退

配了 key 也不怕坏：所有 LLM 入口都是**失败自动回退规则路径**——网络错误、坏 JSON、额度用尽都不会中断流水线，最多是"这次没有 LLM 加成"。现场演示前建议主动拔网线跑一遍，感受降级行为（面试 Q14 会考）。

### 4.6 验证 key 是否生效

```bash
fde-scope corpus --input examples/quickstart_csv/sample_tickets.csv --llm --out reports/corpus_report_llm.html
```

- 生效：输出里合成样本量明显多于纯规则路径，报告 JSON 中 trace 可区分来源（`synthesize:llm`）。
- 未生效：`LLM disabled ... falling back to rule-based mode`——回 §4.3 检查变量名拼写与终端窗口（新开窗口需重新 export）。

## 5. 按人群的环境方案

### 5.1 个人学习（默认方案）

照 §2 走一遍即可。建议**开营前 3 天**装完，留出排错余量。

### 5.2 公司电脑（受限环境）

| 限制 | 对策 |
|---|---|
| 无管理员权限 | §2.3 的 venv 装在用户目录，不需要管理员权限 |
| 必须走公司代理 | `pip install --proxy http://<代理地址>:<端口> -e ".[dev]"`；或让 IT 配好 `pip config` |
| 内网镜像源 | `python -m pip config set global.index-url <公司镜像地址>`（找 IT 要） |
| 完全离线（air-gap） | 提前 3 天找助教要**离线安装包**：在有网机器上 `pip download "./.[dev]" -d wheelhouse`，拷贝到目标机后 `pip install --no-index --find-links=wheelhouse -e ".[dev]"`。⚠ 别开营当天试 |
| 公司安全软件拦截 | 报错截图发群；必要时走 §3.3 保底方案 |

### 5.3 企业内训（团队采购）

- 统一镜像 / 统一 Python 版本 / 统一镜像源，由 IT 或助教提前部署；
- 建议开营前一周发本文件给学员自查，收集"已装好"接龙（`08` §3 T-1 清单）；
- 现场备 2–3 台**预装好的备用机**——环境事故不能占用课堂时间。

### 5.4 讲师环境（提前 24 小时冻结）

- 在**干净环境**完整跑一遍 D1 冒烟链路（本文件 §2–§3 全部命令）；
- 冻结演示环境：关掉自动更新、固定窗口布局、清空历史记录与可疑数据；
- 按 `05` §1 的清单逐项过；演示数据只用虚构案例（`examples/seed_mock_engagements.py`）。

### 5.5 我在用 Cursor / Copilot / 别的 agent CLI，这课还能上吗？

**能上。但门禁演示必须回到本仓库的 CLI。** 这一节是把边界说清楚，免得第 3 天才发现。

先给证据（工具实测 · 2026-10-08）：本仓库**没有** `adapters/` 这类目录，也没有针对第三方 agent 运行时的适配层；
而开源同行 FDEOps 根目录就有 `adapters/` 与 7 种 agent 适配（`24` §4.2 与 §6 #3）。
**这是我们公开的短板，不是没写进文档**——已同时记入 `01` §6.4 与 `13` §6 第 11 项。

三类东西分开看：

| 类别 | 具体 | 能不能带进别的 agent |
|---|---|---|
| **产出物** | runbook、语料报告、门禁记录 JSON、作业模板、结营包 | ✅ 能。它们是 Markdown/JSON，任何编辑器与任何 agent 都能读、能改、能当上下文引用 |
| **判定与状态** | G0–G7 的通过与否、`engage advance` 的**拒绝**行为、`FDE_SCOPE_HOME` 下的持久化状态 | ⛔ 不能。这些只在 `fde-scope` 里求值——**是设计选择**：门禁每次推进都重新求值，不做缓存也不做短路（仓库 `AGENTS.md` 不变量 1）。把判定搬进别的运行时，就等于把"会不会被拦"变成"没人拦" |
| **凭据与数据** | API key、任何真实客户名 / PII | ⛔ 一律不带。key 只从环境变量读（`AGENTS.md` 不变量 3）；真实数据禁入任何第三方工具（本文件 §6.1 红线 3） |

课堂口径三句话：

1. D1–D8 的命令一律用 §2.4 装好的那个虚拟环境里的 `fde-scope` 执行，**不要用别的 agent 的 shell 去猜命令**。
2. 用第三方 agent 写文档、读代码、做检索都可以——它读到的是你导出的**产物**，不是我们的状态机。
3. 结营作品集的评级只看 `fde-scope course labs` 的机器判分项与门禁记录（`03` §5），**别的 agent 帮你写的字不会多给你一分**。

> 一句话对外口径（可直接粘贴到招生页）：
> "本课的方法论落在可携带的 Markdown/JSON 产物上，任何 agent 运行时都能读；
> **验收判定故意不便携**——因为'会拒绝人'必须有一个可信的执行者。"

## 6. 数据合规与 PII 红线（不可协商）

> 本节与 [`03`](03-评估体系与通关门禁.md) §7 第 4 条、[`08`](08-运营手册.md) §11 同源。D2 开课 10 分钟内会逐条讲；**违规 = 数据合规事故**（`03` §8 一票否决项）。

### 6.1 三条红线

1. **只用两类数据**：课程自带虚构数据，或**你自己已脱敏并经公司同意**的数据。
2. **真实客户名与 PII 不进群、不上传**——包括作业、截图、提问里的粘贴内容。
3. **不进任何第三方工具**——在线标注平台、在线 JSON 格式化、网盘、聊天机器人，一律不发。

### 6.2 PII 识别清单（练习前过一遍）

姓名 / 手机号 / 邮箱 / 身份证号 / 地址 / 车牌 / 银行卡 / 订单号 / 设备序列号 / 门禁记录 / 聊天记录里的可定位信息……

> 判断标准一句话：**这条信息能不能定位到具体某个人？** 能 → 按 PII 处理。

### 6.3 工具怎么帮你兜底

- `connect` 输出的 schema 表有 `PII?` 列，可疑字段标 ⚠；
- `corpus` 报告显示 `PII entities masked` 条数——**别把这当免罪符**：自动脱敏是辅助，判断责任在你。

### 6.4 脱敏四步法（自用数据时）

| 步 | 动作 | 例 |
|---|---|---|
| 1 拿掉 | 与任务无关的 PII 直接删列 | 客户表里的身份证列 |
| 2 替换 | 保持格式、换掉内容 | 张伟→客户A，138****1234→13800000001 |
| 3 哈希 | 需要保留关联性时 | 用户ID → `u_3f9a…`（同人同哈希） |
| 4 保真 | 分布、长度、语言风格不变 | 脱敏后仍能被质量门正常处理 |

### 6.5 上传与展示边界

- `fde-scope web` 默认只绑本机 `127.0.0.1`，这是安全设计；不写 `FDE_SCOPE_API_TOKEN` 时认证是关的，但**只对回环生效**——从非回环地址到达的请求会被直接 403；
- 需要局域网演示（给同事看）：**必须两步同时做**——`FDE_SCOPE_ALLOW_REMOTE=1` + 设置 `FDE_SCOPE_API_TOKEN`（控制台 API 的访问令牌，只从环境变量读，不落文件/日志/响应）；只设 opt-in 不设 token 会拒绝启动，绕过 CLI 用 `uvicorn` 起服务也一样，局域网请求 403；演示完立即关掉；
- 截图前 3 秒检查：有没有真实姓名 / 客户 logo / 域名 / 工单编号露在画面里。

### 6.6 LLM 边界

- 使用 `--llm` 时样本内容会发往你配置的端点——**脱敏之后才可以**；
- 公司数据未经许可不得发往任何外部端点（含 MiMo / OpenAI / 在线大模型）；
- 客户只要 air-gap → 直接走 §4.1 零 key 规则路径，全链路不受影响。

### 6.7 违规处置（与 `08` §11 第 3 条一致）

群内一旦出现真实客户名 / PII → 立即撤回 + 私聊 + 记录合规日志；该学员产出退回、替换为脱敏数据重做。情节严重者记入证书备注。

### 6.8 提交前自检五问

1. 这份产出里的数据，我能说出"它是虚构的"或"它脱敏过且公司同意"吗？
2. 截图里有没有任何能定位真人的信息？
3. 群里发的报错原文，有没有粘贴到真实数据？
4. 用 `--llm` 之前，样本脱敏了吗？公司允许发这个端点吗？
5. 本地演示暴露面（`--host`）恢复默认了吗？
