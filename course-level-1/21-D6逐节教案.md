## 0. 今天的三条红线（全天不许破）

| # | 红线 | 怎么守 |
|---|---|---|
| 1 | **只准出现 3 个新概念**：SLO 与错误预算 · Runbook（事件响应与回滚）· 漂移与监控。第 4 个（SLI / 燃烧率 / MTTR / 混沌工程…）一律**进停车位，课后再讲**。客户面前说人话：SLO = "坏了多久算坏"，错误预算 = "这个月还能坏多久"，Runbook = "出事照着做的那张纸" | 开课前把停车位画好；每次有人冒新词，笔一指停车位，不上台展开（[`05`](05-讲师手册.md) §2） |

## S1 · 回炉（0–10 min · 10 min）

**本节定位**：D5 交上来的四件证据里，**"评估可复现"和"Top3 带动作"是本节的讲评素材**；同时用一问一接龙，把全班从"评估心态"切到"运维心态"——**从"怎么证明它行"切到"它半夜坏了我怎么办"。**

**一句话目标**（开场念）："今天不聊效果。今天只聊一件事：**你走了以后，谁修？**"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–3 | **G5 讲评：一优一劣**（各 1 分钟 + 30 秒收口） | 把"可复现 / 带动作"两条 blocker 再钉一遍 |
| 3–8 | **开场问 + 群接龙**："你走了以后，谁修？" 沉默 10 秒 → 接龙"我最怕接到的那个凌晨电话" | 制造今天的心理入口：文档是给别人用的 |
| 8–10 | 今日地图：三个新概念 + 停车位 + 三件产出 | 让学员知道 90 分钟后手里会多什么 |

### 讲稿要点

**① 0–3 min｜G5 讲评：一优一劣**（[`05`](05-讲师手册.md) §2：优的要讲"为什么好"，劣的要讲"我也犯过"）

- **优（念原话 + 为什么好）**：抽一份"Top3 四要素齐全 + 每条动作有人做/有数量/有期限"的。念完追问全班：
  > "好在哪里？**好在换个人接手也能看懂。** 记住这句——今天你要做的事，就是把这个标准推到运维文档上。"
- **劣（不点名）**：找一份"Top3 只写现象、没写动作"或"验证记录只写接受了什么、没写拒绝了什么"的：
  > "这份我第一天也这么写——**现象是感受，动作才是承诺。** 今天三件产出，我会用同一把尺子量：**你写的每一句，别人照着能做吗？**"

**② 3–8 min｜开场问 + 群接龙**（[`05`](05-讲师手册.md) §4 D6 第 1 条原话：'"你走了以后，谁修？" 让沉默 10 秒再继续。'）

- 念完问题**真的沉默 10 秒**（盯着秒表，不许救场）。10 秒后不点名、不评价，直接发群接龙：
  > "群里接一条：**我最怕接到的那个凌晨电话是什么样。** 一句话，不许写'系统挂了'这种废话——写画面。"
- 讲师先自接一条作示范，再挑三条**有层次**的念出来，逐条点评（这三条是今天的"事件地图"）：

| 群接龙（示例） | 讲师点评 | 今天对应 |
|---|---|---|
| "你们的机器人不动了。" | 现象级电话——**你至少知道它坏了** | Runbook 事件 1（服务不可用） |
| "我们的人照着你的文档修，修完更坏了。" | **这是真问题**——修坏了没有回滚，等于把人推进坑 | G6 ① 每类回滚（blocker） |
| "它没报错，只是慢慢变差了。" | **最成熟的一条**——已经在担心"没有报警的坏" | 概念 3：漂移与监控（今天全场就练这个） |

**③ 8–10 min｜今日地图**

- 三个新概念写黑板（今天就这三个，多一个都进停车位）：
  1. **SLO 与错误预算**——"坏了多久算坏"+"这个月还能坏多久"
  2. **Runbook（事件响应与回滚）**——"出事照着做的纸，退路写在里面"
  3. **漂移与监控**——"AI 不是坏了才叫坏，慢慢变差也是坏"
- 三件产出物写黑板（S3 结束时每人手里要有初稿）：**SLO 卡 / Runbook / 值班交接卡**。

### 互动设计

- **沉默 10 秒**是全天的第一个行为艺术：不许有人说话，讲师也闭嘴。10 秒后再开口的那句话是：**"刚才那 10 秒，就是你客户的运维在凌晨 2 点盯着屏幕的感觉。"**
- 群接龙**只挑 3 条念**——不追求全念完，剩下的留作 S4 复盘时的素材（"刚才还有人接龙说……"）。

### 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 讲师心软，沉默 3 秒就自己接话 | 助教在台下打手势：**数字数**。这 10 秒是今天的招牌动作，破了就没味道了 |
| 学员接龙写成"系统挂了，很慌" | "写**画面**：谁的电话、几点、他说了哪句话、你当时手里有什么" |
| 有人问"我们又没有真值班，写这个干嘛" | "D8 面试会问、客户签字会看。**没有值班表，也要有值班文档**——它是你专业度的体检报告" |

## S2 · 讲与演（10–35 min · 25 min）

**本节定位**：全天的**认知核心**。用六幕实测把一句话凿进脑子：**工具只挡"零"，不挡"糊弄"**——门禁拦住"没写 SLO"的人，但拦不住"写了三条空话 SLO"的人；Runbook 的门在工具里**根本不存在**。结论：**Zone C 的质量，人判，不是机器判。**

**一句话目标**（开场念）："接下来 25 分钟，你只需要看懂一件事：**工具能帮你挡什么、挡不住什么——挡不住的部分，怎么自己兜住。**"

### 分钟级时间盒

| 分钟 | 幕 | 动作 | 这一幕教什么 |
|---|---|---|---|
| 10–14 | 幕 1 | `engage list`（窄/宽两次）+ `gate check` 白湖（成品） | 成品长什么样；工具会截断你的视野且**不提醒** |
| 14–19 | 幕 2 | 4 个残缺变体对照（无 SLO / 无路由 / 无预算 / 只有 1 条） | **工具只挡"零"，不挡"糊弄"** |
| 19–24 | 幕 3 | `handoff` 生成 Runbook 骨架，逐段拆 | 骨架 ≠ 交付物；**模板不认识你的客户** |
| 24–29 | 幕 4 | 拿 §4.2 的"重连"做一次**当场盲测** | "命令级"的文档才敢过凌晨 2 点 |
| 29–33 | 幕 5 | 监控模板默认全关（`enabled: false`） | **概率性退化**：慢慢变差也是坏 |
| 33–35 | 幕 6 | `gate check` 说"has no gate" | 工具的门很浅；G6 的 4 条**3 条靠人** |

### 讲稿要点

**① 幕 1（10–14 min）｜先看别人家的成品**

- 先跑**窄版** `engage list`（不加 `COLUMNS=200`），指出：列被截成 `eng-adnova-t…`、`pre_engagem…`——**工具没有任何提示**。
  > "先记住这个画面：**数据被截断的时候，工具不报错。** 这和你昨天遇到的'全 0.0000 不报错'是同一种沉默。"
- 再跑 `COLUMNS=200` 版，14 行全貌。指出今天主角两位：**白湖乳业（ticket，slo_sla 阶段）**与**亚特联汽车（manufacturing，runbook 阶段）**。
- 跑 `gate check eng-whitelake-ticket-seed10` → `✅ PASS · gate=slo`。
  > "这是'别人家的成品'：一个乳业的工单助手，已经有 SLO 了。**昨天你在 D5 跑出来的那些数字，今天要变成一纸承诺。**"

**② 幕 2（14–19 min）｜四个残缺变体，四种命运**

- 依次跑四个变体，每跑一个**先让全班猜**（举手：会过还是被挡？），再揭晓：

| 变体 | 缺什么 | 实测结果 | 退出码 |
|---|---|---|---|
| `eng-d6-noslo` | **完全没有 SLO** | `❌ BLOCKED` + `🚫 未定义任何 SLO——错误预算/告警路由缺失` | **1** |
| `eng-d6-noroute` | SLO 缺告警路由 | `✅ PASS` + `⚠️  SLO 缺告警路由: ['availability', 'alert_response_p95', 'bad_case_rate']` | 0 |
| `eng-d6-nobudget` | SLO 缺错误预算 | `✅ PASS`（**没有任何提示**） | 0 |
| `eng-d6-one` | 只有 1 条 SLO | `✅ PASS` | 0 |

- 三个结论，逐条钉死：
  1. **工具只挡"零"**——`noslo` 被拦，因为它是"什么都没写"；
  2. **工具不挡"糊弄"**——`nobudget` 全无错误预算，照样静默通过。**G6 ② 是 blocker，但工具根本不查它**；
  3. **"1 条也算数"**——`one` 通过。数量不是工具的事，**是 G6 原文"3 条起"的事，得靠人判**。
- 补一句被挡下后的彩蛋（念屏）：
  > `💡 已把这次阻塞沉淀为草稿 skill-… — fde-scope skill review 可查看并完善`
  > "注意：**被挡住不是白挡**——工具顺手把它沉淀成了一张草稿技能卡。这就是 D7 技能卡的前奏。"（⚠️ 草稿 ID 每次运行都不同，**别背 ID**，现场跑 `skill review` 看）

**③ 幕 3（19–24 min）｜生成骨架 ≠ 交付物**

- 跑 `handoff eng-atlas-manufacturing-seed02 --accept`，屏幕出现移交包 + `runbook → /tmp/fde-d6-demo/reports/runbook_eng-atlas-manufacturing-seed02.md`。
- 打开生成的 Runbook，**和 G6 逐条对**，现场列差距：

| G6 要求 | 生成骨架的实测表现 | 差距 |
|---|---|---|
| ① 5 类事件 | 亚特联只有 **3 类**（回复质量退化 / 数据接入中断 / 安全事件） | 缺 2 类（指标暴跌、权限或配额、上游依赖挂 里的至少 2 类） |
| ① 每类含回滚 | 回滚是**全局一段**（§5 三步），**没有按事件分类** | 每类事件都要有自己的回滚段 |
| ② 错误预算 | 骨架 §3 有预算列，但白湖模板里有、亚特联是"预算内/已耗"这种**概数** | 要写成**可算的数字**（如 99.5%/月 → 3.6h） |
| ③ 告警路由 | 骨架 §3 有 `primary-oncall` 这类路由 | 没有**渠道 + 响应时限**表 |
| ④ 盲测 | 工具没这个概念 | 纯人测 |

- 再打开**白湖的 Runbook** §4.2（它是 ticket / 乳业），念出这句：
  > `- **诊断**: 检查 OPC UA / MQTT / MES 连接；网络/OT 隔离变更。`

### 讲稿要点

**① 35–38 min｜定对象 + 建文件**

- 三件文档各自**独立成文件**（G6 按件判分），文件名先建好——**文件名就是承诺**。
- 写之前先答一个问题（写屏幕上）：**"你这个系统，坏了多久算坏？"**
  > "回答不了的，先别写 SLO——你连'坏'的定义都没有。"

**② 38–48 min｜SLO 卡：三条起，每条都要能测**

- 格式照抄 [`12`](12-附录-术语表与模板库.md) §2.7，**一字不改**：

| # | 指标 | 目标值 | 测量方式 | 数据来源 | 覆盖时段 |
|---|---|---|---|---|---|
| 1 | 可用性 | ≥99.5%/月 | 健康检查成功率 | 监控平台 | 7×24 |
| 2 | 响应延迟 P95 | ≤2s | 请求耗时直方图 | 监控平台 | 7×24 |
| 3 | 分类准确率 | ≥91%（周抽样 200 条） | 每周固定测试集重跑 | D5 的 `eval` | 每周 |

- **判据原文**（[`12`](12-附录-术语表与模板库.md) §2.7）："三条起。**每条必须有目标值 + 测量方式**，否则不是 SLO，是口号。"
- **错误预算现场算**（白板推一遍，全班跟算）：
  ```
  可用性 99.5% / 月  →  30 天 × 24 h × (1 − 0.995) = 3.6 h
  ```
  > "这句话翻译成人话：**这个月你还能坏 3.6 小时。** 烧完了怎么办？——"
  > 念 [`12`](12-附录-术语表与模板库.md) §2.7 原文："预算烧完（>100%）→ **暂停新功能，优先修稳定性**。"
- **告警路由表**（照 §2.7 三档）：

| 严重度 | 触发条件 | 通知谁 | 渠道 | 响应时限 |
|---|---|---|---|---|
| P0 | 服务不可用 >5min | 值班工程师 + 我方 | 电话 + 群 | 15 分钟 |
| P1 | 延迟 P95 >5s 持续 10min | 值班工程师 | 群 | 1 小时 |
| P2 | 准确率周环比跌 >5pt | 项目负责人 | 邮件 | 1 个工作日 |

> "**通知谁**这一列只写角色。"——**这是今天红线 3**。

**③ 48–58 min｜Runbook：5 类 × 四段**

- 五类事件标题照 [`12`](12-附录-术语表与模板库.md) §2.8（**一字不改**）：服务不可用 / 指标暴跌 / 数据异常 / 权限或配额 / 上游依赖挂。
- 每类四段：**判断信号 → 处置步骤 → 回滚步骤 → 升级路径**。给一个"指标暴跌"的样例，全班照抄结构：

| 段 | 好例子（可抄） | 反面例子（当场改） |
|---|---|---|
| 判断信号 | "bad_case_rate 周环比 +5pt 连续 2 周；对应看板告警触发" | "感觉效果变差" |
| 处置步骤 | "1) 拉出最近 7 天 bad case Top20；2) 分类归因；3) 若集中在单一类别 → 补语料重训" | "排查一下" |
| **回滚步骤** | "**若重训后指标不升反降 → 切回上一版模型快照（版本号写在变更记录里）**" | "恢复备份"（= 没说） |
| 升级路径 | "第一级：值班工程师（角色）；2 小时未恢复 → 第二级：FDE on-call" | "联系负责人" |

- 前置条件行也要写（§2.8 原话照抄）：
  > 前置：值班人员需具备 <终端操作 + 看日志> 能力，无需懂模型。

**④ 58–64 min｜值班交接卡：四段**

- 格式照 [`12`](12-附录-术语表与模板库.md) §2.9，四段：**当前状态 / 待办（下一班注意）/ 已知风险 / 联系人**。
- 一句话讲清它是什么：
  > "**它是班次之间的接力棒。** Runbook 管'出事怎么办'，交接卡管'交接时别丢信息'——今天你写完就算数，真值班时每天更新。"

**⑤ 64–67 min｜互换盲测（3 分钟）**

- 找一位同学，**交换 Runbook**，对方大声念；念到读不下去的地方**当场举手**。三刀模板（[`07`](07-实战剧本与案例库.md) §3.5）：
  > `B（举手）：这里写"检查服务健康"——凌晨 2 点的人具体敲什么命令？`

### 互动设计

- **巡场第一趟只问一句**（[`07`](07-实战剧本与案例库.md) §4.2 风格）："**这条 SLO 怎么测？谁测？多久测一次？**"——答不出的不算过。

- 写 Runbook 前 2 分钟，让学员**闭眼想一个画面**：凌晨 2 点，一个没参加过你项目的人，打开你这份文档的第一眼——他看到什么？

### 学员动作（现场）

- 建三件文件 + 盲测记录（四个文件名一次建好）

- 写 Runbook（5 类 × 四段；每类的"回滚步骤"用**对象级标识**：哪个快照 / 哪个版本 / 哪份配置）
- 写值班交接卡（四段）
- 做 1 次 3 分钟盲测，记下 ≥3 条断点并当场修
- 按命名规范改文件名

### 常见错误与纠偏

| 错误 | 纠偏（助教用） |
|---|---|
| SLO 写成"尽量快 / 尽可能稳" | "**目标值 + 测量方式**，缺一个 = 口号（[`12`](12-附录-术语表与模板库.md) §2.7 原话）。改成'P95 ≤2s，耗时直方图，7×24'" |
| Runbook 只写"怎么修"，没写回滚 | "**修坏了怎么退？**（第二趟巡场只问这一句）不写回滚 = G6 ① 不过（blocker）" |
| 回滚写"恢复备份 / 回滚一下" | "回滚必须**指名道姓**：哪份快照、哪个版本号、哪份配置——'上一个语料快照（`reports/corpus_report_*.json`）' 这样写" |
| 联系人写了真人姓名 / 手机号 | **当场替换**为角色（primary-oncall / fde-oncall / 客户运维）；提醒 [`11`](11-工具与环境准备.md) §6 红线：姓名 / 联系方式的现实版就是 PII |
| 5 类事件想不出第 5 类 | "照 [`12`](12-附录-术语表与模板库.md) §2.8 标题逐个填：服务不可用 / 指标暴跌 / 数据异常 / 权限或配额 / 上游依赖挂。**上游依赖挂**最容易忘——你的模型服务挂了算谁的？" |
| 值班交接卡写成日记 | "四段就好：当前状态 / 待办 / 已知风险 / 联系人。**别加戏，这是给别人交接用的**" |
| 盲测找不到人换 | 助教现场配对；一个人也能做：**隔 10 分钟自己再读一遍**，读不下去处当场标红 |

### 承接语（最后 30 秒）

> "停一下——看看你手里的三件文档。
> 接下来 10 分钟，**我会随机抽一份，让别人按你的文档当场念。**
> 现在，把你文档里最虚的那一句标出来，**等会儿被抽到，就是它。**"

### 学员笔记要点

- 错误预算算法：`30 × 24 × (1 − 0.995) = 3.6 h`（自己再算一遍）

- 回滚步骤的唯一标准：**指名道姓**（哪个快照 / 哪个版本）
- Runbook 合格线：**没参与过的同事，只照文档能独立处理**
- 我的盲测断点（≥3 条）：____________________________________

## S4 · 复盘（70–80 min · 10 min）

**本节定位**：用"凌晨 2 点盲测"把三件文档**当众过一遍火**。今天这台戏的唯一 KPI：**每一处"读不下去"，都被现场抓出来并现场修掉。**

**一句话目标**（开场念）："接下来谁被抽到，谁就把文档念出声——**念到卡住的地方，举手的是全体。**"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 70–74 | **讲师示范一轮**：随机抽一份 Runbook，按 [`07`](07-实战剧本与案例库.md) §3.5 三刀连问 | 让全班看到"断点"长什么样 |

### 讲稿要点

**① 70–74 min｜讲师示范：先测"别人家的成品"**

- 用幕 3 留下的亚特联 §4.2（原文照念），按 [`07`](07-实战剧本与案例库.md) §3.5 剧本逐刀问（**不笑、不寒暄**）：

| # | 念到的原文 | 讲师（扮凌晨 2 点的值班同事）问 | 断在哪一层 |
|---|---|---|---|
| 1 | "检查 OPC UA / MQTT / MES 连接" | **"我敲哪个命令看连接？在哪个界面看？"** | 命令层 |
| 2 | "必要时切换到离线快照语料" | **"哪个快照？最近的还是昨天的？目录在哪？"** | 对象层 |
| 3 | "升级：FDE on-call" | **"FDE on-call 是谁？怎么找到他？他不接怎么办？"** | 人层 |

- 每砍一刀，**白板记一个字**：`命令` / `对象` / `人`。
- 念来源（[`07`](07-实战剧本与案例库.md) §3.5）："**观察点**：每处卡壳都是 Runbook 的断点，A 学员当场记下并修复；修复后再测一次。"

**② 74–78 min｜两两交换再测**

- 规则（写屏幕）：
  1. **念的人用嘴，不用手**——不许帮作者解释"我懂你的意思"；
  2. **卡住就举手**，两秒内举；
  3. 作者**只记不辩**——现在不是辩护时间，是找断点时间；
  4. 测完交换角色，**两轮各测一份**。
- 讲师/助教走动听，重点盯**三种人**：写满术语的（抽象层断点多）、联系人写"找我就行"的（= #3 Hero Engineer 现场版）、回滚栏空着的（G6 ① 直接不过）。

**③ 78–80 min｜断点归类 + 反模式点名**

| 抓到的模式 | 命名（[`12`](12-附录-术语表与模板库.md) §1.6） | 现场替换 |
|---|---|---|
| "找我就行 / 我手机 24 小时开着" | **#3 Hero Engineer**（全靠一个牛人扛，他一休假就瘫） | "值班角色 + 升级路径；我休假时第一级照样有人接" |

| "我们的效果一直挺稳的，应该不会出事" | **#7 Probabilistic Degradation**（系统悄悄变差，无人发现） | "SLO 周环比 + 漂移阈值；用一个数字看着它" |

- 收口金句（[`05`](05-讲师手册.md) §7）：**"凌晨 2 点没人爱你，除了你的文档。"**

### 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 作者抢着解释"这里的意思是……" | 打断："**你的文档不在场的时候，谁来解释？** 念的人只读字面——这就是凌晨 2 点的真实" |

| 时间不够，两轮只做了一轮 | 不加时；**没轮到的那一半在 S6 补测**，助教盯 |

### 讲稿要点

**① 80–84 min｜G6 四条 + 命名 + 截止**

- **G6 原文**（[`03`](03-评估体系与通关门禁.md) §3，逐字念）：
  > ① Runbook 含 5 类事件且**每类有回滚步骤** ② SLO 卡含错误预算 ③ 明确告警路由（谁/渠道/响应时限） ④ 通过"凌晨 2 点盲测"（同事按文档能处理）

- 念完 G6 后问一句：**"今天谁的 Runbook 里还有'恢复备份'这四个字？举手。"**（不点名，只记数字——S6 助教会重点盯这部分人）
- 盲测记录环节让大家**当场写一行**：**"我盲测里最狠的一刀是：______"**
- D7 预告用**沉默**收尾：问完"明天你要把手里的东西交给一个不爱你的人"——**停 3 秒**再下课

### 学员动作（现场）

- 记下四个提交物的**准确文件名**与截止时间（次日 21:30）
- 当场写一行：我最狠的那一刀：____________
- 在日历上标 D7 日期 + "带齐 D6 四件"
- 群里回一句：**"四件齐。"** 或 **"还差 ____。"**（诚实报缺口）

### 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 学员问"盲测记录是附件，能不能不交" | 不劝——只念 G6 ④："**'通过凌晨 2 点盲测'是 blocker。** 记录是你'做过'的唯一证据" |
| 有人说"我找不到人给我盲测" | "S6 里有配对；实在没有，**自己隔 10 分钟再读**，读不下去处一样算断点" |
| 有人拿 D5 的评估报告当盲测记录 | 明确区分：**D5 测"系统行不行"，D6 测"文档扛不扛得住"**——两码事，都要交 |
| 助教替学员写 Runbook | **不许**。助教只能问："你这五类里，哪一类的回滚还没写？" |

### 承接语（最后 30 秒）

> "今天你们第一次为'不在场的自己'写东西。**明天开始，你要把它交给一个不爱你的人。**
> 下课。四十五分钟自练，助教在群里。"

### 学员笔记要点

- G6 四条（①②④ blocker / ③ warning）+ 各自的**不通过形态**
- 四个提交物文件名 + 截止 + 补交规则
- 盲测记录三行表结构；**"修法"列写的是改后的原文**
- 我最狠的一刀：____________
- D7 三问（抄一遍）：
  1. **明天你要把手里的东西交给谁？**（一个不爱你的人）
  2. 技能卡的"适用边界"是什么？
  3. 你留的"最后一次签名"是什么？

## S6 · 自练（+45 min）

**本节定位**：独立完成、自测、提交。目标只有一个：**三件文档都过得了 G6 ①②④**，盲测记录过 ④。

**一句话目标**：把"写完了"变成"**凌晨 2 点的人能照着做**"。

### 45 分钟怎么分（投屏建议）

| 分钟 | 干什么 | 产物 |
|---|---|---|
| 0–12 | 补齐 Runbook：**5 类 × 四段**（重点：每类的"回滚步骤"指名道姓） | `D6-姓名-Runbook` |
| 12–22 | 打磨 SLO 卡：测量方式逐条落实；**算出错误预算数字**；路由表补"渠道 + 时限" | `D6-姓名-SLO卡` |
| 22–30 | 写值班交接卡（四段）+ 全文档联系人角色化复查 | `D6-姓名-值班交接卡` |
| 30–38 | 找同学**再做一轮盲测**（或补测），记录断点与修法 | `D6-姓名-盲测记录` |
| 38–43 | 自评 G6 四条 + 逐条打钩 + 改文件名 | —— |
| 43–45 | 提交 + 群里发 60 秒收获 | 提交 |

### 三条路径（学员按自己情况选一条）

| 路径 | 谁选 | 做什么 |
|---|---|---|
| **A 完成** | 大多数人 | 四件产出齐活 + 提交（**别加戏，先交出去**） |
| **B 迁移** | 手里有**已脱敏且经公司同意**的运维信息 | 把 SLO 目标值换成**你系统真实历史**支撑的数字（如可用性目标参照近 3 个月实际）；**文档里只写指标与阈值，不写客户名、IP、域名、账号**（[`11`](11-工具与环境准备.md) §6.1） |
| **C 加练** | 想再挖一层 | ① 给你 Runbook 的"事件 2 · 指标暴跌"补上**具体阈值**（周环比跌几个点触发？连续几周？）并写成"判断信号"；② 挑一类事件，把它的四段**浓缩成 Post-it 大小**——练"给凌晨 2 点的人减负" |

> 路径 C 的第一步特别值钱：**你会亲手把"效果变差"这种感受，改写成一个会响的数字。**

### 完成标准（提交前逐条打钩）

```
☐ SLO 卡 3 条起；每条有【目标值】+【测量方式】（缺一 = 口号）
☐ 每条 SLO 有错误预算（写成一个数字：如 99.5%/月 → 3.6h）
☐ 告警路由表有【严重度 / 触发条件 / 通知谁（角色）/ 渠道 / 响应时限】
☐ Runbook 覆盖 5 类事件：服务不可用 / 指标暴跌 / 数据异常 / 权限或配额 / 上游依赖挂
☐ 每类事件四段齐全：判断信号 → 处置步骤 → 回滚步骤 → 升级路径
☐ 回滚步骤写到"命令/对象"级（不含"恢复备份"这类含糊话）
☐ 值班交接卡四段：当前状态 / 待办 / 已知风险 / 联系人
☐ 全部联系人写角色（primary-oncall 等），无真实姓名 / 手机号 / 邮箱
☐ 盲测记录 ≥1 次，含断点清单（层 + 修法 + 复测结果）
☐ 命名：D6-姓名-SLO卡 / -Runbook / -值班交接卡 / -盲测记录
```

### 卡点急救

| 卡在哪 | 怎么救 |
|---|---|
| 写不出 3 条 SLO | 从白湖 §3 抄**骨架**（可用性 / 响应时长 / 坏例率），把目标值换成你自己的；数量先够 3 条，质量靠测量方式 |
| 错误预算算不出来 | 公式：`天数 × 24h × (1 − 目标值)`。99.5%/月 → `30×24×0.005 = 3.6h`；99%/月 → 7.2h |
| 5 类事件不知道写什么 | 对着 [`12`](12-附录-术语表与模板库.md) §2.8 五个标题逐个填；每类先写"判断信号"——**你凭什么知道出事了？** |
| "回滚写不出来" | 问自己："这个动作之前，系统在跑什么？"（上一版模型 / 上一份语料快照 / 上一版配置）——把它写成对象 |
| "联系人写谁？" | 只写角色。被问"找他没用怎么办" → 这就是**升级路径第二级**存在的意义 |
| 盲测没人配对 | 助教现场配对；或自己隔 10 分钟再读一遍，**读不下去的地方就是断点** |
| `engage list` 输出很窄 / 列被截 | `COLUMNS=200` 重跑（**不是数据丢了，是显示截断**——今天幕 1 教过） |
| 想跑 `gate check` 自查 | 只有在 `.fde_scope/` 里有档案时才有效；**今天的三件文档是 Markdown 交付物，门禁在 [`06`](06-学员手册与作业包.md) D6 任务卡里自查** |

### 助教值守规则

- **只回答两类问题**：① 规则类（命名 / 截止 / G6 判据 / 模板格式）② "这条回滚算不算'指名道姓'"
- **不回答**：D7 之后的方案类问题；"我能不能少写一类事件"这类豁免请求（**① 是 blocker，不商量**）
- 每 15 分钟在群里发一次进度提示（"还有 30 / 15 / 5 分钟"）
- 收到提交后**只回一个字**：`✓`（讲评在次日 08:30 门禁榜 + D7 回炉）
- 提交里出现**真实客户名 / PII / 真实账号** → **立即私聊要求撤回重交**，并记录合规日志（[`11`](11-工具与环境准备.md) §6.7）
- 学员问"我这算通过吗" → **只回一句**："**5 类都有回滚吗？错误预算是个数字吗？盲测做了吗？** 三条都是'是'，就是过。"

### 学员动作

- 45 分钟独立完成（路径 A / B / C 三选一）
- 自评 G6 四条 + 完成标准逐条打钩
- 提交 → 收到 `✓`
- 在群里写 60 秒收获（照 [`07`](07-实战剧本与案例库.md) §5 模板）：
  「**对方最难的那个问题是什么？我用了什么回应？下次我会改什么？**」

### 常见错误与纠偏

| 错误 | 纠偏（助教用） |
|---|---|
| Runbook 写成"说明书"（长篇介绍背景） | 递回 [`12`](12-附录-术语表与模板库.md) §2.8：「**五类事件，每类四段**」——它要的是操作步骤，不是背景介绍（[`06`](06-学员手册与作业包.md) D6 常见坑第 1 条） |
| 忘了写回滚 | "**修不好怎么退？**"——补完再提交（[`06`](06-学员手册与作业包.md) D6 常见坑第 2 条） |
| SLO 写得很漂亮但一个都测不了 | "**每条必须有测量方式**（[`12`](12-附录-术语表与模板库.md) §2.7）。测不了的指标删掉或降级成'待补充'" |
| 盲测记录写成"效果很好" | "记录里只留三种东西：**断点、修法、复测**。'很好'不是证据" |
| 21:30 前赶不上 | 别慌：**24 小时内补交 = 正常放行（标注"补交通过"）**——但要**在群里报一句"我补交"**，别静默（[`06`](06-学员手册与作业包.md) §5） |
| 提交里带了真实客户名 / 账号 | **撤回重交 + 合规日志**，不做例外（[`11`](11-工具与环境准备.md) §6.1 / §6.7） |
