> **一句话**：8 天只够把链路走通一遍，能力长在课后的 90 天里。

## 1. 90 天路线图：12 周练习 + 1 周缓冲

### 1.1 为什么给 90 天，而不是"回去多练练"

"回去多练练"是一句没有终点的话，等于没有布置作业。所以这一章给的是一个**有日期、有交付物、
有复评点**的 90 天：13 周 × 每周 2–2.5 小时 ≈ **26–32 小时**（设计口径），
终点就是 D+90 的等级复评（§6）。

它也是我们对应竞品长周期课程的诚实答案：竞品用 4–6 个月讲完体系，我们用 8 天把链路走通一遍，
**再用 90 天把"走过"变成"练过"**。想深造的仍然要去学模型与工程底层——那是另一条路
（[`13`](13-GTM页面与竞品对比.md) §6 #1 这条短板我们不打算靠话术抹平）。

### 1.2 13 周总表

| 阶段 | 周次 | 主题 | 每周投入 | 交付物 | 复评点 |
|---|---|---|---|---|---|
| **复跑** | W1–W2 | 把 8 天重走一遍（W1 用 seed 档案对照，W2 从零建自己的第二个档案） | 2–3 h | 差异清单（"我当时漏了什么"）+ 第二个档案跑到 `success_criteria` 且门禁通过 | ✅ **D+14** |
| **A/B 区纵深** | W3–W5 | 现场与干系人 → 语料 → 真实脏数据原型 | 2–3 h | 现场卡片 / 语料报告 / 原型 + 落差记录 |  |
| **C 区纵深** | W6–W7 | 稳定性承诺与值班：SLO → runbook → 监控漂移 | 2–3 h | SLO 卡 + Runbook + 值班交接卡 | ✅ **D+45** |
| **工业纵深** | W8–W11 | 七个工业门禁沙盘（§5），每周两关 | 2–3 h | 七份沙盘材料（含"被拦一次"的记录） |  |
| **综合与缓冲** | W12–W13 | 综合走一遍 manufacturing 全流程 + 作品化 + 缓冲 | 2–3 h | **90 天纵深包**（见 §2.1） | ✅ **D+90** |

**W1 的起点命令**（在仓库根目录执行）：

## 2. 三个复评点：D+14 / D+45 / D+90

### 2.1 复评点交什么、怎么判

| 复评点 | 交什么（提交物） | 判定方式 | 判不过怎么办 |
|---|---|---|---|
| **D+14** | 复跑记录：差异清单（≥5 条"我当时漏了/做错了什么"）+ 第二个档案的门禁记录截图 | 自评 + 社群互评（同一期学员两两交换看） | 不是"淘汰"——把差异清单补齐即可，**复评点不是门禁** |
| **D+45** | C 区材料包：SLO 卡 + Runbook + 值班交接卡 | 自评 + 助教抽检（**抽检比例是设计口径，第一期结束后回填**） | 同上；C 区材料是结业等级复评的硬材料，缺了会挡住升级 |
| **D+90** | **90 天纵深包**：① 第二个档案全流程的门禁记录；② C 区材料包；③ 工业沙盘材料（若第一个档案是 manufacturing）；④ 一页"这 90 天我改掉了什么习惯" | **必须导师参与**（因为要发等级复评结论） | 等级维持原状（不是降级），可申请下一期复评 |

> 💡 **复评 ≠ 门禁**。课程门禁（[`03`](03-评估体系与通关门禁.md) §3 的 G0–G8）决定你能不能往下一步走，
> 复评决定的是**结业等级要不要动**（C→B→A）。复评没过不丢人，隐瞒不交才丢人。

### 2.2 D+90 的长期跟踪口径

D+90 复评用的三个跟踪问题与 [`09`](09-运营指标与复盘.md) §11 的长期跟踪**是同一套**——
运营侧问的是"课程有没有用"，学员回答的顺便就是自己的复评材料。别重复填两遍：
第一次填完，把副本留给自己，D+90 复评直接交它。

## 3. 影子项目（形态 D）SOP：什么时候能碰真实场景

### 3.1 形态 D 是什么、不是什么

| 是 | 不是 |
|---|---|
| 在**客户书面同意**的前提下，学员在导师 **≤1:3** 的监护下参与一个**范围极小**的真实场景 | 不是实习、不是外包、不是"免费劳动力换经验" |
| 练的是"真实约束下做判断"：真实脏数据、真实干系人、真实截止时间 | 不承诺客户会采纳你的产出 |
| 产出是**方法与骨架**，以及（可选、经双签的）脱敏摘要 | 不承诺收入、不承诺就业、不承诺下一期一定有 |

> 形态 D 与 [`04`](04-交付实施手册.md) §1 的 A/B/C 三形态并列，是**在 A 之后、面向少数人**的加档，
> 不是默认产品。它的存在理由只有一个：把 [`13`](13-GTM页面与竞品对比.md) §6 #3"没有真实客户项目"从"结构性缺失"
> 变成"有条件可得"。

### 3.2 客户侧准入四件套（缺一不可）

1. **书面同意书**：范围、数据范围、签字人、退出机制，四样都写进同一份文件。
2. **场景边界说明书**：一句话问题定义（客户的问题，不是平台能力）+ 明确**不做什么**。
3. **数据最小化声明**：只要必需字段；能匿名就不假名化，能假名化就不带标识。
4. **退出/中止条款**：任一方可随时中止，并写明中止后的数据处置时限。

### 3.3 数据边界：真实数据不出客户环境

这是形态 D 最硬的一条纪律，也是它"贵"的原因——所有环节都得加一层隔离。

| 规则 | 具体做法 |
|---|---|
| **数据不出客户边界** | 在客户环境（或其指定的隔离环境）内处理；学员带走的是**方法结果**与**脱敏摘要**，不是原始数据 |
| **仓库只放虚构** | 仓库、群聊、作业包、截图、录屏里**永不**出现真实客户名、真实工单文本、真实个人信息 |
| **凭据只走环境变量** | API key / 数据库口令一律从环境变量注入，**绝不**落进 engagement JSON、报告、日志、截图、群聊 |
| **离开必过双签** | 任何要离开客户环境的样本，先过 §3.4 的双签 |

### 3.4 脱敏双签：两道签名，一个验收标准

- **签谁**：客户数据负责人 + 我方导师。两名自然人各签一次，**不能代签**。
- **签什么**：脱敏规则清单（哪些字段删除 / 掩码 / 泛化）+ 实际执行记录（对样本逐项勾）。
- **验收标准（记住这一条就够）**：把样本给一个不认识该客户的人看，他**说不出**客户是谁、
  也认不出任何一个自然人。做不到就再脱一遍，不要"差不多就行"。
- **留档**：签字件留在客户侧；我们这边只留一份"已双签"的记录——**不含数据本身**。

### 3.5 权限与凭据

- **只读优先**。任何写权限必须**双人复核 + 有回滚路径**。
- 凭据只从环境变量读（这是本仓库的不变量之一，写在 `AGENTS.md`）。
- 生产环境默认不碰。要在生产验证，先问一句："有没有影子环境？"

### 3.6 交付确认：措辞纪律（这一条最容易吹）

| ✅ 允许写 | ❌ 禁止写 |
|---|---|
| 已按约定范围完成 X 的输出物 | 已为客户创造 N 万元效益 |
| 客户侧联系人已收到并确认收件 | 客户已验收 / 已上线 |
| 在 X 场景内取得 Y 结果（附口径与样本量） | 显著提升 / 大幅优化 |

原因很简单：把"处理过"说成"验收过"，是作品集里最容易被一眼看穿的夸大，
而 [`10`](10-变现路径与结营包.md) §8 的"不承诺"纪律同样约束**描述**而不只是承诺。

### 3.7 中止与退出：中止不丢人，隐瞒才丢人

- **触发**：客户撤回同意 / 导师判断越界 / 学员判断做不下去 / 出现数据风险。
- **动作**：立即停止接触数据 → 24 小时内通知双方 → 按约定期限销毁并留销毁凭证 → 记入「中止档案」。
- **中止档案怎么写**：如实写"因 X 中止"，**照样可以进作品集**（写清你学到了什么）。
  藏起来当没发生过才是反模式（§7）。

### 3.8 导师配比与现实（接着认账）

- 影子项目导师配比 **≤1:3**，而训练营的助教配比是 `1:15–20`（[`04`](04-交付实施手册.md) §1）。
  差一个量级，因为它碰真实数据。
- **现实**：这条**很重**，它正是 [`13`](13-GTM页面与竞品对比.md) §6 #8"交付人力重"的直接来源——
  我们靠收窄规模来换合规，不靠省略步骤来换便宜。
- 因此执行顺序是：**先做 §4 的替代轨道 → 攒到 3 个以上学员到 B 级 → 每期影子项目最多 3 人**。

## 4. 没有影子项目怎么办：三条替代轨道

影子项目不是默认产品（§3.1）。绝大多数人走的是下面三条轨道——它们**不是次等品**，
只要在作品集里如实标注性质，一样能拿 A 级。

| 轨道 | 怎么做 | 能拿到的证据 | 缺什么 |
|---|---|---|---|
| **虚构档案全链路** | 自己建第 3、第 4 个档案，把 18 阶段走完（`engage init` + 逐级 `advance`） | 完整门禁记录 + 作品集 8 件 | 真实约束：真实脏数据、真实的人、真实的截止 |
| **公开数据集** | 用公开数据集（**注明来源与许可**）做 connect → corpus → prototype → eval | 真实脏数据的处理方法与落差记录 | 仍然没有客户与干系人 |
| **身边小场景** | 自己的/朋友的**非敏感**小场景（如社团报名表整理、自家小店的排班表） | 真实干系人（哪怕只有一个） | 规模小——**别包装成"企业项目"** |

> ⚠ 三条轨道都必须在作品集里**标注性质**（虚构 / 公开数据 / 真实小场景）。
> 标注本身就是 [`03`](03-评估体系与通关门禁.md) §7 的"诚实标注"评分维度；不标 = 送分题反向做。

## 5. 七个工业门禁教学沙盘

这一节是 [`13`](13-GTM页面与竞品对比.md) §6 #7"工业纵深未经教学验证"的答卷：
把 7 个工业门禁**逐个变成一道可批改的练习**。工具侧的证据要求来自
`fde_scope/engagement/guided.py` 与 `fde_scope/engagement/gates/*.py`，命令都实测过。

### 5.1 统一跑法

```bash
# 0) 前提：仓库根目录 + 环境就绪（11 §3.1）
python examples/seed_mock_engagements.py     # 幂等

# 1) 看工业档案走到哪、哪一关被拦
COLUMNS=200 fde-scope engage list
fde-scope engage status eng-southbay-manufacturing-seed03

# 2) 只看某关为什么被拦（带 --gate 指名单关；不带则查当前阶段）
fde-scope gate check eng-southbay-manufacturing-seed03
#   ❌ BLOCKED · gate=fat_sat
#     🚫 SAT (Site Acceptance Test) 未执行或未记录
#   💡 已把这次阻塞沉淀为草稿 skill-…（阻塞本身就是知识，见 12 §3.2）

# 3) 照参考答案：读一个"材料齐全"的档案里那一关要写什么
python - <<'PY'
import json, pathlib
p = pathlib.Path(".fde_scope/engagements/eng-aurora-manufacturing-seed07.json")
print(json.dumps(json.loads(p.read_text())["assets"]["air_gap_plan"],
                 ensure_ascii=False, indent=2))
PY
```

读完参考答案，**写进你自己的档案**（别改 seed 档案，改坏了要重新 seed）：

```bash
fde-scope engage init --customer "沙盘练习" --profile manufacturing
# 然后（把 <id> 换成上一步生成的 id，通常是 eng-沙盘练习-manufacturing）
python - <<'PY'
import json, pathlib
from fde_scope import paths
from fde_scope.engagement import Engagement, EngagementContext

eid = "<id>"
f = paths.engagements_dir() / f"{eid}.json"
eng = Engagement(EngagementContext.load(f))
eng.ctx.assets["shift_handover"] = {
    "digital_log_integrated": True,
    "per_shift_runbook": True,
}
eng.ctx.save(f)            # 原子写入（fsutil.atomic_write_text）
print("written:", f)
PY
```

> ⚠ **不适用 ≠ 通过**——这是整个沙盘最重要的一条。7 关里有 **4 关是"情境性"的**：
> 情境字段没打开时，它们会返回 **PASS 并附一句"本 gate 不适用"**。那不是你通过了工业门，
> 是那道门根本没被考到（[`12`](12-附录-术语表与模板库.md) §3.2 里"要命的坑"的机理解释）：

| 门禁 | 情境开关（开在现场卡片 / 安全卡片里） | 开关关着时的行为 |
|---|---|---|
| `site_survey` · `fat_sat` | 工业档案（`--profile manufacturing`）必过，无开关 | — |
| `functional_safety` | 无开关；但缺 `PLr`/`SIL` 要求时**只给 warning 不阻断** | 值不写全 = 门被绕过（最隐蔽的一关） |
| `conformity` | `safety.eu_ai_act_high_risk` | `false` 时 CE marking 只是 warning，不阻断 |
| `works_council` | `site.works_council_represented` | `false` → **PASS** +「现场无 works council 代表，本 gate 不适用」 |
| `air_gap` | `site.air_gapped` | `false` → **PASS** +「非 air-gapped 现场，本 gate 不适用」 |
| `shift_handover` | `site.shift_count > 1` | `≤1` → **PASS** +「单班次现场，shift handover 不适用」 |

**所以每个沙盘的练法是两步**：先**把情境字段按工业真实值填上**（让门真的会拦人），
再**把材料写齐**（让它真的通过）。只做第二步 = 练了个"不适用"。

### 5.2 七个沙盘

| # | 门禁 | 情境怎么打开 | 要写齐的材料（工具侧证据） | 参考档案 |
|---|---|---|---|---|
| 1 | `site_survey` | 工业档案必过 | 现场卡片：地点 / 班次数 / 网络拓扑；**资产清单**（每台关键设备的 name·type·vendor·protocol·criticality）；OT/IT 隔离与气隙状态；工会在场与否 | `eng-horizon-manufacturing-seed08`（早期阶段）→ `eng-southbay-manufacturing-seed03` |
| 2 | `fat_sat` | 工业档案必过 | `assets.fat = {passed, signed_off_by, notes}` **和** `assets.sat = {…}`；SAT 必须现场执行且带客户签字（缺签字只 warning，**未通过直接拦**） | `eng-southbay-manufacturing-seed03`（有 FAT 无 SAT → 被拦）；`eng-atlas-manufacturing-seed02`（齐全） |
| 3 | `functional_safety` | 把 PLr / PL、SIL 要求与达成值都填上 | `safety.hazard_analysis_done`（STPA / HAZOP-lite 是前提）+ `required_plr`/`achieved_pl`（达成 < 要求 → 拦）+ `sil_required`/`sil_achieved` + `iso10218_assessed` | `eng-atlas-manufacturing-seed02`（PL d/d、SIL 2/2） |
| 4 | `conformity` | `eu_ai_act_high_risk = true` | `safety.ce_marking_done` + `assets.technical_construction_file`（EU AI Act **Annex IV** 技术构造文件）+ `hazard_analysis_done` | `eng-aurora-manufacturing-seed07`（只差这一件 → 全档唯一 ❌） |
| 5 | `works_council` | `works_council_represented = true` | `assets.works_council_approval = {status, signed_off_by}`；`status="denied"` → 拦（需重新协商）；`"pending"` → warning | `eng-atlas-manufacturing-seed02` |
| 6 | `air_gap` | `air_gapped = true` | `assets.air_gap_plan`：`edge_hardware`（机型与数量）、`offline_model_update`（介质·校验·回滚）、`telemetry_egress_allowed` **必须为 false**、`local_storage`（日志/语料/审计的本地持久化） | `eng-aurora-manufacturing-seed07` |
| 7 | `shift_handover` | `shift_count > 1`（如 3） | `assets.shift_handover = {digital_log_integrated, per_shift_runbook}`；**每班次要有一份 runbook 与应急联系人** | `eng-atlas-manufacturing-seed02` |

**建议的练习次序**：1 → 2 → 7 → 6 → 5 → 3 → 4。
前两关先建立"现场感"，`shift_handover`/`air_gap` 材料最短（先拿一个成功），
`works_council` 需要写协商过程，`functional_safety`/`conformity` 最贵（要动安全与法规判断，放最后）。

### 5.3 材料骨架：以 `air_gap` 为例

抄骨架、换成你自己场景的数字，**别照抄 seed 的数值**（那是虚构演示值）：

| 字段 | 写什么 | 自查问题 |
|---|---|---|
| `edge_hardware` | 机型 + 数量 + 摆在哪 | 断网它还能推理吗？ |
| `offline_model_update` | 介质 + 清单 + 校验 + 回滚 + 谁在场 | 出新模型时，怎么保证不把产线搞停？ |
| `telemetry_egress_allowed` | **必须是 `false`** | 有没有任何"偷偷 phone home"的默认开关没关？ |
| `local_storage` | 容量 + 保留期 + 谁有权限 | 审计要回看 180 天，存得下吗？ |

### 5.4 沙盘 ≠ 现场：这一节自己的诚实标注

沙盘能练到「材料怎么写、门怎么拦、缺什么」，**练不到**三件事：

1. **真实的脏数据**——seed 档案是干净的结构化演示值，现场数据不会这么客气。
2. **真实的签字压力**——SAT 的客户签字、工会的共决，沙盘里是字符串，现场是政治。
3. **真实的停机成本**——沙盘里 `advance` 被拒只损失一次命令，现场被拒可能损失一班产能。

所以本章**不会**因此在 [`13`](13-GTM页面与竞品对比.md) §6 #7 上写"已验证"。正确的说法是：
**7 关已可教学、可批改；是否真的补齐了工业纵深，要等第一期跑完、拿到 D+90 复评数据才算数**
（回填位置见 [`15`](15-公信力与结果度量.md) §4 的结果度量表）。

## 6. 等级复评与 Level 2 门槛

### 6.1 C→B→A 复评通道

结业等级的定义在 [`03`](03-评估体系与通关门禁.md) §6（A = 8 件产出齐全 + 均分 ≥9/12 + 无未达项 + 无延期；
B = ≥7/12；C = 缺 ≤2 件或 <7/12）。D+90 复评是**升级通道**：

| 方向 | 条件 | 结果 |
|---|---|---|
| C → B | 补齐缺件 + 90 天纵深包完整 | 换发 B 级电子证书 |
| B → A | 补齐 8 件 + 90 天纵深包 + 一份"改掉了什么习惯"的说明 | 换发 A 级证书 + 徽章；讲师签名表现信需另行评估（**不是内推**） |
| 维持 | 纵深包未交或未过 | **等级维持原状，不降级**；可申请下一期复评 |

> ⚠ 复评换发的证书与原证书**同一编号、带复评日期**——不新发编号，避免出现"两张证书"的歧义。
> 有效期与申诉口径见 [`15`](15-公信力与结果度量.md) §1。

### 6.2 Level 2 入学门槛（设计口径，**待开课**）

Level 2 目前**没有开设**。先把门槛写出来，是为了让你在 90 天里有明确的靶子：

1. 结业等级 **B 及以上**；
2. **独立**跑完 ≥2 个档案且门禁全绿（不是"跟着抄"）；
3. D+90 复评通过；
4. 工业方向加一条：§5 的 7 份沙盘材料齐全。

> ⚠ 这四条是**门槛设计**，不是招生承诺。Level 2 的开课时间、形态与价格都还没定——
> 在 [`13`](13-GTM页面与竞品对比.md) §9 的过期提醒机制里登记了这一项，一旦变动先改那里。

## 7. 反模式：这六种练法等于没练

1. **把 seed 数据当真项目写进简历**——虚构档案在简历里叫"编造项目经历"，一票否决级别的问题。
2. **影子项目写成"主导交付"**——[`10`](10-变现路径与结营包.md) §8 与 §3.6 的措辞纪律；写"参与并完成 X 输出物"不丢人。
3. **打卡式刷量**：90 天里建了 20 个档案全卡在 `qualification`——数量不是纵深，**跑完全链路的 2 个**胜过 20 个半截。
4. **只写材料不打开情境开关**——练出来的全是"不适用"（§5.1），等于没练。
5. **没有客户书面同意就动数据**——这是红线，不是"先做着看"；触发即中止（§3.7）。
6. **给"待补"的表格填数字**——[`15`](15-公信力与结果度量.md) §4 的结果度量表在第一批数据出来前必须留空，编数是自毁公信力。
