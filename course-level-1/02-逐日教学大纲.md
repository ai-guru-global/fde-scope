## Day 1 · 入门日：装上世界观与工具箱

**今日承诺**：一天结束时，你能用自己的话讲清 FDE 交付链路，并亲手跑通第一条迷你链路。
**时长**：6 小时（上午 3h + 下午 3h），线上直播。
**认知负荷红线**：全天只允许出现 **3 个新概念**（交付链路 / 门禁 / 真实数据）。
> 历史（Palantir 2003-、招聘数据——引用必须带时点，口径见 [`00`](00-FDE方法论历史与原理.md) §1.6）与原理（80/95/99、前线学习机制）**不占这 3 个额度**——
> 它们是 [`00`](00-FDE方法论历史与原理.md) 的课前读物与讲师备课底料，**不在直播里展开讲**；
> 直播只保留 M1 的 45 分钟"讲故事"版本（见 `00` §4 的对应关系表）。

**课前预读（开营前 20–40 分钟）**：学员读 [`00`](00-FDE方法论历史与原理.md) §1.0 + §1.1（30 秒速通版 + FDE 三位前身），
带一个问题进 D1："FDE 和售前、实施、外包到底差在哪？"——M1 的第一个互动就从这个问题的举手回答开始。

### 时间盒

| 时段 | 模块 | 内容 | 产出 |
|---|---|---|---|
| 09:00–09:30 | 开营 | 学员自我介绍（30 秒/人：我是谁 + 我最怕现场哪件事）；课程契约（D2–D8 每天约 2.25h、门禁制、诚实边界） | —— |
| 09:30–10:15 | M1 世界观 | FDE 是什么：Palantir 起源 → 2026 岗位爆发；FDE vs 售前/实施/客户成功（一句话对比）；FDE 的 40/30/30 能力模型（讲师展开素材见 [`00`](00-FDE方法论历史与原理.md) §1.1–§1.4、§3.6） | 世界观笔记 |
| 10:15–10:30 | 休息 | —— | |
| 10:30–11:30 | M2 交付地铁图 | 4 区 18 阶段讲成"4 条地铁线"；每站的"下车证据"；**门禁**概念（为什么清单会烂、门禁不会）；12 反模式里最常踩的 4 个 | 手绘/数字版地铁图 |
| 11:30–12:00 | M3 三律 | ①先成功标准后代码 ②在真实脏数据上原型 ③一切产出可验证 | —— |
| 13:30–14:30 | M4 工具箱开箱 | 安装 + 冒烟：`pip install -e ".[dev]"` → `fde-scope connect --type csv --source examples/quickstart_csv/sample_tickets.csv` → `fde-scope corpus --input … --out reports/corpus_report.html` → 打开报告 | 冒烟证据 |
| 14:30–15:30 | M5 看控制台 | `fde-scope web` → 工作台 / engagement 矩阵 / gate 面板 / 引导模式；打开一个 mock engagement 看门禁拦截的红色 blocker | 控制台截图 |
| 15:30–16:30 | M6 迷你链路挑战 | 学员独立完整跑一遍 connect → corpus，并向同桌用 3 句话解释"我刚才干了什么、为什么" | 🎯 产出 1 |
| 16:30–17:00 | 门禁 G1 + 答疑 | 对照 G1 检查表自评、提交；讲师预告 D2（明天你就是"进场第一天"） | 通过 G1 |

### 今日讲解要点（讲师提示）

- **用类比，不用术语**：18 阶段 = 地铁 4 条线；gate = 检票闸机（没票不放行）；corpus = 淘米（去砂、去石、补水）。
- **必须"故意翻车"一次**：演示时故意跳过成功标准直接跑 corpus，然后让学员指出问题——先体验代价，再讲原则。
- **降级路径**：学员装不上环境时，立刻切到 `11-工具与环境准备` 的故障排查表，助教 1v1；实在不行用助教共享屏幕代跑，学员口头指挥。
- **M1 讲深讲浅的分寸**：讲师手里的完整素材是 [`00`](00-FDE方法论历史与原理.md) §1–§2（Palantir 与 Ontology、三道成本门槛、80/95/99、前线学习机制），但直播**只讲到"故事层"**——起源时间线、40/30/30、一句"FDE 是做 80%→99% 那一段的活"。学员追问时按 `00` §5 的 8 条回应，**不要当天展开 §2.6 与 §3.4**（会挤爆 45 分钟）。

**常见问题**：

| 学员问 | 回答要点 |
|---|---|
| 我不会 Python 能学吗？ | 能。今天所有命令可复制；Level 2 才碰代码。 |
| 没有 API key 能跑吗？ | 能，全链路有零 key 路径（规则模式），LLM 是可选加速器不是门槛。 |
| 我一直在用 Qoder / Trae / CodeBuddy 写代码，要换工具吗？ | 不用换。课程只叠"流程与门禁层"，编码/办公工具继续用你顺手的（`01` §6.4）。 |
| 学完能进大厂做 FDE 吗？ | 本课给能力与作品集，不承诺结果；D8 会教你正确地把作品集用起来。 |
| FDE 的历史和原理要背吗？还有那些数据？ | **不背**。今天的 3 个新概念里没有它们。要用的场合只有两个：D8 模拟面试、到客户现场被追问——那时翻 [`00`](00-FDE方法论历史与原理.md) §5 的 8 条问答即可。所有市场数字都标了来源与日期（`00` §6），引用时**必须连来源一起说**，不确定的就说"待核实"。 |

**通关门禁 G1**：见 `03` —— 提交"迷你链路证据"（命令 + 一段白话解释 + 一份 corpus 报告截图）。

## Day 2 · Zone A 定边界：把模糊抱怨变成可交付的边界

**今日承诺**：拿到一句客户抱怨，产出"客户委托单"：画像 + 干系人地图 + 可度量成功标准。
**时长**：直播 90 min + 自练 45 min。
**今日 3 个概念**：qualification（值不值得做）· 干系人地图（谁拍板谁买单谁用）· 成功标准（可度量 + 书面 done）。

### 时间盒（直播）

| 时段 | 内容 |
|---|---|
| 10 min | 开炉回炉：抽考 D1 的 3 个概念 + 讲评 1 个错误案例 |
| 25 min | 讲与演：以虚构客户「茶语万象」为例，现场把一句抱怨拆成委托单；演示 `fde-scope engage init --customer "茶语万象" --profile ticket` 与 `fde-scope gate list` |
| 35 min | 上手上：学员用 `07` 的客户剧本做自己的委托单（助教巡场） |
| 10 min | 复盘：展示 1 优 1 劣；重点讲"成功标准写成形容词"这个典型错误 |
| 10 min | 布置 G2 + 明日预告 |

### 交付物要求（🎯 产出 2：客户委托单）

1. **客户画像**：行业、规模、谁付钱、当前怎么干活、痛在哪（≤1 页）
2. **干系人地图**：执行发起人 + **第二发起人**（防 Sponsor Collapse）+ 一线使用者 + IT/安全把关人；标注每个人的"在乎什么"
3. **成功标准**：≥3 条，全部可度量（含数字与时间）；附时间盒：≤14 天集成、≤90 天上线、≤120 天交接（引用自行业 FDE 实践）
4. **放弃标准**：什么情况下我们应该说"这个不该做"（拒绝商品化用例）

**今日反模式警示**：Sponsor Collapse（唯一发起人离职即死）、Infinite Pilots（没人定义 done）。

**通关门禁 G2**：成功标准 ≥3 条且全部可度量；干系人含 ≥2 位发起人；委托单 ≤1 页。

## Day 3 · Zone B 接数据：先看再装

**今日承诺**：拿到一份陌生 CSV/数据源，产出"数据体检报告"，说清能用多少、缺什么、风险在哪。
**今日 3 个概念**：schema 探测（字段/类型）· PII 红线（哪些字段碰不得）· 覆盖度（类别分布）。

### 时间盒（直播）

| 时段 | 内容 |
|---|---|
| 10 min | 回炉：G2 优秀委托单讲评（1 优 1 劣） |
| 25 min | 讲与演：`fde-scope connect --type csv --source examples/quickstart_csv/sample_tickets.csv` → 读 schema 预览与样本；讲 PII 候选字段（schema 标 ⚠——**注意它只按字段名判**：name/email/phone 这类列名才亮，本例四列一个都不亮，但 `content` 文本值里就写着手机号和邮箱 → **不亮 ≠ 没有 PII，自由文本必须逐条看值**）；讲"类别极度不均衡"意味着什么（A/B 两组都用这个文件起步；工业补充数据见 `examples/quickstart_manufacturing/`）|
| 35 min | 上手：每个学员/小组对自己分到的数据源做体检（助教巡场） |
| 10 min | 复盘：快速互评（相邻两人交换体检报告，找对方漏掉的 1 个风险） |
| 10 min | 布置 G3 + 明日预告 |

### 交付物要求（🎯 产出 3：数据体检报告）

- 数据源概况：条数、来源、采集方式、时间范围
- 字段清单与质量：字段名 / 类型 / 缺失率 / 异常值 / 备注
- PII 清单与处置建议：哪些字段必须脱敏、哪些根本别拿
- 覆盖度观察：类别分布 Top/Bottom，是否存在长尾盲区
- 风险与建议：一句话结论——"这份数据能支撑什么、不能支撑什么"

**今日反模式警示**：Data Quality Surprises（假设数据已集中、已干净）。

**通关门禁 G3**：报告含 PII 清单与 ≥3 条质量风险；给出"能不能做"的明确结论（不允许写"待定"）。

## Day 4 · Zone B 造语料：把矿石炼成金属

**今日承诺**：把脏数据锻造成一份可审计的语料报告，并能用客户听得懂的话讲清楚。
**今日 3 个概念**：质量门（什么样的样本不能进）· 去重与清洗 · 补盲合成（补缺口不是凑数量）。

### 时间盒（直播）

| 时段 | 内容 |
|---|---|
| 10 min | 回炉：D3 典型体检报告讲评 |
| 25 min | 讲与演：`fde-scope corpus --input <数据> --out reports/corpus_report.html`，逐段读报告：清洗后可用量、PII 脱敏数、覆盖盲区、合成补齐、train/eval/test 切分；（可选）`--llm` 合成路径与失败回退 |
| 35 min | 上手：学员跑通 corpus 并解读报告；写"对客户怎么说"的话术 |
| 10 min | 复盘：请学员用 3 句话向"客户"（助教扮演）汇报语料结果 |
| 10 min | 布置 G4 + 明日预告 |

### 交付物要求（🎯 产出 4：语料报告 + 客户话术）

- CorpusReport（HTML 或截图）+ 关键数字摘录：原始 N 条 → 可用 M 条（去重 X、质量门淘汰 Y）
- 覆盖度分析：盲区 K 个及补盲策略
- **客户话术**（≤200 字）：向非技术客户解释"你的数据能用多少、我们补了什么、为什么可信"——这一项是门禁硬指标
- 诚实声明：合成数据比例与来源标注

**今日反模式警示**：数据"凑数"（用合成量掩盖真实缺口）、不报告合成比例。

**通关门禁 G4**：报告数字与实际运行一致；话术里无术语（"语料/覆盖度"需替换成白话）；合成比例如实标注。

## Day 5 · Zone B 验证与评估：用证据说话

**今日承诺**：产出一个能演示的原型 + 一份评估结果 + 最该先修的 3 个 bad case。
**今日 3 个概念**：真实数据原型（不用策展测试集）· 评估指标（意图准确率/采纳率与业务口径）· bad case（改进抓手）。

### 时间盒（直播）

| 时段 | 内容 |
|---|---|
| 10 min | 回炉：G4 话术讲评 |
| 25 min | 讲与演：`fde-scope eval --agent mock --test-set test_set.jsonl` 读指标（测试集模板见 `12` §2.4，先自己造 5 行再扩到 200）；`fde-scope kpi <你的档案id> --samples examples/quickstart_manufacturing/station_samples.jsonl` 看场景 KPI；讲"demo 与生产的落差"为什么发生在这一步 |
| 35 min | 上手：学员跑评估；从 bad case 里挑 3 个并写"根因假设 + 下一步动作" |
| 10 min | 复盘：干系人验证演练——助教扮演"持反对意见的业务主管"，学员用数据回应 |
| 10 min | 布置 G5 + 明日预告 |

### 交付物要求（🎯 产出 5：原型 + 评估 + bad case）

- 原型证据：可运行命令与输出截图（或控制台 demo 录像 ≤2 min）
- 评估结果：主指标 + 至少 1 个业务口径指标
- bad case 清单：Top 3，每条含"现象 → 根因假设 → 下一步动作 → 预计改善"
- 一页"验证记录"：向谁演示了、对方提了什么、我们接受了/拒绝了什么（含理由）

**今日反模式警示**：Demo-Debt（演示里承诺平台做不到的事）、No HITL（假设全自动）。

**通关门禁 G5**：评估可复现（同命令同结果）；bad case 每条都要有"下一步动作"，不允许只描述现象。

## Day 6 · Zone C 运维化：让东西稳得住

**今日承诺**：产出 Runbook + SLO 卡 + 值班交接卡——你走了，系统也能活。
**今日 3 个概念**：SLO 与错误预算 · Runbook（事件响应与回滚）· 漂移与监控（AI 会退化）。

### 时间盒（直播）

| 时段 | 内容 |
|---|---|
| 10 min | 回炉：G5 bad case 讲评 |
| 25 min | 讲与演：`fde-scope gate check <你的档案id>` 看 `slo` 门禁检查了什么（SLO/SLA + 错误预算 + 告警路由）；演示 `fde-scope handoff <你的档案id>` 生成 runbook 草稿；讲"概率性退化" |

> `<你的档案id>` 用 `COLUMNS=200 fde-scope engage list` 查（不加 `COLUMNS` 会被截断成 `eng-xxx-t…`）；
> 想先看别人家的成品，用 `eng-southbay-manufacturing-seed03` 等行业种子档案，见 `12` §3.2。
| 35 min | 上手：学员为自己的场景写 SLO 卡与 Runbook（模板见 `12`） |
| 10 min | 复盘：盲测——随机抽一份 Runbook，问"凌晨 2 点值班的人按这份文档，能不能处理完？" |
| 10 min | 布置 G6 + 明日预告 |

### 交付物要求（🎯 产出 6：Runbook + SLO 卡 + 值班卡）

- **SLO 卡**：3 条 SLO（含目标值与测量方式）、错误预算、告警路由（谁在什么渠道多久内响应）
- **Runbook**：5 类常见事件（服务不可用 / 指标暴跌 / 数据异常 / 权限或配额 / 上游依赖挂）各自的：判断信号 → 处置步骤 → 回滚步骤 → 升级路径
- **值班交接卡**：交接要素（当前状态 / 待办 / 已知风险 / 联系人），适配多班次场景

**今日反模式警示**：Probabilistic Degradation（无飞轮，线上退化无人知）、Hero Engineer（只有你知道怎么修）。

**通关门禁 G6**：Runbook 含回滚步骤；SLO 卡有明确告警路由（缺路由只能算 warning，需补）；用"凌晨 2 点盲测"通过同事检验。

## Day 7 · Zone D 交接与沉淀：交得出去，带得走

**今日承诺**：产出完整交接包 + 把现场经验沉淀成可复用技能卡。
**今日 3 个概念**：交接包（交接的四件套）· 知识转移（教会 ≠ 讲完）· 退场（有始有终的时间盒）。

### 时间盒（直播）

| 时段 | 内容 |
|---|---|
| 10 min | 回炉：G6 盲测结果讲评 |
| 25 min | 讲与演：`fde-scope handoff <你的档案id> --accept` 装配交接包；`fde-scope skill add --title "<标题>" --category methodology --body "<正文>"` 沉淀技能卡，再 `fde-scope skill publish <skill-id>` 发布；讲"无限 Pilot"与"≤120 天交接"的行业时间盒 |
| 35 min | 上手：学员装配自己的交接包（4 件套 + 培训材料题纲），写 1 张技能卡 |
| 10 min | 复盘：交接签字演练（助教扮演客户运维负责人，提 3 个刁难问题） |
| 10 min | 布置 G7 + 明日预告（变现日预告：带齐 7 件产出） |

### 交付物要求（🎯 产出 7：交接包 + 技能卡）

- **交接包四件套**：Runbook + 评估报告 + SLO 卡 + 培训材料（题纲即可）
- **验收清单**：客户签收项逐条列出（谁验收、验收标准、签字人）
- **技能沉淀卡**（1 张）：本次最有复用价值的一条经验，格式：场景 → 问题 → 做法 → 证据 → 适用边界
- **退场计划**：交接后 30/60 天的支持安排与终止条件

**今日反模式警示**：Infinite Pilots（没有 done）、Consulting Trap（越做越像定制咨询，没人能接手）。

**通关门禁 G7**：交接包四件套齐全；技能卡含"适用边界"（防止经验被滥用）；退场计划有明确终止条件。

## Day 8 · 变现日：把 7 件产出换成职业资产

**今日承诺**：作品集三套包装完成；完成结营答辩；带走一份可以直接用的简历段落与面试题库。
**今日 3 个概念**：作品集（证据 > 描述）· 汇报公式（做了什么/证据/下一步要什么）· 变现三层（客户/雇主/个人）。

### 时间盒

| 时段 | 模块 | 内容 |
|---|---|---|

### 交付物要求（🎯 产出 8：作品集三套包装）

- 作品集索引页（一页）：8 件产出的名称、日期、证据链接、一句话价值
- 简历段落（3–5 行，使用 `10` 的句式模板，含数字）
- 一页纸汇报（给老板/客户）
