# D4 · 造语料 —— 判「切分与来源字段能不能对上账」

`06` Day 4 复用 D1 那条 `corpus` 命令，但换成另一组问题：**数据是怎么被切开的、
每一条能不能追回来历、给客户看的那段话里有没有漏术语。**
同一份 CSV，另一组断言——这是这一天 lab 的全部设计。

判分：**9 个机器项 + 1 个人工项**（可信度：工具实测，v0.1.0，2026-10-06）。
档案 `lab-d4`，profile `ticket`。8 项契约项 + 1 项写作项（`话术`）。

## 跑起来

```bash
./check.sh D4
starter/客户话术.md        # 唯一要写的那件，机器只判「有没有踩到清单里的词」
python -m fde_scope course check D4 --verbose
```

## 机器判了什么（9 项）

| # | id | 命令 / 面 | 判什么 |
|---|---|---|---|
| 1 | `corpus` | `corpus --input <lab 自带工单 CSV> --out <沙箱>/main/t.html` | 打印 `Corpus forged`（D1 判的是那句里的三个数，这一天只要求命令成功） |
| 2 | `splits` | `corpus_report.json` | `train.items` 长度 = **332** |
| 3 | `eval-split` | 同上 | `eval.items` 长度 = **41** |
| 4 | `synthetic-share` | 同上 | `synthetic == 395`（395/415 ≈ 95%） |
| 5 | `golden-zero` | 同上 | `golden == 0` —— 还没有人工标注的标准答案 |
| 6 | `diversity` | 同上 | `coverage.diversity_index ≥ 0.9`（实测值 0.9569） |
| 7 | `target-per-category` | 同上 | `coverage.target_per_category == 100`（缺口就是按这个目标算的） |
| 8 | `provenance` | 同上 | 报告里出现 `provenance` 字段，且文件 ≥ 100000 字节（实测 153650） |
| 9 | `话术` | `{{drafts}}/客户话术.md` | 无 `TODO`、≥ 300 字节，且**不含这五个词**（**写作项**） |

第 2/3 项加起来的账（我实测过，不是推的）：**332 + 41 + 42 = 415**，
`test` 切分 42 条。三块加起来正好等于总数，所以这一天没有数据泄漏、也没有丢行——
这就是 G4 ① 里"数字与实际一致"在这一天唯一可判的形式。

第 8 项是这一天的重心。`provenance` 是**每一条**样本上的字段（实测某条
`train.items[0].provenance == "synthetic"`），所以"这条是真、那条是补的"不是
你在报告里写的一句话，是 JSON 里逐条可查的标签。断言用 `min_bytes=100000`
而不是判某个值：只有把整份报告写全了才可能到这个体积，空壳报告一眼就红。

第 9 项拦的是这五个写法：**`SLO`、`P95`、`OEE`、`bad case`、`corpus`**
（加上 `TODO`）。`starter/客户话术.md` 里刻意不印这份清单，就是为了让你
先写、再被逐字拦下——删完 TODO 仍然红，才是这一天该学到的东西。

## 判不了的（1 项）

`话术质量`（`ManualCheck`）：`06` G4 的"话术让非技术负责人读一遍就能复述：
做什么、怎么算成功、现在做到哪"。**不进分母。**

## 工具与门禁的差距

| G4 自查（`03` §3） | 语义 | 工具/lab 拦得住吗 |
|---|---|---|
| ① 报告数字与实际运行一致 | blocker | ✅ 判了（第 2、3、4、5、7 项都落在同一份 JSON 上，且 332+41+42=415 自洽） |
| ② 有覆盖盲区说明与补盲策略 | blocker | ⚠️ 半判：第 6/7 项证明"缺口是按目标 100 条算出来的"；**策略是什么**判不了（D3 第 11 项给出 12 条可数缺口） |
| ③ 客户话术 ≤200 字且**零术语** | blocker | ⚠️ 只拦上面那五个英文写法。**"语料/覆盖度/合成/补盲/长尾"这几个中文词不在拦截列表里**，见下 |
| ④ 合成数据比例如实标注 | warning | ❌ 第 4 项只证明报告里**有** 395 这个数；你有没有在话术里讲出来，机器不知道 |

两个必须说清的边界，别把这一天判绿当成 G4 过了：

* **字数上限不判**。`06` 要求 ≤200 字，断言只有 `min_bytes=300`（下限）。
  中文字数与字节不等价，判上限容易给出看起来很稳实则没意义的数——所以留给讲师。
* **中文黑话不拦**。这不是能力问题（字符串匹配一样拦得住），是这一版的取舍：
  把中文术语放进 `not_contains`，连 `starter/` 自带的那段说明都会被自己拦下。
  要自己加严，改 `fde_scope/course/catalog.py` 里 D4 那条 `not_contains` 就行——
  加严之后必须重跑 `course check D4`，别沿用本文数字。

## 卡住了怎么办

1. **只有第 9 项红** → 先确认你改的是**数据根目录**下那份
   `course-labs/D4/客户话术.md`，不是 `starter/` 里的原件；再看那五个词——
   踩到 `corpus` 最常见（复制本报告里的字段名时会顺手写进正文）。
2. **第 2/3 项红、报 415 但切分不是 332/41** → 合成器带种子，同版本稳定；
   跨版本可能漂。先 `python -m fde_scope --version` 对一下是不是 v0.1.0。
3. **第 8 项红、体积不足 100000** → 你只跑了 `--dry-run`（`cli.py:180-182` 那条
   分支只打印计划、不落盘），或者 `--out` 指到了别处：`corpus_report.json`
   永远落在 `--out` **同目录**（`cli.py:222`）。
4. **第 6 项红** → `diversity_index` 判的是 ≥0.9 而非定值；红说明语料类别铺不开，
   检查 `--input` 是不是那份 20 行的 CSV。
5. **想手跑而不污染档案** → `corpus` 不读写 engagement，只吃 `--input`，
   随便在临时目录里跑（`--out` 用绝对路径）。
