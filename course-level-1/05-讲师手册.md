# 05 · 讲师手册（Facilitator Guide）

> 面向主讲讲师与助教。目标：**让任何合格的 FDE 从业者，按本手册都能带出合格的课。**
> 依赖：[`02-逐日教学大纲.md`](02-逐日教学大纲.md)（教什么）· [`07-实战剧本与案例库.md`](07-实战剧本与案例库.md)（用什么演）
> 备课底料：[`00-FDE方法论历史与原理.md`](00-FDE方法论历史与原理.md)（历史 / 原理 / 方法论 + §5 常见追问 8 条——**学员问到"为什么"时的弹药库**）

## 1. 讲师画像与备课清单

**能力要求**：做过至少 1 个完整交付项目；会用 `fde-scope` 全链路；能接受"小白式提问"不烦躁。

**备课量**：首期 ≈ 每天 4 小时（含试跑）；成熟期 ≈ 每天 1 小时（过脚本 + 检查环境）。

- [ ] 通读 `01/02/03`，理解门禁判定的每一句话（学员会挑战你）
- [ ] **通读 [`00`](00-FDE方法论历史与原理.md) §1–§3**（历史 / 原理 / 方法论）：直播不展开讲，但学员的"为什么"要能一句话答上；§5 的 8 条追问先自己答一遍
- [ ] 在干净环境完整跑一遍 D1 冒烟链路（`11` 第 2–3 节）
- [ ] 通读 `07` 的三份案例剧本，选定本期使用的客户案例
- [ ] 准备"故意翻车"脚本（D1 必演，见第 3 节）
- [ ] 准备 3 个自己的现场故事（真实、脱敏、有代价）：一个成功、一个失败、一个"当时不懂后来才懂"

> **铁律**：讲师讲的每个故事必须真实且脱敏；宁可少讲，不可编造。这与课程"诚实标注"原则一致。
> 同理，引用 `00` 里的市场/薪资数字时**必须连来源与日期一起讲**；两来源冲突的（如 OpenAI Deployment Company 的成立时间）就照 `00` §1.6 说"两种说法，我们讲 2025–2026 年间"，**不要挑一个顺口的当定论**。

## 2. 每场直播的标准骨架

| 环节 | 时长 | 讲师动作要诀 |
|---|---|---|
| 开场公式 | 3 min | ①昨天最高分产出点名（10s）②今天一句话目标（10s）③"学完你能拿走什么"（10s）④今天的最小挑战（20s） |
| 回炉 | 10 min | 只抽 3 个概念 + 1 个错误案例；抽人不抽"积极分子"（点名靠后的学员） |
| 讲与演 | 25 min | 演示 > 讲解；每 7 分钟一次互动（投票/提问/群里打 1） |
| 上手 | 35 min | 讲师闭嘴巡场；助教主攻；只答"卡住超过 3 分钟"的问题 |
| 复盘 | 10 min | 1 优 1 劣，优的要讲"为什么好"，劣的要讲"我也犯过" |
| 布置 | 10 min | 只念门禁检查项，不念说明书——让学员去读 `06` |

## 3. D1 演示脚本（含"故意翻车"）

**场景**：用虚构客户「茶语万象」的工单数据演示。全程投屏，命令逐条敲（不要复制粘贴大段）。

**M1 世界观段（09:30–10:15）的讲法**：先收学员课前预读的问题（"FDE 和售前/实施/外包差在哪？"），
用 `00` §1.1 的类比速答（售前=试驾员 / 实施=装车工 / 外包=代驾 / FDE=随队工程师）；
时间线只讲三个锚点（2003 Palantir → 2023 LLM → 2024–2026 岗位爆发），**不要展开 §2 的原理**——
那 45 分钟的 KPI 是让学员记住"FDE 是做 80%→99% 那一段的活"这一句话。

```bash
# 第 1 步：先看数据长什么样（look before you load）——建立"先看再装"的职业习惯
fde-scope connect --type csv --source examples/quickstart_csv/sample_tickets.csv

# 第 2 步：锻造语料——讲"淘米"类比：去砂（去重）、去石（质量门）、补水（补盲）
fde-scope corpus --input examples/quickstart_csv/sample_tickets.csv --out reports/corpus_report.html

# 第 3 步：打开报告——逐段读关键数字，示范"对客户怎么说"
open reports/corpus_report.html      # macOS；Windows 用 start，Linux 用 xdg-open
# 学员更推荐：直接在文件管理器里双击 reports/corpus_report.html

# 第 4 步：打开控制台——让学员看到 18 阶段与门禁面板的红色 blocker
fde-scope web     # → http://127.0.0.1:8080
# 这一步不用敲 open：把终端里打印的 http://127.0.0.1:8080 地址复制到浏览器即可
```

**翻车脚本（必演）**：演示前**故意**先跑 `corpus` 再"想不起来"要定成功标准，问学员：
"我刚才跳过了哪一站？跳过它的代价是什么？"
→ 引出 D2 的委托单。用"代价的体验"替代"原则的说教"。

**控时提示**：D1 是 6 小时长直播，必须在 10:15、14:30 设两个硬性休息；
第 3 段（工具箱）不能晚于 14:30 开始，否则装环境的学员会拖到晚上。

## 4. D2–D8 每日带教要点（每节 ≤5 条）

**D2 定边界**
1. 收作业时先问："你的成功标准，客户能自己验收吗？"——验收主体搞错是最高频错误。
2. 干系人地图必须逼出"第二发起人"，没有就让他写"死亡风险"三个字在图上。
3. 现场把一句形容词成功标准（"提升效率"）改造成可度量版本，示范一次胜过讲十次。
4. 提醒：Zones A 的目标不是写方案，是**定义 done**。
5. 预告 D3 时埋钩子："明天你会看到号称最干净的数据长什么样。"

**D3 接数据**
1. 让学员先猜"这份数据有几成能用"，再跑命令对照——制造认知冲突。
2. PII 环节用提问推进："如果这列身份证泄了，谁担责？"
3. 强制结论："待定"不允许，逼学员做判断并写出条件。
4. 用仓库里 mock engagement「南湾汽车」的"门禁被真实拦截"案例展示数据问题的后果。
5. 提醒不要真拿客户数据：红线再讲一遍（`11` 第 6 节）。

**D4 造语料**
1. 核心一句："合成是补盲区，不是凑数量。" 每一条合成样本都要有缺口理由。
2. 演示 `--llm` 与规则路径的差异（有 key 时），并演示**失败自动回退**——让学员看到"没有 key 也能活"。
3. 话术环节做角色扮演：助教扮演客户老板，听学员用 ≤200 字白话解释。
4. 诚实标注合成比例，当场制造一个"如果客户问合成比例是多少"的追问。
5. 预告："明天的坏消息是，指标一定不好看——这正是它的价值。"

**D5 验证与评估**
1. 先给学员打预防针：第一次评估指标难看是正常的，指标是地图不是成绩单。
2. 强调 bad case > 平均分：把"最该先修的 3 个"讲成"烧钱最快修的 3 个"。
3. 角色扮演高潮：助教演反对的业务主管，学员必须用数据回应（不能讲情怀）。
4. 要求记录"被拒绝的需求"——这是防 Scope Creep 的证据。
5. 预告："明天开始，你要为凌晨 2 点值班的人写文档。"

**D6 运维化**
1. 开场问："你走了以后，谁修？" 让沉默 10 秒再继续。
2. 讲 SLO 时用外卖超时赔付类比（错误预算 = 赔付额度）。
3. Runbook 环节做"凌晨 2 点盲测"：随机抽一份，让别人按文档念，发现断点当场标注。
4. 提"概率性退化"：AI 不是坏了才叫坏，慢慢变差也是坏。
5. 预告："明天你要把手里的东西交给一个不爱你的人。"

**D7 交接与沉淀**
1. 核心心态："交接不是走过场，是你专业度的最后一道签名。"
2. 技能卡必须有"适用边界"——强迫学员写出"什么情况下这条经验不适用"。
3. 角色扮演：客户运维负责人提三个刁难问题（剧本见 `07`）。
4. 讲"无限 Pilot"是行业最贵的反模式：没有 done，就没有价值结算。
5. 预告 D8："明天带齐 7 件产出——空手的，作品集直接判 C。"

**D8 变现日**
1. 作品集装配时反复强调：**证据 > 描述**；把"我做了"改成"数据显示"。
2. 模拟面试优先问 `10` 的 20 题里学员最虚的：没有外网/客户数据差/多租户防泄露。
3. 答辩控时严格（10 min），超时打断——这就是交付现场的纪律。
4. 结营仪式必须点名每一位完成者（哪怕 30 秒），掉队者私聊而非公开处刑。
5. 最后布置一个"课后动作"：72 小时内完成一次对真人的作品集讲解（同事/朋友都行）。

## 5. 提问库（苏格拉底式，随机抽用）

| 场景 | 问题 |
|---|---|
| 讲成功标准 | "这句话，客户用什么数字来验收？" |
| 讲干系人 | "如果这位发起人明天离职，项目还活着吗？" |
| 讲数据 | "这份数据的哪个字段一旦泄露，你要负法律责任？" |
| 讲语料 | "你怎么向客户证明，补的这些样本不是编的？" |
| 讲评估 | "指标 91% 很好看——它回答的是客户的哪个问题？" |
| 讲 bad case | "如果只能修一个，你选哪个？为什么是它？" |
| 讲 SLO | "凌晨 3 点报警，谁来处理？他看哪份文档？" |
| 讲交接 | "客户拿到你的交接包，不给你打电话能活几天？" |
| 讲变现 | "你的产出里，哪一件能直接放进简历？证据在哪？" |

## 6. 卡点解药表（学员原话 → 应对）

| 学员原话 | 背后情绪 | 讲师应对 |
|---|---|---|
| "我不会写代码，是不是学不了？" | 畏难 | "今天所有操作都是可复制的命令——你的任务是看懂每一步在干什么；代码是 Level 2。" |
| "我们公司没有这样的客户，学这个有什么用？" | 迁移焦虑 | 现场把他的日常工作映射到 4 区："你现在做的 X 属于 Zone B 的哪一站？缺的是哪一站？" |
| "客户根本不给我数据" | 真实困境 | "这正是 Zone A 的存在意义：先拿到成功标准和干系人，数据是第 5 站的事。说说你卡在哪一位干系人？" |
| "我的指标很差，是不是做错了？" | 挫败 | "指标差是信息，不是判决。把它翻译成一个 bad case 加一个下一步动作。" |
| "Agent 这么强，FDE 会不会被取代？" | 职业焦虑 | "工具越强，'定边界 + 交接'越值钱。课程前两站和最后两站全部是跟人打交道——这正是训练重点。" |
| "能不能给个模板我直接填？" | 求效率 | 给模板（`12`），但追加一问："这个模板的第 2 条为什么这么写？"确保理解而非套壳。 |
| "我全用 AI 生成的行不行？" | 试探边界 | "行。答辩我会请你脱稿讲 3 分钟，讲不清的判定为未达——这是课程唯一的'防伪'。" |
| "没时间打卡" | 掉队前兆 | 启动三级干预（`08` 第 7 节）；先给最小可交付版本（Mini 版产出），保住连续性。 |

## 8. 控场技巧

| 状况 | 处理 |
|---|---|
| 冷场（没人答） | 换选择题："A 还是 B？群里打字母"；先点已经举手的人，再引第二个 |
| 超时 | 助教举牌暗号（黄牌=剩 5 分钟，红牌=立即收尾）；被砍的彩蛋课后录 3 分钟短视频补给 |
| 跑题 | "这是个好问题，我先记在'停车场'里，答疑窗口第一个讲"（准备白板/文档记 Parking Lot） |
| 专业抬杠 | 承认合理部分 + 转成练习："这个反例很好，D7 的盲测环节请你来当客户运维负责人。" |
| 学员当众贬低课程 | 不辩论；私聊了解真实诉求；若是共性，写入期报改进项 |
| 有人全程开摄像头吃饭/摸鱼 | 运营侧处理（私聊），讲师不点名 |
