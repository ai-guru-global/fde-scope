## S1 · 回炉（0–10 min · 10 min）

**本节定位**：10 分钟干两件事——确认 D1 的三个概念没丢，再用一个"错误示范"制造今天的动机。**不讲课，只提问。**

**一句话目标**（开场念）："昨天你看到了整条链路，今天你要在链路的**第一道闸机**前，替客户把边界画出来。"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–2 | 一句话回顾 D1（80%→99%）+ 宣布今天产出物 | 建立连续性 |
| 2–5 | 抽考 D1 三概念（选择题，3 题 1 分钟） | 低成本复现，不是考倒人 |
| 5–9 | **案例 D 星澜科技**（[`07`](07-实战剧本与案例库.md) §2.4）：念客户原话 + 三级追问 | 制造今天的核心动机 |
| 9–10 | 命名反模式并收口："今天第二个概念就是它的解药" | 埋 S2 的钩子 |

### 讲稿要点

**① 抽考怎么问（2–5 min）——用选择题，不用问答题**

问答题会让没复习的人在 90 分钟的第一分钟就掉队。选择题让他"至少能蒙"，蒙完听到正确答案，认知成本最低。

投屏 3 题，让全体在群里打字母，讲师 20 秒后揭晓：

| # | 题目 | 选项 | 答案 |
|---|---|---|---|
| 1 | D1 说 FDE 做的是哪一段的活？ | A. 从 0 到 80%　B. 从 80% 到 99%　C. 从头做到尾 | **B** |
| 2 | "门禁"和"作业清单"最大的区别？ | A. 门禁更严格　B. 门禁在你要通过的那一刻重新验证　C. 门禁是讲师定的 | **B** |
| 3 | D1 那条迷你链路里，为什么要先跑 `connect` 再跑 `corpus`？ | A. 手册这么写的　B. 要先看真实数据长什么样　C. `corpus` 需要 `connect` 的输出 | **B** |

揭晓后的点评只有一句：

> "三题全是 B——听起来像出题偷懒。不是。**这三题是同一个答案的三个侧面**：
> 你的活在下半场、你的证据要现场成立、你的判断要建立在真东西上。
> 今天这一整天，就是把这三句话用在**一个人身上**——那个给你提要求的人。"

**② 案例 D 星澜科技（5–9 min）——逐字念 [`07`](07-实战剧本与案例库.md) §2.4**

> "出海营销 AI 素材工厂。COO 一个人拍板，说'先把东西做出来，其他人我来协调'。
> 委托单很漂亮，成功标准也有数字。但干系人地图上，发起人只有 1 个。"

**念完停 3 秒**，然后走三级追问（[`07`](07-实战剧本与案例库.md) §2.4 原题 + 两级递进）：

| 级 | 追问 | 学员通常答 | 讲师动作 |
|---|---|---|---|
| 1 | "这个项目有什么问题？" | "只有一个发起人""其他人没参与" | 不评价，点头，接着问 |
| 2 | "如果这位 COO 下季度调岗，这个项目还活着吗？" | （**沉默**——这是今天最值钱的 5 秒） | 让沉默待满，不救场 |
| 3 | "委托单很漂亮、成功标准也有数字——那问题出在哪？" | "……出在没人第二个签字" | 收口 |

第 3 问是关键：**它把学员的注意力从"文档质量"搬到"结构风险"上。**
多数新人相信"文档写好 = 项目稳"；这一问当场推翻它。

> ⚠️ 讲师注意：**别说成"这个 COO 不行"**。要说成"**这个结构不行**"。
> COO 可能是全场最支持这个项目的人——**恰恰因为他一个人扛，他才最危险。**

**③ 命名 + 收口（9–10 min）**

> "这个反模式有名字，叫 **Sponsor Collapse（发起人塌陷）**——[`12`](12-附录-术语表与模板库.md) §1.6 十二反模式第 5 条。
> 它的解药，是今天三个概念里的第二个：**干系人地图**。
> 而这张图今天要逼出一样东西，叫**第二发起人**。一会儿你会知道为什么它是硬门槛。

投屏一行字，全天常驻：

```
Sponsor Collapse → 干系人地图必须 ≥2 位发起人
```

### 投屏·板书

- 左：3 道选择题（揭晓前只显示题目）
- 中：案例 D 客户原话（大字，只留 30 秒）
- 右：常驻一行 **Sponsor Collapse → 干系人地图必须 ≥2 位发起人**
- 白板角落：**停车位**（今天所有跑题问题记这里）

### 互动设计

| 问题 | 期望答案 | 冷场备选 |
|---|---|---|
| "这位 COO 调岗了，项目还活着吗？" | 任何回答都接住，重点是让沉默发生 | 改成人举手："觉得还活着的举手"——通常 0 到 1 只手，比语言更有力 |
| "你公司里有没有这种'一个人扛'的项目？" | 不要求公开回答（涉及真实公司），改成群里匿名打 1（有）/ 0（没有） | 讲师自曝一个脱敏版本 |

### 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 抽考变成点名批评 | 全程群内打字母，**不点名**；答错的人不会暴露 |
| 学员开始讨论"这个 COO 是不是傻" | 立刻拉回："COO 是好人，**结构是坏结构**——我们今天要学的就是怎么救它" |
| 讲师在案例 D 上讲解超过 5 分钟 | **硬性**：9 分钟必须收口。案例 D 是钩子，不是教学内容（D2 的"讲"在 S2） |
| 有人问"星澜科技的档案在哪看" | "控制台里能看——它真实存在，`success_criteria` gate 是**红的**"（[`07`](07-实战剧本与案例库.md) §2.4），不展开 |

### 承接语（最后 30 秒）

> "看到了坏结构，接下来看**好结构长什么样**。25 分钟，我用一个虚构客户，把一句抱怨拆成一页纸。"

### 学员笔记要点

- D1 三概念回顾：**FDE 做 80%→99%** · **门禁是现场重新验证** · **判断建立在真东西上**
- 反模式 **Sponsor Collapse**：唯一发起人离职即死 → 解药是干系人地图 + 第二发起人
- 今天的产出物：**客户委托单（≤1 页）**，门禁 G2

## S2 · 讲与演（10–35 min · 25 min）

**本节定位**：全场唯一的"演示"段。目标不是讲清方法论，是**让学员亲眼看到闸机会拦人**。
**本节产出的不是知识，是"证据长什么样"的样板。**

**一句话目标**："25 分钟后，你能说出委托单的 7 个格子分别填什么，并知道你填错时**哪一行会变红**。"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–3 | 念客户原话，把它拆成 3 个问题 | 从"感受"到"结构" |
| 3–8 | 投屏 [`12`](12-附录-术语表与模板库.md) §2.1 的 7 节模板 + 时间盒四数字 | 给出骨架 |
| 8–20 | **现场演示**：立项 → 看闸机 → 撞门 → 硬推被拦 | 本节核心，不可省 |
| 20–23 | **形容词改造示范**（1 分钟 1 个，改 3 个） | 示范胜过讲十遍（[`05`](05-讲师手册.md) §4 D2-3） |
| 23–25 | 收口：两套门禁一个标准 + 承接 S3 | 过渡 |

### 讲稿要点

**① 把抱怨拆成 3 个问题（0–3 min）——逐字念 [`07`](07-实战剧本与案例库.md) §2.1**

投屏客户原话（**先不投屏任何模板，只投这段大白话**）：

> "全国 2800 家门店，每周订货全凭店长拍脑袋——订多了报废，订少了断货。
> 我们买了数据平台，但没人知道怎么让它'会订货'。"

念完问全场："**这段话里，客户提了几个要求？**"（学员会说"一个""两个"）

> "他说了 0 个要求。他说的是**一个现象**。
> 委托单的全部工作，就是把这个现象翻译成三个问题的答案——"

投屏三行（**这一整天反复回来看的骨架**）：

```
① 谁说了算？        → 干系人地图
② 值不值得做？      → qualification
③ 什么算 done？     → 成功标准
```

> "注意第三问的措辞：**不是"要做什么"，是"什么算 done"。**
> 这是 [`05`](05-讲师手册.md) §4 里对 D2 最重要的一条提醒：**Zones A 的目标不是写方案，是定义 done。**
> 方案是 D4–D5 的事。今天你要是开始写技术方案了，你**跑错站了**。"

**② 给出骨架（3–8 min）——投屏 [`12`](12-附录-术语表与模板库.md) §2.1 的 7 节**

不逐字讲模板（学员课后自己看），只讲**每格填错会怎样**：

| 节 | 填什么 | 填错的后果 |
|---|---|---|
| 1 业务画像 | 行业 · 规模 · 谁付钱 · 现在怎么干活 · 痛在哪 | 后面所有判断失去依据 |
| 2 干系人地图 | 执行发起人 · **第二发起人** · 一线使用者 · IT/安全把关人 | **Sponsor Collapse**（G2 blocker） |
| 3 成功标准 | ≥3 条，全部可度量 | **Infinite Pilots**（G2 blocker） |
| 4 时间盒 | ≤14d 集成 / ≤90d 上线 / ≤120d 交接 / 每周同步 | 项目变成没底洞 |
| 5 范围 | ✅做 / ❌不做 / 🔄变更规则 | **Scope Creep** |
| 6 放弃标准 | 什么情况下我们应该说"这个不该做" | 沉没成本滚雪球（G2 warning） |
| 7 已知风险 | 风险 · 影响 · 缓解 · 责任人 | 出事时无人可找 |

**只强调两格**：第 2 格和第 3 格。理由：

> "7 个格子里，只有 2 个是**硬拦**（blocker），其余是提醒。
> **硬拦的只有这两格——因为它们是唯一两个"你写错了、别人替你兜不住"的地方。**"

**时间盒四个数字要念出来**（[`12`](12-附录-术语表与模板库.md) §2.1 / [`02`](02-逐日教学大纲.md) Day 2）：

```
≤14 天  完成数据接入          ← 集成
≤90 天  上线                  ← 出价值
≤120 天 完成交接              ← 你得走得掉
每周   一次同步               ← 别让人失联
```

> "这四个数字不是我编的（引用自行业 FDE 实践）。它们的用途不是承诺，是**触发复盘**：
> 到第 15 天数据还没接完，不是'再等等'，是**该开会了**。"

**③ 现场演示（8–20 min）——**本节核心，一条命令都不能省****

演示前把终端字号调到最大，并**先声明工作目录**：

```bash
# 本演示全部写入 /tmp，不污染课程仓库（学员自己练时用默认目录即可）
export FDE_SCOPE_HOME=/tmp/fde-d2-demo
mkdir -p /tmp/fde-d2-demo
```

> 讲师旁白："我特意把它指到临时目录——**演示可以乱、仓库不能乱**。这也是个习惯。"

**第 1 步 · 立项（约 30 秒）**

```bash
fde-scope engage init --customer "茶语万象" --profile ticket
```

真实输出（**照抄，不要美化**）：

```
FDE Scope v0.1.0 — engage init · ticket

✅ Engagement eng-茶语万象-ticket created (profile=ticket)
   phase: qualification · zone: pre_engagement
   visible phases: 15
```

三处要点，逐句讲：

1. `--profile ticket` → 这就是**qualification（值不值得做）**的第一个判断：**这条链路用哪套**。
   "同一件事，工厂和互联网公司的交付链路不一样。选错 profile，后面每一站都白走。"
2. `phase: qualification · zone: pre_engagement` → 你现在站在**地图的第一站**。
3. `visible phases: 15` → "看到 15 了吗？[`02`](02-逐日教学大纲.md) 说 ticket 走 15 个阶段、manufacturing 走 18 个。
   **差的那 3 个全是工业专属阶段**——现场勘察、部署上线、变更管理培训。工业现场这三站躲不掉，互联网项目多数用不上。"

```
└───────────────────┴───────────────────────────────────────────────────────┴─────────────────┘
```

**必须讲清的三件事**（学员最容易在这里踩坑）：

1. **这 10 个不是本课程的门禁 G0–G8。** 它们是**工具门禁**，管的是 SOP 链路某个阶段能不能推进。
   "两套门禁，一个标准，别搞混——[`03`](03-评估体系与通关门禁.md) §1.1 专门写了这件事。"
2. **🏢 通用的只有 3 个**：`success_criteria` · `slo` · `handoff_signoff`。
   "**今天我们要过的是第一个。**"
3. ⚠️ **不要演示 `gate check <id> --gate site_survey`**。ticket 档案上它会印 **✅ PASS**——
   那是"这个门在 ticket 档案下**没有可检查的数据**"的空过，**不是通过了工业门**（[`03`](03-评估体系与通关门禁.md) §1.1 专门警告过）。
   "拿这个空 ✅ 去充作品集，助教一眼看穿。"

**第 3 步 · 现在去撞门（10–14 min）——今天最重要的一条命令**

```bash
fde-scope gate check eng-茶语万象-ticket --gate success_criteria
```

真实输出（退出码 = 1，**这行字本身就是证据**）：

```
❌ BLOCKED · gate=success_criteria
  🚫 成功标准未定义——无法判定 done（无限 pilot 反模式）
  🚫 仅有 0 个 sponsor——要求 ≥2（防 Sponsor Collapse）
  ⚠️  sponsor 未填写可度量的 success_metric
💡 已把这次阻塞沉淀为草稿 skill-1d607e0f — fde-scope skill review 可查看并完善
```

逐行讲解——**这一段浓缩了今天全部三个概念**：

| 行 | 讲什么 |
|---|---|
| `🚫 成功标准未定义——无法判定 done` | 今天第 3 个概念。**没有 done，项目就没有终点** = Infinite Pilots |
| `🚫 仅有 0 个 sponsor——要求 ≥2` | 今天第 2 个概念。**Sponsor Collapse**——和刚才星澜科技一模一样的病 |
| `⚠️ sponsor 未填写可度量的 success_metric` | 同样是"没标准"，但严重度降级：这是**提醒**，不是硬拦 |
| `💡 已把这次阻塞沉淀为草稿 skill-1d607e0f` | **飞轮第一次出现** |

关于最后一行，逐字稿：

> "这行字长得像 bug，其实是这门课最有意思的设计之一：
> **你撞墙的这一刻，系统把你的错误变成了资产。**
> 它记了一张"待审技能卡草稿"——`fde-scope skill review` 可以看，`fde-scope skill archive <id>` 可以清。
> 这就是 D1 说的"把现场经验回流成产品能力"的最小形态。
> 注意：**它不替你把门打开，它只是记下来。** 挡你还是挡你。"

**关于 `🚫` 和 `⚠️` 的符号语义**——顺手指一下投屏的 [`03`](03-评估体系与通关门禁.md) §3：

> "🚫 = blocker = **硬拦**，不补齐不放行；⚠️ = warning = **可放行但记入档案**，在作品集评分里扣分。
> 这套语义**课程门禁 G0–G8 和工具门禁完全同构**——`03` §3 的表里原话就是这两行。"

**第 4 步 · 硬推一次，看它会不会真拦（14–18 min）**

很多人以为 `gate check` 只是个"报告工具"。**下一演示要推翻这个想法。**

```bash
fde-scope engage advance eng-茶语万象-ticket   # 第 1 次
fde-scope engage advance eng-茶语万象-ticket   # 第 2 次
fde-scope engage advance eng-茶语万象-ticket   # 第 3 次
```

真实输出：

```
✅ Advanced → stakeholder_map (干系人地图与对齐) · zone=pre_engagement
✅ Advanced → success_criteria (成功标准契约化) · zone=pre_engagement
❌ ADVANCE BLOCKED — phase=success_criteria
❌ BLOCKED · gate=success_criteria
  🚫 成功标准未定义——无法判定 done（无限 pilot 反模式）
  🚫 仅有 0 个 sponsor——要求 ≥2（防 Sponsor Collapse）
  ⚠️  sponsor 未填写可度量的 success_metric
💡 已把这次阻塞沉淀为草稿 skill-3fffbaa7 — fde-scope skill review 可查看并完善
```

**这里有个反直觉的地方，必须停下来讲**：

> "注意——**前两步不但没被拦，还放行了。**
> 因为 `qualification` 和 `stakeholder_map` 这两个阶段**本身没有挂门禁**，
> 它们靠的是检查表加**你自己的诚实**。整条链路里，**只有 `success_criteria` 挂了闸机。**
>
> 这不代表前两站不重要。**恰恰相反**：
> 闸机只装在**最重要、也最容易被糊弄**的那一站。
> 前两站糊弄了，你自己心里知道；**成功标准糊弄了，三个月后客户和你才知道——那时候代价最大。**"

再补一刀：

> "还有一层：**门禁是"推进那一刻"算的，不是"提交那一刻"算的。**
> 今天它拦住我，因为我现在没有标准。
> 明天我补上了，它让我过——但**每次推进它都会重算**。
> 所以**没有"我上周通过了"这回事**（[`AGENTS.md`](../AGENTS.md) 第 1 条不变量）：

> **一个过期通过记录，不等于一次真通过。**

**第 5 步 · 那怎么才能变绿？（18–20 min）——诚实回答**

学员一定会问："那我填什么它才让我过？"——**如实回答，不要编**：

> "说实话：`fde-scope` 目前**没有** `engage set-sponsor` 这类"录入"命令。
> 工具的定位是**验收**，不是**录入**——它在你推进的那一刻，去读那份 engagement 档案并重新判定。
>
> 所以在真实项目里，闭环是这样的："

投屏：

```
你写委托单（Markdown，交课程门禁 G2）
        ↓   结构化进 engagement 档案 JSON（团队真实项目里）
fde-scope gate check / advance（工具门禁现场验收）
```

> "**两套门禁，一个标准。** 标准是什么，今天就要定下来——而且标准不长在工具里，长在**你和客户之间**。"

**④ 形容词改造示范（20–23 min）——示范一次胜过讲十遍**

投屏左列，现场改右列（**真的当场打出来，不要预先做好**）：

| ❌ 形容词版 | ✅ 可度量版 |
|---|---|
| 提升客服效率 | 客服中心人工工单从 **1.2 万件/周降到 ≤8400 件/周**，**90 天内**，按周报口径统计 |
| 提升用户体验 | 会话平均处理时长从 **4.2 min 降到 ≤3.0 min**，**同一批 200 条测试集**上测 |
| 提高数据质量 | 关键字段缺失率从 **12% 降到 ≤2%**，**接入后第 30 天**复核 |
| 让 AI 更聪明 | 在 **200 条客户测试集**上准确率从 **61% 到 ≥85%**，bad case **逐条有记录** |
| **提升运营效率** | **？？？** |

最后一行是本节课的"钉子"，**停下来讲**：

> "前面四条我都能改。第五条改不了——**不是因为不精确，是因为没人知道"运营"指什么。**
> 这就是形容词标准的真正问题：**它不是写得模糊，是它根本还没想清楚问题是什么。**
>
> 所以下次你要写"提升效率"的时候，别急着找数字——**先回去问客户：你说的效率，是谁的哪个动作快了？**
> 问不出来，说明这一条**还不该进委托单**。"

**改造三件套**（投屏，全天常驻）：

```
① 谁的数字（主体是客户，不是你的模型）
② 从多少到多少（基线 → 目标）
③ 什么时候、拿哪批数据测（时间 + 测量集）
```

**⑤ 收口（23–25 min）**

> "今天你看到的这一页纸，是整条链路里**唯一一份"不进代码"的产出**——
> 它不跑、不部署、不上线，但它决定了后面 17 站值不值得走。
> 现在轮到你了。"

## S3 · 上手（35–70 min · 35 min）

**本节定位**：全场唯一"必须产出"的一段。学员 35 分钟内做出**自己的第一版委托单**，并被助教当场压力测试。
**助教必须在场**——这一段的教学效果，一半来自角色扮演。

**一句话目标**："35 分钟后，你手里有一份**能拿去给客户看**的委托单草稿——不是完美的，是能用的。"

### 分组建档（讲师，1 分钟）

按 [`07`](07-实战剧本与案例库.md) §1 固定分组，**从 D2 一直用到 D7**（D8 交叉提问）：

| 组 | 案例 | 类型 | 训练重点 |
|---|---|---|---|
| **A 组** | 案例 B · 迅捷出行 | ticket（网约车） | 冲突干系人 · 含 PII 数据 |
| **B 组** | 案例 C · 南湾汽车 | manufacturing（整车厂） | 工业叠加层 · 门禁真实拦截 |

> 讲师逐字念："从现在到 D7，你一直用这个案例。**D8 答辩时，你要回答对方那个案例的问题**——
> 因为客户现场就是这样：**你用的不是你的案例，但仍要听懂对方讲什么。**"

**为什么两组案例不同**：A 组练"人的冲突"（要快 vs 要稳），B 组练"工业现实"（PLC 不许碰）。
两种病都得见过。

### 分钟级时间盒（学员视角）

| 分钟 | 学员做什么 | 助教做什么 |
|---|---|---|
| 0–1 | 分组建档，读规则 | 念规则 + 声明红线 |
| 1–6 | **读客户简报**（原始形态，故意不整理） | 巡场，只回答"简报里有没有"类问题 |
| 6–10 | **独立写**"我认为的 3 条成功标准"（**不许讨论**） | 强制安静，看到讨论就制止 |
| 10–12 | 组内对标准，找出分歧 | 记录分歧点（这是 S4 的弹药） |
| 12–25 | 补完干系人地图 + 范围 + 放弃标准 + 风险 | **逼第二发起人**（见下） |
| 25–33 | **助教扮演客户 CTO 压力测试**（每桌 2–3 分钟） | 按 [`07`](07-实战剧本与案例库.md) §3.1 + §4.1 |
| 33–35 | 每组自评 G2 四条 | 收自评结果，挑 S4 的素材 |

### 讲稿要点

**① 念规则（0–1 min）——三条，不多**

> "三件事：
> ① **先各自写，再讨论**——因为客户不会给你时间开会，你第一次听到的抱怨往往是碎片；
> ② **只用手头的简报**，不许上网查这家公司、不许用真实客户名；
> ③ **35 分钟必须有一版**——不完美可以，空白不行。"

**② 关于"独立写 4 分钟"（6–10 min）——这是本节的隐藏考点**

讲师在开始时说明理由，之后**闭嘴**：

> "接下来 4 分钟，**谁也不许说话**。写下你认为的三条成功标准。
> 写得难看的、写得犹豫的，都留着——**那是你真实的判断力快照。**
> 一会儿组内一对，你会发现：**同一段简报，三个人读出了三种"成功"。**
> 这个分歧不是你们不专业，**是客户简报本身就是这个德性**——它就是个没整理的抱怨。"

**③ 逼第二发起人（12–25 min）——助教的核心动作**

这是 [`05`](05-讲师手册.md) §4 D2-2 的原文要求，助教必须执行：

> "干系人地图必须逼出'第二发起人'，**没有就让他写'死亡风险'三个字在图上**。"

操作细节（助教照着做）：

| 情形 | 助教的话 |
|---|---|
| 图上只有 1 个发起人 | "第二个人呢？" → 学员说"简报里没有" → **"那就写上**「**死亡风险：唯一发起人**」**五个字，就写在图上"** |
| 学员说"数据总监应该也算吧" | "**算不算你说了不算，客户说了算。** 你现在要做的是：写下他的名字，然后**在备注里写"待确认支持度"**" |
| 学员说"我不知道第二发起人是谁" | "好——**那你的下一次会议议程就有了**：第一个问题就是问这个" |

> ⚠️ 助教红线：**不要替学员想答案。** 学员说"没有"，就让他把"没有"写下来——
> **一张标着"死亡风险"的干系人地图，比一张编出来的四人图有价值得多。**

**④ 两组各自的关键摩擦（讲师巡场时按组提问）**

| 组 | 案例里埋的雷 | 讲师/助教该问的问题 |
|---|---|---|
| A 组（迅捷出行） | 罗成要快 vs 邓琳要稳；钱锋怕背锅；孙丽关心司机侧 | "**这四个人四个 KPI，你的成功标准写谁的？**"（→ Scope Creep 预警） |
| B 组（南湾汽车） | 车间主任说"PLC 谁都不许碰"；安全部门未签字；"我们厂没有工会" | "**谁能在焊装线上给你开停机窗口？**"——这个人不在简报里，**他必须被写进干系人地图** |

> B 组的"我们厂没有工会"是**故意写的陷阱**：学员会以为"没有工会 = 没有劳工风险"。
> 助教追问："**那 `works_council` 这个门禁在你们厂由谁满足？**"
> —— 正确答案不是"不用管"，是"**把它写进风险清单，责任人待定**"（[`07`](07-实战剧本与案例库.md) §2.3）。

**⑤ 助教扮演客户 CTO 压力测试（25–33 min）**

台词骨架（[`07`](07-实战剧本与案例库.md) §3.1 原文，可直接打印给助教）：

```
（学员：自我介绍 + 想了解"痛点"）
客户 CTO：别问了，我时间有限。我就一句话——AI 客服，三个月，能上就上。
          （学员若直接问数据）
客户 CTO：数据的事你找数据部，我只要结果。
          （学员若坚持问成功标准）
客户 CTO：那你说，你觉得这个"成功"应该怎么定？给我个数字。
```

**暗号**（[`07`](07-实战剧本与案例库.md) §4.1）：

> 学员问出"**谁和您一起为这个结果负责**"时，你可以提"**VP 和我也在盯**"（给出第二发起人线索）。

**观察点**（[`07`](07-实战剧本与案例库.md) §3.1）：

- 学员是否顶住"直接要结果"的压力，把对话拉回**成功标准与干系人**；
- 是否识别出"客户只有一位出面人"（→ 追问第二发起人）。

> ⚠️ **本节节奏警戒**：35 分钟做一页纸是**紧的**。若助教人手不足（每桌压不到 2 分钟），
> **优先砍压力测试，不要砍独立写 4 分钟**——那个环节的认知冲击最强，且不可事后补。

**⑥ 自评 G2（33–35 min）——四条打钩**

投屏，学员自查（**先自评，讲师不替他们评**）：

```
G2 自查（[03] §3）
✅ ① 成功标准 ≥3 条，且每一条都有数字与时间        ← blocker
✅ ② 干系人含 ≥2 位发起人（没有 → 写"死亡风险"）   ← blocker
✅ ③ 有"放弃标准"（什么情况下该说"这个不该做"）    ← warning
✅ ④ 委托单 ≤1 页（超 2 页 = blocker）              ← warning
```

- 右：G2 自查四条（打钩区）
- 白板角落：停车位

### 互动设计

| 问题 | 期望答案 | 冷场备选 |
|---|---|---|
| （独立写环节）"写完的举手" | **不需要回答**，这一环节刻意不说话 | —— |
| "你们组的分歧在哪一条？" | 通常是"拦截率 60% 算不算成功" | "先别争对错——**把它记下来，一会儿我告诉你为什么分歧本身就是产出**" |

### 学员动作（现场）

1. 读客户简报（5 分钟，**只看简报**）
2. 独立写 3 条成功标准（4 分钟，**不许讨论**）

### 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 学员偷偷联网查"迅捷出行是哪家公司" | **当场制止**：编造真实背景会污染练习，且触碰"真实客户名"红线 |
| 小组一上来就开会讨论，跳过独立写 | 助教站到桌边计时："还有 3 分钟**独立**时间"——用时间压力代替批评 |

| 干系人地图只有 4 个名字没有"在乎什么" | "名字是最不值钱的一列，**'在乎什么'才是**——没有它，这张图不能用于决策" |

> "停笔。现在**先别改**——我要让你看看两份真实的作业，一份好的，一份……有代表性的。
> 看完你再改，会改得更狠。"

### 学员笔记要点

- 分组：**A 组案例 B（迅捷出行）· B 组案例 C（南湾汽车）**，用到 D7，D8 交叉提问

- 第二发起人找不到 → **写"死亡风险"到图上**（不是编一个名字）
- "在乎什么"是干系人地图里最值钱的一列
- 放弃标准模板句："如果 <前置条件> 在 <时点> 之前不成立，我们建议暂停并重新评估"

## S4 · 复盘（70–80 min · 10 min）

**本节定位**：10 分钟，用 **1 优 1 劣**把 S3 的产出拉到标准线上。
**重点是"成功标准写成形容词"这个最高频错误**（[`02`](02-逐日教学大纲.md) Day 2 复盘行原文）。

**一句话目标**："下课时你能一眼看出：哪条标准客户能验收，哪条不能。"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–3 | **1 优**：念案例 A 茶语万象的参考成功标准，逐条拆解 | 给出"好"的具体形态 |
| 3–6 | **1 劣**：展示"形容词标准"的三种变体（**不点名**） | 让多数人对号入座 |
| 6–8 | 三种失败模式速讲 | 建立检查清单 |
| 8–9 | 埋案例 E 钩子 | 给"放弃标准"这一条加重量 |
| 9–10 | 修订指令 + 承接 S5 | 立刻行动 |

### 讲稿要点

**① 1 优 · 案例 A 茶语万象的参考成功标准（0–3 min）**

投屏（[`07`](07-实战剧本与案例库.md) §2.1 档案版原文）：

```
≤14d  完成数据接入（瞬时 10w+ TPS）
≤90d  AI 订货预测上线，覆盖 90% 门店
      MAE 较基线下降 ≥20%
≤120d 完成运维移交，SLO 99.5%
```

逐条拆**结构**（不是内容）：

| 条 | 数字 | 时间 | 被测对象 | 谁来验收 |
|---|---|---|---|---|
| 数据接入 | 10w+ TPS | ≤14d | 接入链路 | 数据平台负责人（赵磊） |
| 订货预测 | 覆盖 90% 门店 | ≤90d | 上线范围 | 数字化中心（王芳） |
| 预测质量 | MAE ↓≥20% | （同一窗口） | 模型效果 | 供应链总监（林晓） |
| 运维移交 | SLO 99.5% | ≤120d | 可运维性 | 运维接手人 |

> "看这张表最后一列——**每一条都指得出来一个人**。
> 这就是可度量的第二个意思：**不是数字够多，是每一条都能找到那个会说"我确认"的人。**"

**② 1 劣 · "形容词标准"的三种变体（3–6 min）**

> ⚠️ **纪律：绝对不点名、不投屏真实学员作业。** 用 [`06`](06-学员手册与作业包.md) 的 G2 典型错误表 + 常见变体。

| 变体 | 例子 | 病在哪 |
|---|---|---|
| **A · 纯形容词** | "提升运营效率""赋能一线""提升体验" | **没定义问题**——最严重 |
| **B · 只有工程师能测** | "F1 ≥ 0.85""RMS 误差 < 0.3""P99 延迟 < 200ms" | **验收主体错了**——见下 |
| **C · 只有方向没有量** | "大幅下降""显著提升""明显改善" | 有主体，没数字——**改造成本最低** |

**B 变体必须单独停下来讲**（这是最反直觉的一类，学员普遍觉得"我这条很专业"）：

> "`F1 ≥ 0.85` 是好标准吗？它精确、有数字、可复现。
> **但它是一件工程师能做、客户不能验收的标准。**
>
> 你的客户不会在验收会上说'我确认一下 F1'。
> 客户能验收的是**'人工工单少交了 30%'**——数字可以是你算的，
> 但**判断"少了没有"的人必须是他**。"

这就是 [`05`](05-讲师手册.md) §4 D2-1 说的"验收主体搞错是最高频错误"，**在这里落地**。

**③ 三种失败模式速讲（6–8 min）**

给学员一张可以贴在电脑上的检查清单：

```
① 形容词标准        → 回去问：你说的 X，是谁的哪个动作变好了？
② 只有工程师能验收  → 换成客户的业务量：工单数 / 时长 / 覆盖率 / 缺陷数
③ 没有放弃标准      → 写一句："如果 <条件> 在 <时点> 前不成立，我们建议暂停"
```

顺带回答 S3 里记下的"分歧"：

> "刚才你们组内争的'拦截率 60% 算不算成功'——**分歧本身是产出。**
> 它说明你们已经读出了这个项目最难的那部分：**两个人对"成功"的定义不一样。**
> 委托单的用途之一，就是**把这个分歧写下来，让客户自己看见**。"

**④ 埋案例 E 钩子（8–9 min）**

> "今天你写了'放弃标准'——可能很多人是硬凑的。
> 因为你觉得：都做到这一步了，怎么可能不做？
>
> 这门课里有一个案例，**正确答案是走人。** 客户氛围很好、已经谈了两轮、你也投入了很多——
> 但三条致命信号出现之后，**专业的人会说"不"**。
> D7 我们讲它。今天你只要记住一句话："

投屏大字：

> **会做的人是供应商，会说不的人才是顾问。**（[`07`](07-实战剧本与案例库.md) §2.5 讲师收尾金句）

**⑤ 修订指令（9–10 min）**

> "现在给你 60 秒：**打开你刚才那份委托单，只做一件事——**
> 把每一条成功标准读一遍，问自己一句'**客户自己能验收吗**'。
> 读不过去的，画个圈。圈出来的，才是你今晚要改的。
> 别改别的。"

### 投屏·板书

- 左：案例 A 参考成功标准（4 行）
- 中：三种失败模式（A 纯形容词 / B 工程师标准 / C 没数字）
- 右：金句 **会做的人是供应商，会说不的人才是顾问**
- 白板角落：停车位

### 互动设计

| 问题 | 期望答案 | 冷场备选 |
|---|---|---|
| "`F1 ≥ 0.85` 有没有问题？" | 有：客户不能验收 | 改成举手："觉得这条没问题的举手"——一般小半数，然后逐层拆 |
| "你们组的分歧点，现在能写成一条标准吗？" | 不要求现场答，留给自练 | "写不出来不要紧，**写出来"这条待客户确认"就是合格产出**" |
| "放弃标准你们凑了几条？" | 坦诚承认硬凑也没关系 | 立刻接案例 E 钩子 |

### 学员动作（现场）

1. 对照案例 A 的四条，检查自己是否"每条都指得出来一个人"
2. 把三种失败模式抄进笔记
3. **60 秒圈的圈**——只圈不改（改在 S6）

### 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 学员要求"看看别人组怎么写的" | "D8 交叉提问时你会看到。今天先把自己的看清" |
| 有人被"1 劣"对号入座而不快 | 讲师**先自我暴露**："我第一份委托单写的也是'提升效率'——**[`05`](05-讲师手册.md) §5 说，这门课允许犯错，但不允许糊弄**" |
| 有人问"那 B 变体就一定不好吗？" | **好问题，正面回答**："它该出现在**技术方案**里，不该出现在**验收标准**里——你可以在旁注里保留它，但主标准必须是客户的" |
| 复盘被讲师讲成 15 分钟 | **硬性**：10 分钟必须进 S5。宁可少讲一个变体，也要留时间给"布置" |

### 承接语（最后 30 秒）

> "好——圈也圈了。现在花 10 分钟，我把今晚要做的事交给你，然后你去自练。"

### 学员笔记要点

- **可度量的第二个含义**：每一条标准都指出**一个会说"我确认"的人**
- 三种失败模式：**纯形容词 / 只有工程师能验收 / 只有方向没有量**
- `F1 ≥ 0.85` 该进技术方案，**不该进验收标准**
- 组内分歧**本身就是产出**——写下来让客户看见
- 金句：**会做的人是供应商，会说不的人才是顾问**

## S5 · 布置 G2 + 明日预告（80–90 min · 10 min）

**本节定位**：把今天的产出变成可提交的作业，并让明天的课"有悬念"。
**这一节不讲新东西，只做三件事：念门禁、说清怎么交、埋钩子。**

**一句话目标**："下课后你不需要问任何人——你知道交什么、交到哪、什么时候交、按什么标准判。"

### 分钟级时间盒

| 分钟 | 动作 | 目的 |
|---|---|---|
| 0–3 | 逐条念 G2（[`03`](03-评估体系与通关门禁.md) §3 原文 + 判定语义） | 判定标准零歧义 |
| 3–6 | 命名规范 + 截止时间 + 提交方式 | 消除流程问题 |
| 6–8 | 三条自检 + 两条高频坑 | 提前拦截典型错误 |
| 8–10 | 明日钩子 + 一句收尾 | 建立悬念 |

### 讲稿要点

**① 念 G2（0–3 min）——原文照念，不要翻译**

投屏 [`03`](03-评估体系与通关门禁.md) §3 的 G2 行：

```
G2 边界门（挂 D2）
① 成功标准 ≥3 条且全部可度量（有数字与时间，禁止"提升体验"类形容词）
② 干系人含 ≥2 位发起人
③ 有"放弃标准"
④ 委托单 ≤1 页
判定：①② blocker；③④ warning（④ 超 2 页为 blocker）
```

念完补三句：

> "第一句：**①②是硬拦**——差一条，G2 不过。
> 第二句：③④是提醒——过了也会记档，在作品集评分里扣分。
> 第三句：**超 2 页也是硬拦。** 一页纸不是格式要求，是**一种纪律**——
> 写不到一页，说明你没想清楚；写超过两页，说明你没做取舍。"

**② 怎么交（3–6 min）**

| 项 | 规则 |
|---|---|
| **命名** | `D2-姓名-委托单`（如 `D2-张三-委托单`）；多文件加后缀 `D2-张三-委托单-干系人图.png`（[`06`](06-学员手册与作业包.md) §3） |
| **格式** | Markdown 或 PDF 均可，**总分页 ≤2 页**（>2 页直接打回） |
| **截止** | **直播次日 21:30** |
| **门禁榜** | 次日 **08:30** 公布通过名单 |
| **补交** | 24 小时内补交（每门 1 次）= **正常放行（标注"补交通过"）**；再晚 = **延期通过**，**作品集等级最高 B**（[`03`](03-评估体系与通关门禁.md) §3） |
| **数据红线** | **只用 [`07`](07-实战剧本与案例库.md) 的虚构案例**，或你自己**已脱敏并经公司同意**的场景；真实客户名与 PII 不进群、不上传（[`11`](11-工具与环境准备.md) §6.1） |

> 讲师补一句："**别把'我公司真实项目'直接抄上来**——想用自己的场景，走 S6 路径 A 的脱敏流程。"

**③ 三条自检 + 两条高频坑（6–8 min）**

三条自检（[`05`](05-讲师手册.md) §4 D2 的落地版）：

```
① 每一条成功标准，客户能自己验收吗？        → 不能 → 改
② 干系人图上，有第二发起人吗？              → 没有 → 写上"死亡风险"
③ 放弃标准里，有没有一句"什么情况下不做"？  → 没有 → 补
```

两条高频坑（[`06`](06-学员手册与作业包.md) D2 任务卡 + [`03`](03-评估体系与通关门禁.md) §4）：

| 坑 | 症状 | 处方 |
|---|---|---|
| **成功标准只有工程师能测** | 全是 F1 / MAE / 延迟 | 换成客户的业务量：工单数 / 时长 / 覆盖率 / 缺陷数 |
| **发起人只有一位** | 图上孤零零一个名字 | 问自己一句："**他明天离职，项目还活着吗？**"（[`06`](06-学员手册与作业包.md) D2 常见坑原文） |

**④ 明日钩子（8–10 min）**

> "今天你写的是'**什么算成功**'。
> 明天你会拿到决定'**能不能成功**'的那份东西——数据。
>
> 明天有一句话你会反复听到：**先看再装。**
> 你还会看到一个反常识的现象：**一份'干净得不能再干净'的 CSV，它自己不会告诉你哪里有问题。**
>
> 明天见。"

### 投屏·板书

- 左：G2 四条（原文 + 判定）
- 中：提交规则表（命名 / 截止 / 补交 / 红线）
- 右：三条自检
- 白板角落：停车位（课后答疑时逐个清）

### 互动设计

| 问题 | 期望答案 | 冷场备选 |
|---|---|---|
| "有没有人对 G2 哪一条不确定？" | 通常问 ④"一页"怎么算 | 现场给判据："**打印出来一页正反面之内**" |
| "用自己的真实项目算不算违规？" | **算，除非脱敏并经公司同意** | 现场念 [`11`](11-工具与环境准备.md) §6.4 脱敏四步法（拿掉/替换/哈希/保真） |

### 学员动作（现场）

- 确认提交规则（命名 + 截止）
- 把三条自检抄到笔记里
- 在群里回一个"收到"（讲师以此确认覆盖率）

### 常见错误与纠偏

| 错误 | 纠偏 |
|---|---|
| 讲师开始提前讲 D3 的 `connect` 命令 | **立即收**："明天讲。今天讲了，明天你就不听了" |
| 学员问"能不能用 Notion / 飞书文档交" | 可以导出 PDF 交；但**格式不重要，G2 的四条才重要** |
| 有人问"补交会不会影响证书" | 诚实回答：**会记录在案，作品集等级受限**——这正是门禁的意义（[`03`](03-评估体系与通关门禁.md) §1） |
| 收尾拖到 90 分钟之后 | **硬性**：到点收。自练时段学员自己会来问 |

### 承接语（最后 30 秒）

> "今天就到这儿。接下来 45 分钟是自练——**今晚的目标不是完美，是交出去。**
> 交出去你才有资格被指出错在哪。"

### 学员笔记要点

- **G2 四条**：标准可度量（blocker）· ≥2 发起人（blocker）· 放弃标准（warning）· ≤1 页（warning，超 2 页 blocker）
- 命名 `D2-姓名-委托单`；截止直播次日 **21:30**；补交 24h 内正常放行（标注"补交通过"），再晚延期通过（封顶 B）
- **红线**：只用虚构案例，或自己已脱敏并经公司同意的场景
- 两条高频坑：标准只有工程师能测 · 发起人只有一位

## S6 · 自练（+45 min）

**本节定位**：不讲课，学员自己做完并提交。助教在群里值守答疑。
**这一节的成功判据只有一个：提交率。** 讲师课后统计，未交者次日 08:30 前私聊。

### 45 分钟怎么分（投屏建议）

| 分钟 | 做什么 | 为什么这么排 |
|---|---|---|
| 0–10 | 把成功标准改成可度量（用 S4 圈的圈） | 最难、最值钱，放精力最好的时候 |
| 10–20 | 补完干系人地图（逼出第二发起人） | 需要"想人"，比改数字更费脑 |
| 20–30 | 写放弃标准 + 范围（✅做 / ❌不做 / 🔄变更规则） | 需要判断，但要基于前面两步 |
| 30–40 | 通读 + 压缩到 ≤1 页 | 压缩是最好的自检 |
| 40–45 | 自评 G2 四条 + 提交 | 留够提交时间，别卡在最后一分钟 |

### 三条路径（学员按自己情况选一条）

| 路径 | 适合谁 | 做什么 |
|---|---|---|
| **A · 完成**（推荐） | 所有人 | 用 [`07`](07-实战剧本与案例库.md) 案例 B（A 组）/ 案例 C（B 组）完成委托单 → 自评 → 提交 |
| **B · 迁移** | 手头有真实项目的人 | 用**你自己已脱敏并经公司同意**的场景重做一份（[`11`](11-工具与环境准备.md) §6.4 脱敏四步法：拿掉 / 替换 / 哈希 / 保真）。**红线：真实客户名与 PII 不得出现在提交物里** |
| **C · 加练** | 想多练手的人 | 用案例 E 明源体检（[`07`](07-实战剧本与案例库.md) §2.5）写一份"**放弃标准清单**"——体会什么叫"什么时候该说不" |

> 关于路径 C：**只写放弃标准，不写整份委托单。** 目标是把"说不"练成一种可执行的判断，而不是一种态度。

### 完成标准（提交前逐条打钩）

```
☐ 成功标准 ≥3 条，每条都有【数字】和【时间】，且【客户能自己验收】
☐ 干系人地图含 ≥2 位发起人（找不到第二位的，图上必须有"死亡风险"标注）
☐ 每个人的"在乎什么"都写了（不是只有名字）
☐ 有放弃标准，且至少一条是可触发的条件句
☐ 委托单打印出来 ≤1 页（最多 2 页）
☐ 命名 D2-姓名-委托单
```

### 卡点急救

| 卡在哪 | 怎么救 |
|---|---|
| "我找不出第二发起人" | **别编。** 写"死亡风险：唯一发起人"，并在风险清单里写"**下次会议的首要议程 = 确认第二发起人**"——这是一份**合格的**产出 |
| "客户验收不了我这条标准" | 三步换主体：① 这条标准对应的**客户业务动作**是什么？② 那个动作的**数量/时长**叫什么？③ 从多少到多少？ |
| "一页装不下" | 不是删字，是**删节**：先砍第 7 节（风险）到 3 行，再砍第 1 节（画像）到 2 行。**第 2、3、6 节一个字都不能少** |
| "我不知道放弃标准写什么" | 套模板句："**如果 <前置条件> 在 <时点> 之前不成立，我们建议暂停并重新评估**"。前置条件从"数据拿不到 / 无第二发起人 / 无验收人"里挑 |

### 助教值守规则

- **只回答两类问题**：① 规则类（命名 / 截止 / 格式）② "这条标准客户能验收吗"——**用 S2 的改造三件套反问，不替改**
- **不回答**：案例背景的"标准答案"（会破坏 D8 交叉提问）、技术方案类问题（D4–D5 才讲）
- 每 15 分钟在群里发一次进度提示（"还有 30 / 15 / 5 分钟"）
- 收到提交后**只回一个字**：`✓`（不讲评——讲评在次日 08:30 门禁榜 + D3 回炉）

### 学员动作

- 45 分钟独立完成（路径 A / B / C 三选一）
- 自评 G2 四条
- 提交 → 收到 `✓`
- 在群里写 60 秒收获：「**我今天最难的一条标准是什么？我最后怎么改的？**」

### 常见错误与纠偏

| 错误 | 纠偏（助教用） |
|---|---|
| 学员把委托单写成 4 页方案书 | "**跑错站了**——今天是 Zone A，方案在 D4–D5。你先把范围砍回一页" |
| 学员提交里出现真实公司名 / 手机号 / 邮箱 | **立即私聊**，要求撤回重交；引用 [`11`](11-工具与环境准备.md) §6.1 红线（**违规 = 数据合规事故**，[`03`](03-评估体系与通关门禁.md) §8 一票否决项） |
| 学员把 seed 档案的参考标准原样抄来 | 不禁止，但**次日回炉会点名问**："这条 MAE ≥20% 是谁来验收？"——抄的人答不上来 |
| 学员只交了成功标准，没交干系人图 | 打回：**blocker 缺一条就是没过**，不是"部分完成" |
