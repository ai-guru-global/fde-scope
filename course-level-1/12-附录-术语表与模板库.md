## 1. 中英术语表

> 每条给三样东西：**英文**（客户和外企面试会这么说）、**白话解释**（说给非技术同事听）、**课程位置**（在哪天学到）。
> 学会术语不是为了显摆——是为了**不被术语骗**。凡是只给英文缩写不给白话解释的供应商，先打个问号。

### 1.0 电脑基础词（完全没碰过命令行也能看懂）

> 这一节是**给零基础同学的**。学过就用不着，卡住了回来查。
> 后面所有章节出现的这些词，含义以本表为准。

| 词 | 白话解释 | 在本课哪里会遇到 |
|---|---|---|
| **终端 / Terminal / 命令行** | 一个**只能打字、不能点鼠标**的黑窗口。你在里面敲一行指令，电脑执行完把结果打回给你 | D1 起，全程 |
| **命令 / Command** | 你在终端里敲的那一行字。如 `fde-scope connect ...`。**一行就是一件事** | 全程 |
| **参数 / 选项 / Flag** | 命令后面那些 `--source`、`--out` 开头的部分。它们是"这道指令的附加说明"，比如数据在哪、结果存哪 | 全程 |
| **工作目录 / 当前目录** | 终端"此刻站在哪个文件夹里"。同一行命令，站的位置不同，结果可能不同 | D1 装环境；见下方"路径" |
| **`cd`** | change directory，**换工作目录**。`cd fde-scope` = 进入 fde-scope 这个文件夹 | D1 装环境 |
| **路径 / Path** | 一个文件或文件夹的**完整地址**。`examples/quickstart_csv/sample_tickets.csv` 就是一条路径 | 全程 |
| **绝对路径 / 相对路径** | 绝对路径从根 `/` 写起（`/Users/你的名字/fde-scope`），走到哪都不会错；相对路径从当前位置写起（`examples/...`），换了位置就找不到 | §3.2 与 §3.5 的"找不到数据"问题都源于此 |
| **PATH** | 一个**系统环境变量**，里面记着"敲命令时去哪些文件夹里找程序"。`fde-scope: command not found` 十有八九是它没包含你的虚拟环境 | `11` §3.2 第 1–2 行 |
| **虚拟环境 / venv** | 一个**独立的 Python 小盒子**：盒子里的软件包和系统其他部分互不干扰。装错了、装乱了，删掉盒子重来即可 | `11` §2.3 |
| **CSV** | 一种**最朴素的表格文件**：纯文本，逗号分隔，第一行是列名，之后一行是一条记录。用 Excel 也能打开 | D3 数据体检 |
| **JSON** | 一种**结构化的文本格式**，用 `{"键": 值}` 的写法表达数据。本课的报告文件（`corpus_report.json`）就是它 | D4 起 |
| **JSONL** | **一行一个 JSON** 的变体（JSON Lines）。不用整个文件包成一个大数组，**读到坏行也不影响其他行**——所以测试集/语料用它 | D4 语料、D5 测试集 |
| **Markdown / `.md`** | 用纯文本记格式的写法：`#` 是标题、`**粗体**` 是加粗。本课程全部文档、以及你的作品集说明都是它 | D1 起 |
| **文本编辑器 / 记事本** | 用来写 `.md`、`.jsonl` 这类**纯文本文件**的工具：Windows 自带「记事本」，macOS 自带「文本编辑」，装过 VS Code 更顺手。**保存时有两个坑**：扩展名别丢（见 §2.4 提醒）、文件存到命令能找到的位置 | D5 造测试集 |
| **文件管理器 / 访达 / 资源管理器** | 平时"翻文件夹、双击打开文件"的那个窗口（macOS 叫访达，Windows 叫资源管理器）。本课生成的 **HTML 报告就在里面双击打开**——会自动用浏览器显示 | D1 起 |
| **截图** | 把屏幕画面存成图片（作业证据反复要用）：macOS `⌘ + Shift + 4` 框选（自动存桌面），Windows `Win + Shift + S` 框选（进剪贴板，直接粘贴到聊天窗口） | D1 起，全程 |
| **API key** | 一串**调用外部 AI 服务的通行证**。**本课程全流程不需要它**（默认走规则路径）；只有想开 LLM 增强时才找教练要 | `11` §4.3 |
| **`127.0.0.1` / 端口** | `127.0.0.1` = **本机自己**（不是外网）；端口（如 8080）像房门号。所以 `http://127.0.0.1:8080` = "打开我自己电脑上的 8080 号门" | D1 起，`fde-scope web` |

> 📌 **复制粘贴三条纪律**（终端里最容易吃亏的地方）：
> 1. **粘贴前先看**：确认你粘的是完整一行，尤其别漏了开头的 `fde-scope` 或结尾的路径。
> 2. **别敲回车去"试试看"**：终端不认"差不多"，拼错一个字母就是报错。
> 3. **报错先读最后一行**：原因几乎总在最后一行（见 §3.5）。

### 1.1 角色与干系人

| 中文 | English | 白话解释 | 课程位置 |
|---|---|---|---|
| 前向部署工程师 | FDE / Forward Deployed Engineer | 不坐办公室写代码，而是**驻到客户现场**，把"客户的一句话需求"变成"能跑能验收的系统"的人。既要懂技术，也要懂业务和沟通 | D1 全程 |
| 交付项目 | Engagement | 一次完整的"从接触到撤出"的客户交付。不是"一个需求"，是一整个有开始有结束的项目 | D1 / D2 |
| 现场走访 | Gemba Walk | 源自丰田：**去事情真实发生的地方站着看**。不要听汇报，去客服工位坐一小时，看真实工单长什么样 | D2 |
| 资格判断 | Qualification | 判断这个客户"值不值得做"：有没有真问题、有没有预算、有没有发起人、愿不愿意给数据。**判断"不做"也是本事** | D2 / `10` §6 |
| 发起人 | Sponsor | 客户方**有预算权、能拍板**的人。他说"继续"项目才能继续 | D2 |
| 执行发起人 | Executive Sponsor | 最高层那位发起人。签预算、扛政治压力的人 | D2 |
| 第二发起人 | Second Sponsor | **第二个能拍板的人**。防的是"唯一发起人离职/调岗 = 项目当场死亡"——这是 FDE 最经典的反模式之一（Sponsor Collapse） | D2 |
| 把关人 | Gatekeeper | 不推项目前进、但**能一票否决**的人：IT、安全、法务、工会、车间主任。他不在你的动员名单里，就在你的风险清单里 | D2 |
| 干系人地图 | Stakeholder Map | 一页纸画出：谁在乎什么、谁支持、谁反对、谁沉默但有毒。**四类必标**：执行发起人 / 第二发起人 / 一线使用者 / IT·安全把关人 | D2 / `12` §2.1 |
| 一线使用者 | End User / Frontline User | 真正每天点你系统的人。他的"麻烦"往往和老板的 KPI 不是一个东西 | D2 |
| 内部拥护者 | Champion | 客户内部主动帮你推的人（很多是一线主管）。**没有 Champion 的项目，落地率腰斩** | D2 |

### 1.2 流程与交付

| 中文 | English | 白话解释 | 课程位置 |
|---|---|---|---|
| 范围 | Scope | 你**答应做什么、以及明确不做什么**。不写"不做什么"，范围就无限膨胀 | D2 |
| 界定范围 | Scoping | 开工前把"做什么/不做什么/什么算做完"谈清楚的过程。**这是 FDE 最值钱的能力**，也是"定边界工作坊"卖的东西 | D2 / `10` §6 |
| 范围蔓延 | Scope Creep | 需求一点点加、工期一点点拖，最后变成一个谁也不认得的项目。反制手段：**时间盒 + 书面委托单 + 每加一项就砍一项** | D2 / `10` §10 |
| 时间盒 | Time Box | 给每件事**封死的期限**。课程时间盒：≤14 天完成集成、≤90 天上线、≤120 天交接完毕 | D2 |
| 可度量成功标准 | Measurable Success Criteria | 带**数字和时间**的验收标准。"提升体验"是废话，"意图准确率从 78% 到 91%"才是标准。课程要求 ≥3 条 | D2 / G2 |
| 放弃标准 | Disengagement Criteria | 事先写好"什么情况下我们体面退出"。**写不出放弃标准的人，会被无限试点拖死** | D2 |
| 无限试点 | Infinite Pilot | 永远在试点、永远不验收、永远不付款。反制：**先定义 done** | D2 / `10` §10 |
| 门禁 | Gate | 每一阶段出口的**硬检查点**：不通过不许往下走。门禁是工程，不是清单——它由代码强制，不是靠自觉。⚠️ 本词有**两个所指**：课程进度门禁 G0–G8 与工具里的 10 个阶段门禁，对照见 `03` §1.1 | D1 起每天 |
| 强制推进 | `--force` | 工具允许你绕过门禁，但**依然会评估并留下记录**。课程里的"补交"就是 `--force` 的课程版：24 小时内补齐正常；超过 24 小时算"延期通过"并记入证书备注 | `03` §5 |
| 阻塞项 / 警告项 | Blocker / Warning | 门禁里的两种判定：blocker 不过就停；warning 记录但不拦。**不要为了好看把 blocker 降级** | `03` §4 |
| 交接 | Handoff | 把你的系统、知识、责任**正式移交给客户团队**。交付的终点不是"上线"，是"客户能自己跑" | D7 |
| 交接四件套 | Handoff Package | Runbook + 评估报告 + SLO 卡 + 培训材料。四件缺一不算交接 | D7 / G7 |
| 退场计划 | Disengagement Plan | 写清楚"我什么时候走、走了以后 30/60 天谁支持什么、什么条件下一刀切断"。**没有退场计划的交付 = 永久售后** | D7 / `10` §10 |
| 推广 | Rollout | 从"一个团队能用"到"全公司能用"。课程教你**先证明再推广**，不做大爆炸上线 | D5 / D7 |
| 冷启动 | Cold Start | 系统刚上线、还没积累数据/反馈的阶段。此时表现最差是正常的，关键是**别在冷启动期下"没用"的结论** | D5 |
| 人机协作 | HITL / Human-in-the-Loop | 关键决策让**人**来拍板，AI 只给建议。客服、医疗、工业场景必须有 | D6 / `07` 案例 B |
| 升级路径 | Escalation Path | 处理不了的时候，**按什么顺序找谁**。Runbook 里每类事件都要写 | D6 |
| 回滚 | Rollback | 出问题时**退回上一个已知好状态**的具体操作步骤。Runbook 里没有回滚步骤 = 没有 Runbook | D6 / G6 |
| 影子模式 | Shadow Mode | 新系统先"跟着跑"不生效：AI 给建议、人做决策、记录差异。**上线前最安全的一步棋** | D5 |
| 验收 | Acceptance / UAT | 客户正式确认"这东西符合我们约定的标准"。要有**签字人**，不能是口头"挺好的" | D7 / G7 |
| 出厂验收 / 现场验收 | FAT / SAT | 工业专有：FAT = 在工厂里验（Factory Acceptance Test），SAT = 装到现场后验（Site Acceptance Test）。制造业客户必问 | `07` 案例 C |
| 物理隔离 | Air-gap | 网络与互联网**物理断开**的环境（军工、部分工厂）。此时不能调外部大模型，必须走本地/规则路径 | `11` §6.6 |
| 工会共决 | Works Council | 德国等地区：涉及员工监控的系统需工会审批（BetrVG §87）。**这是把关人，不是流程障碍** | `07` 案例 C |
| 功能安全 | Functional Safety | 工业机器人场景：不通过安全等级验证不许上产线（ISO 13849 / IEC 61508 / ISO 10218）。工业 FDE 的硬门禁 | `07` 案例 C |
| 价值冲刺 | Value Sprint | 课程方法论：把交付切成 ≤14 天的可交付小段，每段都产生**可被看见的价值**，而不是等三个月给一个大惊喜 | `01` §4 |

### 1.3 数据与语料

| 中文 | English | 白话解释 | 课程位置 |
|---|---|---|---|
| 原始数据 | Raw Data | 客户直接给你的、**没洗过**的东西。真实世界的数据永远比 demo 脏 | D3 |
| 数据体检 | Data Health Check | 拿到数据第一件事：看字段、看缺失、看重复、看 PII、看覆盖度。产出一页报告，回答"**这数据能不能做这件事**" | D3 / G3 |
| 字段 | Field / Column | 表格的一列。要写清**类型**（文本/数字/时间）和**缺失率** | D3 |
| 数据源连接器 | Connector | 把数据从客户系统（CSV / 工单系统 / 数据库）取出来的适配器。课程里先只用 CSV | D3 / `11` §3.1 |
| 覆盖率 / 覆盖盲区 | Coverage / Coverage Gap | 你的数据里**这类情况有多少条、缺哪几类**。盲区比总量重要：3 万条里没有一条"退款"数据，那退款场景必炸 | D4 / G4 |
| 长尾 | Long Tail | 出现次数少但种类极多的那部分情况（各种方言、冷门问题）。**模型效果差，八成死在长尾上** | D4 |
| 语料 | Corpus | 洗干净、标注好、**可以直接拿去训练/评估**的数据集合。不是"数据"，是"弹药" | D4 |
| 语料锻造 | Corpus Forge | 课程核心动作：把原始数据 → 去重 → 质量门 → PII 脱敏 → 补盲 → 产出可用语料，并给出一份可审计报告 | D4 |
| 个人信息 | PII / Personally Identifiable Information | 能定位到具体个人的信息：姓名、手机、身份证、地址、车牌、银行卡。**碰 PII 前先读 `11` §6** | D3 起每天 |
| 脱敏 | De-identification / Masking | 把 PII 换成占位符（如 `<PHONE>`）。四步法：拿掉 / 替换 / 哈希 / 保真（见 `11` §6.4） | D3 / `11` §6.4 |
| 合成数据 | Synthetic Data | 用规则或 AI **生成**的补盲数据，用来补真实数据够不到的角落。**必须如实标注比例**，不许冒充真实数据 | D4 / G4 |
| 质量门 | Quality Gate | 给每条候选语料打分（长度、完整度、语言、重复度），不达标的淘汰。**淘汰了多少条也要写进报告** | D4 |
| 去重 | Dedup | "在吗""你好"这类无信息量重复项的清理。去重日志要有数字：去掉了多少、为什么 | D4 |
| 标注 | Labeling / Annotation | 给数据打上正确答案（这条工单属于"退款咨询"）。**标准不统一，评估就全是噪音** | D4 / D5 |
| 本体 / 概念体系 | Ontology / Taxonomy | 把业务概念理成一张有层级的关系网（退款 → 部分退款 → 超时退款），让覆盖度检查能按**概念**而非关键词做 | D4（`--ontology`） |
| 数据漂移 | Data Drift | 客户的业务变了，数据分布跟着变，模型悄悄失效。**没人监控的 AI 100% 会漂** | D6 |

### 1.4 评估与指标

| 中文 | English | 白话解释 | 课程位置 |
|---|---|---|---|
| 基线 | Baseline | **改动之前的真实水平**。没有基线的提升都是玄学。课程用 78% 之类的数字做基线 | D5 / G5 |
| 测试集 / 金标集 | Test Set / Golden Set | 一套**固定的**、有人工标注答案的题目。同一套题反复跑，才看得出真实变化 | D5 |
| 准确率 | Accuracy | 做对的占总数的比例。课程主指标。**但要看它和什么比**（vs 基线） | D5 |
| 离题率 / 幻觉 | Hallucination / Off-topic Rate | AI 一本正经胡说。要单列一条指标盯它，别混进总分 | D5 |
| 坏案 | Bad Case | **做错的那些样本**。坏案比总分值钱：它告诉你下一步该干什么。课程要求给 Top3 每条**附动作** | D5 / G5 |
| 一级解决率 | FCR / First Contact Resolution | 一次接触就解决的问题比例。客服场景核心业务指标 | D5 |
| 处理时长 | Handle Time | 处理一次要多久。课程基线取人工 8 分钟（480 秒） | D5 |
| 客户满意度 | CSAT / Customer Satisfaction Score | 客户打分（通常 1–5）。**样本少时不要拿它当主指标** | D5 |
| 转人工率 | Escalation Rate | 多少比例的问题得找人。太低说明硬扛（有风险），太高说明没省下事 | D5 |
| 数据飞轮 | Data Flywheel | 线上使用 → 收集坏案 → 补语料 → 重新评估 → 变好 → 更多人用。**没有飞轮，上线就是开始退化** | D6 |
| 概率性退化 | Probabilistic Degradation | 反模式：系统不是"坏了"，是**悄悄变差了**，而没人监控、没人发现 | D6 / `10` §10 |
| 服务等级目标 | SLO / Service Level Objective | 你承诺的"正常水平"，例："95% 请求 2 秒内响应"。**要有目标值 + 测量方式** | D6 / G6 |
| 错误预算 | Error Budget | 允许失败的那部分额度（SLO 99% 意味着每月可失败约 7 小时）。**烧完就停止新功能、先修稳定性** | D6 / G6 |
| 告警路由 | Alert Routing | 出事了**谁、通过什么渠道、多久内**响应。三要素缺一 = 没人管 | D6 / G6 |
| 运维手册 | Runbook | 一页页写清楚"这类事件怎么判断、怎么处理、怎么回滚、找谁升级"。**判断标准：同事照着能做** | D6 / G6 |
| 凌晨 2 点盲测 | 2 AM Test | 课程考核法：找没参与的同学，只给 Runbook，让他独立处理一次事件。**盲测通过才算 Runbook 合格** | D6 / G6 |
| 监控指标 | KPI | 客户业务层面的数字（工单下降 30%、拦截率 60%）。和 SLO（技术稳定性）是两回事，**汇报时别混** | D6 / `fde-scope kpi` |
| 值班交接 | Shift Handover | 多班次生产环境：上一班必须把状态、待办、风险交接给下一班。工业场景的硬门禁 | D6 / `07` 案例 C |

### 1.6 十二大反模式速查（FDE 专属"避坑清单"）

> 来源：[`docs/fde_sop_full.md`](../docs/fde_sop_full.md) §"12 大反模式"。**面试与答辩高频考点**——被问"你遇到最大的坑是什么"，答反模式比答"加班太多"强一百倍。

| # | 反模式 | 一句话症状 | 反制动作（课程教的） |
|---|---|---|---|
| 1 | Consulting Trap 咨询陷阱 | FDE 越做越像定制外包，产品永远长不出来 | 每做完一个项目必须沉淀技能卡（`skill add`） |
| 2 | Snowflake-Per-Customer 一客一版 | 每个客户一套代码，维护成本爆炸 | 优先复用已有模式与模板 |
| 3 | Hero Engineer 英雄工程师 | 全靠一个牛人扛，他一休假就瘫 | 交接四件套 + 盲测 |
| 4 | Demo-Debt Spiral 演示债 | demo 演的东西平台根本做不到 | **在真实脏数据上做原型**，不搭布景 |
| 5 | Sponsor Collapse 发起人崩塌 | 唯一发起人离职，项目当周死亡 | 干系人地图必标 **≥2 位发起人**（G2 硬门槛） |
| 6 | Burnout Death Spiral 燃尽螺旋 | 最能干的人先离职 | 时间盒 + 明确放弃标准 |
| 7 | Probabilistic Degradation 概率性退化 | 系统悄悄变差，无人发现 | SLO + 告警路由 + 数据飞轮 |
| 8 | Infinite Pilots 无限试点 | 永远试点、永远不定义 done | 委托单写死 done 与时间盒 |
| 9 | Data Quality Surprises 数据质量惊吓 | 假设"数据已经治理好了" | 开工先做数据体检（G3） |
| 10 | Scope Creep 范围蔓延 | 需求只加不减，工期只拖不缩 | 每加一项，砍一项；委托单 ≤1 页 |
| 11 | No HITL 无人机协作 | AI 直接对外说话，没人兜底 | 关键决策留人确认 |
| 12 | Safety Incidents 安全事故 | 没做危险分析就动产线 | 工业 profile 的功能安全门禁 |

**⚠ 读表前必看：哪几个数字是真信号，哪几个只是"没填数据"**

`eval` 打出 10 行指标，**只有你亲手填进样本的字段才是真信号**，其余是"没数据时的默认值"。把默认值当成绩写进作品集，等于编数据（违反 [`README.md`](README.md) 诚实边界）。

| 指标 | 没数据时它会显示 | 真实含义 |
|---|---|---|
| `intent_accuracy` | 填了 `expected_category` → **0.000**<br>没填 → 1.000 | 见下方「为什么是 0.000」 |
| `reply_adoption_rate` | 1.000 | `adopted` 留空 = **默认算采纳**，不是实测 100% |
| `escalation_rate` | 0.000 | ✅ **真信号**：样本里 `escalated: true` 的条数占比 |
| `first_contact_resolve` | 1.000 | `resolved_first_contact` 默认 true，**不是实测** |
| `avg_handle_time` | 0.000 | **没有数据**（没填 `handle_time_seconds`），不是"0 秒搞定" |
| `customer_satisfaction` | 3.000 | 没填 `csat` 时的 1–5 中性中点，**不是实测 3 分** |
| `cost_per_ticket` | 1.000 | 没时长数据时按"与人工基线持平"记，不是"成本没降" |
| `corpus_coverage` / `corpus_quality_avg` / `corpus_diversity` | 0.000 | **没接语料报告**（`corpus` 阶段产物），不是"覆盖率 0" |

**为什么 `intent_accuracy` 是 0.000？**

打分口径是**子串匹配**：`expected_category` 这串字**必须原样出现在 AI 回复里**才算命中（`fde_scope/eval/metrics.py` 的 `score_intent_accuracy`）。
而 `--agent mock` 的回复只含用户原话——`已为您处理：<input 前 30 字>…（mock 回复）`，**不带类别名**。所以只要你填了 `expected_category`，mock 就恒为 0.000。**这不是你写错了。**

三种正确用法：

| 你想干什么 | 怎么做 |
|---|---|
| 只想跑通流程、看 bad case 挖掘与语料建议 | **删掉 `expected_category`**（该条记 1.0 = 无信号），流程照跑 |
| 想验证「打分逻辑本身」通不通 | 像 `tests/test_eval.py` 那样在样本里直接写 `agent_reply`：`{"expected_category": "退款", "agent_reply": "已为您处理：退款"}` —— 这样才有区分度 |
| 要真实的准确率数字 | 用 `--agent mimo` 或接你自己的 Agent：`agent_reply` 由 Agent 填，`expected_category` 才真正生效 |

> `--accuracy`（默认 0.9）只决定 mock 回哪句套话（另有 10% 回"抱歉，我不太理解"），**不改变判分口径**。
> ⚠ 这条口径对真模型同样成立：`MiMoReplyFn` 的 prompt 并不要求它输出类别名，所以 `expected_category` 照样可能命中不了。真要量化，就在 Agent 的输出格式里约定带上类别标签。
> **别把 mock 跑出来的任何数字写进作品集。**

### 2.13 技能卡（⭐G7 · 📅D7）

> **FDE 的复利资产**。每做完一个项目，把可复用的东西写成卡，存进技能库。
> 五要素：**场景 → 问题 → 做法 → 证据 → 适用边界**。最后一条最重要——不写边界的技能卡是坑人。

```markdown
# 技能卡 · <标题：客服场景长尾类别补盲>

## 场景
<新茶饮连锁客服工单意图分类；数据以物流查询为主，退款/会员/退换货类样本近乎为零。>

## 问题
<长尾类别准确率仅 61%，整体被拖累；客户不允许更换模型。>

## 做法
<1. 用本体概念清单做概念级覆盖度检查，而非关键词匹配；
2. 对覆盖不足的概念，按业务规则枚举模板 + 少量真实样本改写，生成 <4,000> 条候选；
3. 全部候选过同一质量门（长度/完整度/语言/重复度），淘汰 <35%>（保留约 <2,600> 条进语料）；
4. 合成比例如实标注在报告中，不混入真实计数。>

## 证据
<- 合成后长尾类别准确率 61% → 88%（同一测试集 <200> 条）
- 报告路径：<reports/corpus_report.html>
- 复现命令：`fde-scope corpus --input <路径> --ontology --out <报告>`>

## 适用边界（⚠ 必填）
<- 适用：规则明确、可枚举的封闭业务场景（退款规则、会员等级）
- 不适用：开放式创意类、强合规场景（医疗诊断、法律意见）
- 前提：必须有 ≥20 条真实种子样本；零种子时纯合成不可信
- 副作用：合成比例 >20% 时，需额外人工抽检，成本上升>
```

**工具路径**：
```bash
fde-scope skill add --title "客服长尾类别补盲" --category methodology \
  --tags "corpus,synthetic,longtail" --body-file card.md \
  --phase corpus            # --phase 用真实阶段 slug，见 §3.4
fde-scope skill publish <skill-id>                       # 发布进团队技能库
fde-scope skill review                                   # 助教审核（课程内）
fde-scope skill export <skill-id> --format agentscope    # 导出成可复用格式
```

> `--category` 四选一：`research` / `implementation` / `optimization` / `methodology`（技能卡用 `methodology`）。
> `--phase` / `--gate` 填**真实 slug**（见 §3.4 与 §3.2）——填错的卡能被创建，但 `skill list --phase`/`--gate` 检索不到。

### 2.16 业务与风险侧补漏骨架（7 个 · 来自开源对标）

**这 7 个骨架为什么在这儿**：对标附卷 [`24`](24-开源对标与来源清单.md) §5.2 列出了开源同行有、我们没有的
7 个**业务侧与风险侧**产物（证据档位：代码原文——FDEOps 仓库 `skills/` 目录下的 36 个 `SKILL.md`，基准日 2026-10-08）。
我们的 18 阶段偏**交付与验证**，这 7 项偏**说服与兜底**——FDE 在现场翻车，多数不是技术不行，而是**没写这七张纸**。

> ⚠ **它们不是门禁，也不进状态机。** 加门禁要改契约测试（`docs/fde_sop_full.md` 的 10 门禁是受约束的契约），
> 而这七张纸的性质是**建议产出**：讲师不据此打分，`fde-scope` 也不校验它们。
> 与 §2.1–§2.15 的区别就在这一句：**那 15 个是"交上去才有 Gx"，这 7 个是"交了你会更稳"。**
>
> **教学状态**：⛔ 尚未在任何真实班级跑过（已记入 [`13`](13-GTM页面与竞品对比.md) §6 第 12 项）。
> 因此下面每份骨架都只写"填空结构"，**不写示例数字**——编一个没人验证过的数字，正是本课一票否决的那件事。

**① 董事会一页纸**（board memo · 给掏钱的人看）

```markdown
# <事项> · 一页纸 · <日期>
## 我们要解决谁的什么问题（≤2 句，业务口径，不许出现模型名）
## 现在每小时/每天损失多少（有出处就写出处，没有就写"未测量"）
## 要什么：<金额 / 人天 / 授权>，期限 <日期>
## 不给会怎样：<可观察的后果>（不是"项目失败"这种不可证伪的话）
## 我们已验证到哪一步：<一句，指向作品集里的证据文件>
## 三个备选：<最小可用 / 推荐 / 完整>，各自的价与风险
```

> 与 §2.15 ③"一页纸汇报"的区别：那张给**接手的人和客户方技术负责人**（讲价值与证据），
> 这张给**没有义务读完的人**（讲决策与代价）。写作约束只有一条：**读完第一行就知道你要什么**。

**② 商业论证**（business case · 立项 / 续约）

```markdown
# <项目> 商业论证 · <版本> · <日期>
## 成本：人天 __ × 费率 + 许可 __ + 集成 __ + 运维 __（口径各写一行）
## 收益：<可度量指标> 从 __ 到 __，折算 __；周期 __ 个月
## 不做的代价：__
## 敏感性：若收益数字错 30%，结论是否仍成立？__（成立/不成立，写出理由）
## 证据与出处：每条数字 → 作品集文件路径或"未测量"
```

> **纪律**：这张纸是唯一允许出现"钱"的模板，所以它是**最容易造假**的一张。
> 三个"未测量"胜过五个编出来的数字（[`03`](03-评估体系与通关门禁.md) §4 诚实标注同样适用）。

**③ 用例打分排序**（score use cases · 场景很多时的取舍）

```markdown
| 候选场景 | 业务价值(0-5) | 数据可得(0-5) | 上线风险(0-5) | 可演示性(0-5) | 维护成本(0-5，低=好) | 加权 | 备注 |
|---|---|---|---|---|---|---|---|
| <场景 A> |  |  |  |  |  |  |  |
```

> 用法：D2 之前和**客户一起**填这张表——权重（哪一维最重要）必须由客户定，不是我们定。
> 它补的是 §2.1 客户委托单里"为什么是这个场景"这一格：委托单写结论，这张表写**怎么得出的结论**。
> 打完分 Top1 进委托单，其余行**留档**——三个月后一定会被问"当时为什么不选 X"。

**④ 失效面预演**（what breaks · 上线前那一次冷静的悲观）

```markdown
# 失效面预演 · <系统名> · <日期>
## 逐层列（每层至少 1 条，写不满就是没想过）
- 数据层：<脏 / 缺 / 漂移 / 断供> → 触发信号 __ → 处置 __ → 谁负责 __
- 模型层：<答非所问 / 幻觉 / 超时> → 同上
- 集成层：<上游改接口 / 配额 / 证书过期>
- 权限层：<账号失效 / 越权 / 审计断链>
- 组织层：<对接人离职 / 值班真空班>
- 物理与环境层：<断网 / 隔离网数据外送 / 班次交接>（⚙ 工业场景必填，见 [`03`](03-评估体系与通关门禁.md)）
```

> 与 D5 坏例子复盘（[`07`](07-实战剧本与案例库.md)）的分工：坏例子是**已经发生的**，
> 这张表是**还没发生但你必须先想到的**。两者都是"诚实"的训练，只是一个朝后看一个朝前看。

### 3.2 交付项目与门禁

| 我想…… | 命令 |
|---|---|
| 新建客户交付档案 | `fde-scope engage init --customer "<客户名>" --profile ticket` |
| 指定档案 id | `fde-scope engage init --customer "<客户名>" --profile ticket --id <自定义id>` |
| 看当前在哪个阶段、门禁状态 | `fde-scope engage status <id>` |
| 推进到下一阶段（门禁自动重评） | `fde-scope engage advance <id>` |
| 门禁没过但必须推进（会留下记录） | `fde-scope engage advance <id> --force` |
| 退回到之前某阶段 | `fde-scope engage rollback <id> --to <phase>` |
| 列出所有进行中的档案 | `COLUMNS=200 fde-scope engage list`（不加 `COLUMNS` 时 id 列会被截断，抄不全）|
| 记一条现场笔记 | `fde-scope engage journal <id> --kind research --note "<记录内容>"` |
| 查看现场笔记 | `fde-scope engage journal <id>` |
| 记笔记时关联技能卡 | `fde-scope engage journal <id> --note "<内容>" --link-skill <skill-id>` |
| 看系统里全部 10 个门禁 | `fde-scope gate list`（**两个 profile 都印全部 10 行**，不是少印几行；第 3 列 `industrial_only` 用 🏭 / 🏢 标出哪些是工业专属。`--profile` 只改标题那一行）|
| 查某个档案的全部门禁结论 | `fde-scope gate check <id>` |
| 只查某一关 | `fde-scope gate check <id> --gate <gate-slug>` |

> `--kind` 三选一：`research`（调研）/ `implementation`（实施）/ `optimization`（调优）。
>
> **`--gate` 可用的 slug（共 10 个）**：`success_criteria` · `slo` · `handoff_signoff`（通用 3 个）；
> `site_survey` · `fat_sat` · `functional_safety` · `conformity` · `works_council` · `air_gap` · `shift_handover`（工业专属 7 个，见 `gate list` 第 3 列的 🏭）。
> 填错 slug 会直接报 `Unknown gate`——**故意不静默放过**。
>
> ⚠️ **一个要命的坑**：在 **ticket** 档案上手动 `gate check <id> --gate site_survey`，你会看到 **`✅ PASS`**——
> 那是"没有可检查的数据"的**空过**，**不是**你通过了工业门。**别把这个 ✅ 当成证据写进作品集**
> （ticket 档案根本走不到工业阶段，[`03`](03-评估体系与通关门禁.md) §3 的门禁表里也没有这 7 关）。
> 同理 `gate check <id>`（不带 `--gate`）在 `qualification` 阶段会直接说 `Phase 'qualification' has no gate.`——这是正常输出，不是报错。
> **判断"我该过哪几关"只认 [`03`](03-评估体系与通关门禁.md) §3 的 G0–G8 课程门禁**，那是本课程自己的一套，
> 与工具里的 10 个门禁**同名不同源**——两套门禁的对照表见 [`03`](03-评估体系与通关门禁.md) §1.1。

### 3.4 概念 → 阶段映射（18 阶段全表）

> 18 阶段按四区划分（A 定边界 / B 造出来 / C 稳得住 / D 交得出去）。
> **标 ⚙ 的 3 个是工业专有阶段**：`--profile ticket` 下自动跳过，所以 ticket 走 15 阶段。

| # | 区 | 阶段 slug（`--phase` 用这个） | 白话 | 你在这里产出 |
|---|---|---|---|---|
| 1 | A | `qualification` | 值不值得做？ | 资格判断结论 |
| 2 | A | `site_survey` ⚙ | 去现场看真实业务（Gemba walk） | 现场笔记（`engage journal`）|
| 3 | A | `stakeholder_map` | 认清谁在乎什么 | 干系人地图（委托单 §2.1 第 2 节）|
| 4 | A | `success_criteria` | 把"做完"谈清楚 | 成功标准 + 放弃标准（委托单 §2.1 第 3/6 节）|
| 5 | B | `connect` | 数据接进来 | 字段预览 + PII 字段名标记 |
| 6 | B | `corpus` | 把数据洗成能用的语料 | 数据体检 §2.2 + 语料报告与话术 §2.3 |
| 7 | B | `prototype_real_data` | **在真实脏数据上**做原型 | 原型 + 落差记录（防 Demo-Debt）|
| 8 | B | `validate` | 拿给真实干系人看 | 验证记录 §2.6 |
| 9 | B | `deploy` ⚙ | 装上产线（工业走 FAT→SAT） | 上线确认 |
| 10 | B | `eval` | 用数字证明有效 | 测试集 §2.4 + Bad Case §2.5 |
| 11 | C | `slo_sla` | 定稳定性承诺与值班 | SLO 卡 §2.7 |
| 12 | C | `runbook` | 写清出事怎么办 | Runbook §2.8 + 值班交接卡 §2.9 |
| 13 | C | `monitoring_drift` | 盯住"悄悄变差" | 监控与漂移看板 |
| 14 | C | `change_mgmt_training` ⚙ | 培训 + 工会共决 | 培训材料 |
| 15 | C | `flywheel_productization` | 让经验回流、越用越好 | 技能卡 §2.13 |
| 16 | D | `ops_handoff` | 运维责任移交 | 交接包 §2.10 |
| 17 | D | `knowledge_transfer` | 知识交出去 | 培训材料 + 文档包 |
| 18 | D | `disengage` | 体面撤退 | 验收清单 §2.11 + 退场计划 §2.12 |

**查当前阶段的命令**：`fde-scope engage status <id>`（会显示当前阶段 slug 与门禁状态）
**查某 profile 的完整阶段序列**：`fde-scope engage init --customer "tmp" --profile ticket` 建一个临时档案——
⚠ **id 不是你起的名字**：`--customer "tmp"` 生成的 id 是 **`eng-tmp-ticket`**，不是 `tmp`。
建完先 `COLUMNS=200 fde-scope engage list` 确认 id，再 `fde-scope engage status eng-tmp-ticket`、逐级 `advance` 观察；
方法论文档见 [`docs/fde_sop_full.md`](../docs/fde_sop_full.md)。

### 3.5 出错时的含义（速查）

| 现象 | 含义 | 怎么办 |
|---|---|---|
| `fde-scope: command not found` | 虚拟环境没激活，或装错环境 | 见 `11` §3.2 第 1–2 行 |
| 命令退出码 2 + 提示缺 key | 该命令需要 LLM（`corpus --llm` / `eval --agent mimo` / `handoff --llm`） | 去掉 `--llm`/改用 `mock` 走规则路径，或按 `11` §4.3 配 key |
| 门禁 blocker 不过，`advance` 被拒 | 门禁在正常工作 | 补齐材料重跑 `gate check`；确认无法补齐再用 `--force`（留记录）|
| `Refusing to bind non-loopback` | `web` 默认拒绝对外暴露（安全设计） | 见 `11` §6.5：局域网演示需两步同时做，演示完关掉 |
| 网络错误但流程继续跑 | LLM 自动降级到规则路径（设计如此） | 检查报告里的来源标记；要真实模型结果需配 key |
| `engage list` 显示 `No engagements yet.`（**没报错**） | 你不在仓库根目录。数据目录靠"当前目录下有没有 `.fde_scope/`"定位，换目录后就找不到了 | `cd` 回仓库根目录；或从别处用 `FDE_SCOPE_HOME=<仓库绝对路径> fde-scope …`，见 §3.2 |
| `engage list` 的 id 是 `eng-adnova-t…` 这种带省略号的 | 终端宽度不够，Rich 把列截断了（**不是数据损坏**） | 命令前加 `COLUMNS=200`：`COLUMNS=200 fde-scope engage list` |
| 跑完 `gate check` / `advance` 后技能卡多了一张 `skill-xxxx` 草稿 | **飞轮设计**：门禁阻塞被自动沉淀成知识 | 预期行为。想看就 `fde-scope skill review`，不想要就 `fde-scope skill archive <skill-id>` |
| `eval` 的 `intent_accuracy` 恒为 0.000 | 判分是**子串匹配**，而 mock 回复里没有类别名 | **不是 bug**：先删掉 `expected_category` 或改用 `--agent mimo`，见 §2.4 |
| `eval` 指标是 3.000 / 1.000 / 0.000 这类整数 | 没填对应字段，这是**默认值不是实测值** | 对照 §2.4「读表前必看」那张表，别把默认值写进作品集 |

## 4. 门禁速查一览（G0–G8）

> 判定语义（blocker/warning）见 [`03`](03-评估体系与通关门禁.md) §3，明细判分标准见 §4。
> 此表用于**快速定位："这一关我要交什么、怎么生成"**。

| 门 | 时间 | 核心 blocker（必须过） | 模板 | 关键命令 |
|---|---|---|---|---|
| **G0 入学门** | 开营前 | 环境自检通过（契约与雷达是 warning，**可开营后补**） | `11` §3.1 | `python3 --version` / `fde-scope --help` |

| **G4 语料门** | D4 | 报告数字与实际一致；覆盖盲区说明与补盲策略；话术 ≤200 字零术语 | §2.3 客户话术 | `fde-scope corpus … [--ontology/--llm]` |

| **G6 稳运门** | D6 | Runbook 5 类事件**每类含回滚**；SLO 卡含错误预算；通过凌晨 2 点盲测 | §2.7 / §2.8 / §2.9 | `fde-scope handoff <id>`（生成骨架）|

**权重提醒**：作品集 60% + 答辩 25% + 互助出勤 15%（[`03`](03-评估体系与通关门禁.md) §2）。
**等级**：判定条件以 [`03`](03-评估体系与通关门禁.md) §6 为**唯一口径**——A 级 = 8 件齐全 + 平均分 ≥9/12 + 无未达项；B 级 = 8 件齐全 + 平均分 ≥7/12；C 级 = 缺 ≤2 件或平均分 <7/12（发完课证明，非证书）。
**诚实边界**：本课程不承诺就业、不承诺收入；证书只证明"你在课程内完成了什么"（[`03`](03-评估体系与通关门禁.md) §6、[`08`](08-运营手册.md) §11）。
