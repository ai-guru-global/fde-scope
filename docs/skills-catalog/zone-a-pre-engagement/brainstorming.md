# brainstorming

> 状态：✅ 已安装（superpowers 系）· 类型：流程/方法论 · FDE 位点：Zone A · qualification / success-criteria

## 能做什么
在任何创造性工作（新功能、新组件、改行为）动手**之前**，用探索性对话厘清意图、需求与设计。防止"用户说了个大概就直接开写"导致的返工。

## 何时使用
- 用户说"我们做个 X / 加个 X / 改一下 X"而没有明确规格
- 需求含糊、有多个合理方向、或涉及行为变更
- Zone A 与客户对齐成功标准（success-criteria 阶段的方法论支撑）

**不用于**：规格已经完全明确的执行型任务；纯查询/纯排障。

## 最佳实践
- Do：先问"为什么"再问"做什么"；把假设显式写出来
- Do：产出物落成文字（计划/规格），供 [writing-plans](../cross-cutting/writing-plans.md) 接续
- Don't：不要跳过它直接进实现——这是 superpowers 的硬性优先级（流程技能先于实现技能）
- 边界：brainstorming 管"想清楚"，spec 类技能管"写精确"

## 项目应用位点
- fde-scope 新阶段/新 gate 设计前的需求探索
- 与客户开工会（kickoff）的问题清单骨架
